AWS IAM Role

Think of an AWS IAM Role like a temporary employee ID badge.

Simple Analogy

Imagine you work in a company.

  • 👤 IAM User = A permanent employee with their own ID card.
  • 🎭 IAM Role = A temporary badge that gives someone permission to do a specific job.

For example:

  • Alice is a developer.
  • She normally doesn't have access to the finance room.
  • When she needs to fix a finance server, she's given a temporary badge.
  • After she's done, the badge expires.

That's exactly how an IAM Role works.

What is IAM?

IAM stands for Identity and Access Management.

It controls:

  • Who can access AWS
  • What they can do
  • Which AWS services they can use

What is an IAM Role?

An IAM Role is a set of permissions that can be temporarily assumed by:

  • AWS services
  • Users
  • Applications
  • Another AWS account

Unlike an IAM User, a role has no permanent username or password.

Instead, AWS gives temporary credentials.

Example Policy

The role might have this permission:


{
    "Version": "2012-10-17",
    "Statement": [
        {
            "Effect": "Allow",
            "Action": "s3:PutObject",
            "Resource": "arn:aws:s3:::my-bucket/*"
        }
    ]
}

Meaning:

Allow uploading files to my-bucket.

Because Lambda automatically receives temporary credentials from its IAM Role.

YES

Why not just use Access Keys?

Imagine putting your house key inside every app.

Bad idea.

If someone steals the code:


Access Key
Secret Key

they own your AWS account until you rotate those keys.

IAM Roles solve this because:

  • no permanent credentials
  • temporary credentials
  • automatically rotated
  • safer

IAM User vs IAM Role

IAM User IAM Role
Permanent identity Temporary identity
Has username No username
Has password/access keys No permanent keys
Used by people Used by AWS services, apps, or users temporarily
Credentials don't rotate automatically Temporary credentials rotate automatically

Your Lambda function never stores AWS credentials. Instead, it automatically assumes its IAM Role, receives temporary credentials from AWS, and uses those to securely access the AWS services it's authorized to use. This is the recommended and most secure pattern for serverless applications.
