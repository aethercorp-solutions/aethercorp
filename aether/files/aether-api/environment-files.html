Environment Files

This lets you use different API endpoints, Google OAuth credentials, and AWS Amplify settings without changing code.

A good setup is to have three separate environments:

  • Development → http://localhost:3000
  • Staging (optional) → https://staging.example.com
  • Production → https://app.example.com

1. Create Vite Environment Files


project/
│
├── .env
├── .env.local
├── .env.development
├── .env.production
├── vite.config.ts

.env.development


VITE_API_URL=https://dev-api.example.com/api/v1

VITE_GOOGLE_CLIENT_ID=xxxxxxxxxxxxxxxx.apps.googleusercontent.com

VITE_AWS_REGION=us-east-2
VITE_USER_POOL_ID=us-east-2_xxxxxxxxx
VITE_USER_POOL_CLIENT_ID=xxxxxxxxxxxxxxxxx
VITE_IDENTITY_POOL_ID=us-east-2:xxxxxxxx-xxxx

.env.production


VITE_API_URL=https://api.example.com/api/v1

VITE_GOOGLE_CLIENT_ID=yyyyyyyyyyyyyyyy.apps.googleusercontent.com

VITE_AWS_REGION=us-east-2
VITE_USER_POOL_ID=us-east-2_yyyyyyyy
VITE_USER_POOL_CLIENT_ID=yyyyyyyyyyyy
VITE_IDENTITY_POOL_ID=us-east-2:yyyyyyyy

2. Access Environment Variables


export const config = {
    apiUrl: import.meta.env.VITE_API_URL,

    googleClientId: import.meta.env.VITE_GOOGLE_CLIENT_ID,

    aws: {
        region: import.meta.env.VITE_AWS_REGION,
        userPoolId: import.meta.env.VITE_USER_POOL_ID,
        userPoolClientId: import.meta.env.VITE_USER_POOL_CLIENT_ID,
        identityPoolId: import.meta.env.VITE_IDENTITY_POOL_ID,
    }
}

3. Configure Axios


import axios from "axios";
import { config } from "./config";

const api = axios.create({
    baseURL: config.apiUrl,
});

export default api;

Now switching between environments happens automatically.

import { defineConfig } from 'vite'

})

5. Configure Google OAuth

Using @react-oauth/google:


import { GoogleOAuthProvider } from "@react-oauth/google";

<GoogleOAuthProvider
    clientId={import.meta.env.VITE_GOOGLE_CLIENT_ID}
>
<App />
</GoogleOAuthProvider>

import.meta is a JavaScript object provided by Vite.

import.meta.env contains the environment variables that Vite makes available to your app.

VITE_GOOGLE_CLIENT_ID is the specific environment variable you've defined.

9. Environment Variables in AWS Amplify

Instead of committing .env.production, define environment variables in your Amplify app.

Example:


VITE_API_URL
VITE_GOOGLE_CLIENT_ID
VITE_AWS_REGION
VITE_USER_POOL_ID
VITE_USER_POOL_CLIENT_ID
VITE_IDENTITY_POOL_ID

Amplify injects these values during the build.

The same flow applies in production, except the application runs on your production domain and uses the production Google OAuth client and API endpoints.

Recommended setup

Since you're already using React + Vite, AWS Amplify Hosting, AWS Lambda, API Gateway, and Google Authentication, a clean approach is:

  • Keep separate .env.development and .env.production files (or use Amplify environment variables for production).
  • Use one Google OAuth client if both http://localhost:3000 and your production domain can be added as authorized origins. Otherwise, use separate clients for development and production.
  • Store only the Google client ID in the frontend; keep secrets (if any) on the backend.
  • Configure your backend CORS to allow your development and production origins.
  • Let AWS Amplify manage production environment variables so you don't need to commit production-specific configuration.
