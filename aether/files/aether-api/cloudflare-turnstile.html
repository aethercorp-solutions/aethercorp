Cloudflare Turnstile

Cloudflare Turnstile is like a smart security guard at the entrance.

How it works

Imagine you own a store.

  • Real customers walk in and buy things.
  • Robots (bots) try to flood your store with fake orders.

Cloudflare Turnstile is like a smart security guard at the entrance.

Instead of asking everyone to solve annoying puzzles ("Click all the traffic lights"), it quietly watches for signs that you're a real person.


User visits your website
         │
         ▼
Cloudflare Turnstile checks:
- Browser behavior
- Device signals
- Mouse/keyboard interaction
- Other security signals
         │
         ▼
If user looks legitimate:
    ✓ Pass automatically
Else:
    Show a small challenge
         │
         ▼
Browser receives a token
         │
         ▼
Your server verifies the token with Cloudflare
         │
         ▼
If valid:
    Process the form
Else:
    Reject the request

What is the token?

The token is like a visitor pass.

Example:


eyJ0eXAiOiJKV1QiLCJh...

Your website sends this to your backend.

Your backend asks Cloudflare:

"Did you really issue this token?"

Cloudflare replies:


{
    "success": true
}

or


{
    "success": false
}

If false, reject the request.

Why can't a bot just fake the token?

Because only Cloudflare can generate valid tokens.

Your server verifies every token using your Secret Key.

Think of it like a concert ticket.

A scammer can print:


VIP PASS

But the security scanner checks the official database.

If the ticket isn't real:

❌ Entry denied.

Why not just check on the frontend?

Because attackers can skip your website entirely.

They can send requests directly to your API:


Bot
   │
   ▼
POST /api/quote

So your backend must always verify the token before processing the request.

Why developers like Turnstile

  • ✅ Free for most use cases
  • ✅ Better user experience than traditional CAPTCHAs
  • ✅ Many users never see a challenge
  • ✅ Protects forms, login pages, registration, contact forms, and APIs
  • ✅ Easy to integrate with frameworks like Next.js, React, and Node.js

Test your own RFQ endpoint

Here's a simple Node.js script that repeatedly submits an RFQ form to your own Next.js API for testing.

Install


npm install axios

bot.js


const axios = require("axios");

const URL = "http://localhost:3000/api/quote"; // Your API endpoint

async function sendRFQ(i) {
  try {
    const response = await axios.post(URL, {
      companyName: `Test Company ${i}`,
      contactName: "John Doe",
      email: `john${i}@example.com`,
      phone: "09171234567",
      serviceType: "AI Development",
      projectDescription: "Automated test submission",
      budget: "$5,000",
      targetDate: "2026-08-01",

      // Normally generated by Turnstile in the browser.
      // Here we're intentionally sending a fake token.
      turnstileToken: "fake-token"
    });

    console.log(`#${i} Success`, response.status);
  } catch (err) {
    if (err.response) {
      console.log(
        `#${i} Rejected`,
        err.response.status,
        err.response.data
      );
    } else {
      console.log(err.message);
    }
  }
}

async function main() {
  for (let i = 1; i <= 100; i++) {
    await sendRFQ(i);
  }
}

main();

If your backend verifies Cloudflare Turnstile correctly, every request should be rejected with something like:


400 Invalid Turnstile token

That confirms your protection is working.

Better load test

For performance testing your own API, use a tool such as:

  • k6
  • Apache JMeter
  • Artillery

These tools let you simulate hundreds or thousands of legitimate concurrent clients in a controlled way and are the standard approach for stress-testing your own services.

For example, with k6:


import http from "k6/http";

export default function () {
  http.post("http://localhost:3000/api/quote", JSON.stringify({
    companyName: "Test",
    contactName: "John",
    email: "john@example.com",
    turnstileToken: "fake-token"
  }), {
    headers: {
      "Content-Type": "application/json"
    }
  });
}

Running this against your own API is a good way to verify that:

  • your rate limiting works,
  • Turnstile verification rejects invalid tokens,
  • your server remains stable under load,
  • and legitimate requests continue to succeed.
