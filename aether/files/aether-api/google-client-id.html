Google Client ID

A Google Client ID is like an ID card for your app that tells Google who is asking users to sign in.

Simple analogy

Imagine you're entering an office building.

  • You (the user) = the visitor
  • Google = the security guard
  • Your app = the company you're visiting
  • Google Client ID = the company's visitor ID

When your app asks Google to let someone sign in, it says:

"Hi Google, I'm app 123456789-abc.apps.googleusercontent.com."

Google checks if that Client ID is valid and whether it matches the app's registered settings.

What it looks like

A Google Client ID looks something like this:


123456789012-abcdefg123456.apps.googleusercontent.com

Why do you need it?

Without a Client ID, Google doesn't know:

  • Which app is requesting login.
  • Which redirect URLs are allowed.
  • Which users are allowed to sign in.

What happens during Google Sign-In?

  1. Your app sends its Client ID to Google.
  2. Google shows the login screen.
  3. The user signs in.
  4. Google verifies the Client ID.
  5. Google sends your app an ID token, access token, or authorization code.

Is the Client ID secret?

No. A Client ID is public and is safe to include in frontend code (such as a Vite app, iOS app, or Android app).

The Client Secret is different:

  • ✅ Client ID → Public
  • ❌ Client Secret → Private (keep it on your backend)

Different apps have different Client IDs

Each platform typically has its own Client ID because Google identifies them separately.

For example:

  • Web app → Web Client ID
  • iOS app → iOS Client ID
  • Android app → Android Client ID

Even if they're all for the same project, they usually use different Client IDs.

Example

Suppose you have a Vite frontend and an AWS Lambda backend.

    • Vite frontend
    • User signs in.
    • Receives an authorization code or ID token.
  • AWS Lambda backend
    • Verifies the token or exchanges the authorization code for access tokens.
    • Uses those tokens to call Google APIs if needed.

In short, a Google Client ID identifies your application to Google, allowing Google to recognize your app and safely handle the sign-in process. It is not a password and is meant to be shared with your application's client side.
