Production-grade Retrieval-Augmented Generation (RAG) system

A production-grade Retrieval-Augmented Generation (RAG) system is much more than "embed documents and search." Modern RAG architectures include ingestion, preprocessing, retrieval, reranking, prompt construction, generation, evaluation, and monitoring.

Below is the industry-standard pipeline used by companies building AI assistants (OpenAI, Anthropic ecosystem, Microsoft, LangChain, LlamaIndex, AWS Bedrock, etc.).

Best practices for a modern production RAG system

  • Ingestion: Incrementally index new or changed documents rather than rebuilding the entire index.
  • Chunking: Use structure-aware chunking (headings, tables, code blocks) instead of fixed character counts when possible.
  • Retrieval: Combine dense vector search with keyword search (hybrid retrieval) and apply metadata filters for tenant, department, permissions, or date.
  • Ranking: Retrieve a larger candidate set (e.g., top 20–50) and rerank down to the best 3–10 chunks before generation.
  • Security: Enforce document-level access control during retrieval so users only receive content they are authorized to access.
  • Prompting: Instruct the model to answer only from the retrieved context and acknowledge when the answer cannot be found.
  • Observability: Log retrieval scores, latency, token usage, citations, and user feedback to continuously evaluate and improve the system.
  • Scalability: Cache embeddings, frequent queries, and generated responses where appropriate to reduce latency and cost.

If you're building this in your AWS/React/Node.js stack, a common production architecture is:

  • Frontend: React or React Native
  • API: AWS API Gateway + Lambda (Node.js)
  • Document Storage: Amazon S3
  • Embedding Pipeline: Lambda or batch jobs invoking an embedding model
  • Vector Database: PostgreSQL with pgvector, MongoDB Atlas Vector Search, or Qdrant
  • LLM: OpenAI GPT-5.5
  • Monitoring: CloudWatch for infrastructure plus a RAG evaluation framework such as RAGAS or LangSmith for retrieval quality and answer evaluation.
