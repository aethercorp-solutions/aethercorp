Long context in an LLM

Long context in an LLM (Large Language Model) refers to how much information the model can remember and use within a single conversation or prompt. The context is measured in tokens, not words.

Think of it like human working memory

  • Short context: You remember only the last few paragraphs of a conversation.
  • Long context: You can remember an entire book, multiple source files, or hours of conversation while answering questions.

Example

Suppose you provide:

  • 200-page PDF
  • 50 JavaScript files
  • Your resume
  • API documentation
  • Your question

If the model's context window is large enough, it can consider all of that simultaneously instead of forgetting earlier parts.

[Document B]
[Codebase]
[Conversation]

What is a context window?

A context window is the maximum number of tokens the model can process at once.

Approximate conversions:

  • 1 token ≈ 0.75 English words
  • 100 tokens ≈ 75 words
  • 1,000 tokens ≈ 750 words

So:

Context Window Rough Equivalent
8K tokens ~6,000 words
32K tokens ~24,000 words
128K tokens ~96,000 words
1M tokens ~750,000 words (roughly several large books)

Why is long context useful?

1. Large codebases

Instead of showing only one file:


auth.js
user.js
payment.js
routes.js
database.js
...

you can provide the entire project.

The LLM can answer questions like:

"Find every place where JWT tokens are created."

or

"Refactor authentication across the whole project."

2. Long conversations

Without long context:


You: Remember my architecture?
LLM: Sorry, I forgot.

With long context:


You: Remember the MongoDB schema we discussed 2 hours ago?
LLM: Yes, here's the schema...

3. Multiple documents

For example:

  • Company handbook
  • Product requirements
  • Meeting transcript
  • Design document

Then ask:

"Summarize all conflicting requirements."

4. Legal or research work

You can load:

  • Contracts
  • Research papers
  • Financial reports

and ask the model to compare or analyze them together.

Does a larger context window make the model smarter?

No.

A larger context window increases how much information the model can consider at once, not its reasoning ability.

Think of it this way:

  • Small desk → You can only spread out a few papers.
  • Large desk → You can spread out hundreds of papers.

Your ability to think hasn't changed—only how much information is immediately available.

Are there trade-offs?

Yes.

  • More computation: Larger contexts generally require more processing.
  • Higher cost: API usage often costs more because more input tokens are processed.
  • Potential dilution: If you include a lot of irrelevant information, it can make it harder for the model to focus on what's important.

Example in software development

Imagine you're interviewing for a senior backend role.

With a short context window, you might provide:


controllers/

and ask:

Explain this API.

With a long context window, you can provide:


controllers/
services/
repositories/
middleware/
models/
tests/
README
OpenAPI spec
Docker files
CI pipeline

Then ask:

"Review the architecture, identify performance bottlenecks, security issues, and suggest improvements."

The model can analyze the entire system together rather than one file at a time.

Summary

  • Long context is the amount of text (measured in tokens) an LLM can process and remember within a single prompt or conversation.
  • It enables analysis of large codebases, lengthy documents, and extended conversations without losing earlier information.
  • A larger context window improves the amount of information the model can use at once, but it does not inherently make the model better at reasoning.

Long context and RAG (Retrieval-Augmented Generation) both help an LLM answer questions using large amounts of information, but they solve different problems.

Feature Long Context RAG
How it works Put all information directly into the prompt Search for only the relevant information, then send it to the LLM
Data size Limited by the model's context window Can scale to millions or billions of documents
Speed Slower for very large inputs Usually faster because only relevant documents are retrieved
Cost Higher if you send lots of tokens every time Lower because fewer tokens are sent
Best for Documents that fit in the context window Large knowledge bases and frequently changing data

Example:


Prompt:

Question:
How does authentication work?

The model reads everything, even if only two files are relevant.

Advantages

  • Simple to implement.
  • The model can reason across all provided information.
  • Good when documents naturally fit in the available context.

Disadvantages

  • Expensive because every request includes all the data.
  • Slower as the amount of input grows.
  • Limited by the maximum context window.

Which is better?

It depends on the use case.

Use Long Context when:

  • You have a book, report, or codebase that fits comfortably in the context window.
  • You need the model to reason across many related documents simultaneously.
  • The information doesn't change frequently.

Use RAG when:

  • You have millions of documents.
  • Your data changes regularly (e.g., company wikis, support articles, databases).
  • You want lower latency and lower cost.

Modern AI systems often use both

Many production systems combine RAG with long-context models.


    Millions of documents
            │
    Vector Search (RAG)
            │
Retrieve 20 relevant documents
            │
    Long-context LLM
            │
        Final Answer

The retrieval system narrows the search space, and the long-context model reasons over all of the retrieved information.

Software development example

Suppose you're building an AI assistant for your company's codebase.

Long context only:

  • Send the entire repository (if it fits) with every request.
  • Good for small to medium projects.

RAG only:

  • Search for the most relevant files based on the question.
  • Send only those files to the model.
  • Good for very large repositories.

Combined approach (common in production):

  • Use RAG to retrieve the 20–100 most relevant files.
  • Feed those files into a long-context model.
  • The model can then reason across all the retrieved code, making it both scalable and efficient.

Prompt

A prompt is the input you give an LLM (Large Language Model) to tell it what you want it to do.

Think of it as the instructions + context + question that the model uses to generate a response.

Simple example

Prompt:


What is HTTP PATCH?

LLM Output:


HTTP PATCH is an HTTP method used to partially update a resource.

Everything you typed is the prompt.

A prompt can contain multiple parts

A prompt is often more than just a question.


Instruction
Context
Examples (optional)
Question

For example:


You are a senior Node.js engineer.

Explain this code to a junior developer.

Code:
function add(a, b) {
    return a + b;
}

The prompt contains:

  • Instruction: "You are a senior Node.js engineer."
  • Task: "Explain this code."
  • Context: The code snippet.

Prompt structure

A well-structured prompt often looks like this:


Role

Task

Context

Constraints

Output format

Example:


Role:
You are a backend architect.

Task:
Review this API.

Context:
Node.js
Express
MongoDB

Constraints:
Keep the answer under 300 words.

Output:
Bullet points.

Prompt vs Response

    │
    ▼
┌────────────┐

Example:

Prompt


Write a function to reverse a string.

↓

Response


function reverse(str) {
    return str.split("").reverse().join("");
}

Prompt engineering

Prompt engineering is the practice of designing prompts that help the model produce better results.

Instead of:


Explain caching.

You might write:


Explain caching like you're teaching a junior Node.js developer.

Include:
- What caching is
- Why it's useful
- Redis example
- Time complexity

The second prompt is more specific, so the response is more likely to match your needs.

Types of prompts

1. Question


What is Docker?

2. Instruction


Summarize this article.

3. Code generation


Write an Express middleware for JWT authentication.

4. Code explanation


Explain this React component line by line.

5. Transformation


Rewrite this email professionally.

6. Reasoning


Compare SQL and MongoDB for an e-commerce application.

How prompts fit into an LLM


        Prompt
            │
            ▼
Tokenization (convert text into tokens)
            │
            ▼
    Large Language Model
            │
            ▼
    Generates output tokens
            │
            ▼
        Response

The model doesn't understand text directly. It first breaks the prompt into tokens, processes those tokens using its neural network, and then predicts the next token repeatedly until it forms the complete response.

Real-world example

Suppose you're building an AI assistant for your application.

A user asks:


Find all users created after January 1, 2026 and sort them by last name.

That entire request is the prompt. The application might also prepend hidden instructions, such as:


You are a database assistant.
Only generate SQL.
Never modify data.

The combined text (system instructions + user request + any relevant context) is what the LLM actually receives as the prompt.

In one sentence

A prompt is all the information and instructions provided to an LLM so it can generate the desired response.
