Retrieval-Augmented Generation (RAG) application

If you're building a Retrieval-Augmented Generation (RAG) application, there are many excellent open-source frameworks. Each focuses on different parts of the RAG pipeline, such as document loading, embedding generation, vector search, retrieval, orchestration, or evaluation.

Here's an overview of the most popular ones.

Framework Best For Language Strengths
LangChain General-purpose RAG Python, JavaScript Large ecosystem, many integrations
LlamaIndex Document-centric RAG Python, TypeScript Excellent indexing and retrieval
Haystack Production search & QA Python Modular pipelines and enterprise features
DSPy Optimized LLM pipelines Python Automatically improves prompts and retrieval
FastRAG Fast production RAG Python Optimized for speed
RAGFlow Complete RAG platform Python UI + ingestion + retrieval
Pathway Streaming RAG Python Real-time indexing
txtai Semantic search Python Lightweight and easy to deploy

2. LlamaIndex

Designed specifically for RAG.

Instead of focusing on LLM workflows, it focuses on:

  • retrieval

Supports

  • Word

  • Notion

  • Google Drive
  • Slack
  • GitHub

Provides advanced retrieval techniques like

  • Recursive retrieval
  • Tree indexes
  • Graph indexes
  • Hybrid search
  • Metadata filtering

Excellent document support.

Vector databases commonly used with RAG

Most RAG frameworks integrate with vector databases such as:

  • Chroma
  • Milvus
  • Qdrant
  • Weaviate
  • FAISS
  • Pinecone (managed service, not open source)
  • OpenSearch (supports vector search)
  • Elasticsearch (supports vector search)

For your stack

Based on your previous questions, you're building a serverless backend with Node.js/AWS and exploring RAG implementations. A strong architecture would be:

  • Orchestration: LangChain (JavaScript/TypeScript)
  • Embeddings: a model from providers such as OpenAI or open-source embedding models
  • Vector database: Qdrant or Chroma for self-hosting, or OpenSearch if you're already using AWS
  • LLM: an API-hosted model or a self-hosted open-source model
  • Storage: Amazon S3 for documents and Amazon DynamoDB or your existing database for metadata

This combination is well supported, works well with AWS Lambda, and scales from prototypes to production systems.
