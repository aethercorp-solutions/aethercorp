Google OAuth

Google OAuth is basically a way to let a user log in with their Google account without giving your app their Google password.

Simple flow

Imagine your app has:

Your App → Google → Your App

  1. User clicks "Sign in with Google"
  2. Your app sends the user to Google
  3. Google asks the user to log in/approve access
  4. Google authenticates the user
  5. Google sends your app a code or token
  6. Your backend verifies it
  7. Your backend knows:
    • Who the Google user is
    • Their email
    • Their Google user ID
  8. Your backend creates your own session/JWT/access token
  9. Your app uses your token for future API requests

The important distinction

There are usually two different tokens/concepts involved:


Google OAuth
     ↓
Google authenticates user
     ↓
Google ID Token
     ↓
Your Backend verifies it
     ↓
Your Backend creates YOUR JWT
     ↓
Mobile/Web App uses YOUR JWT
     ↓
Your API

ID Token vs Access Token

ID Token

Answers:

"Who is this user?"

Example payload:


{
    "sub": "123456789",
    "email": "paul@example.com",
    "name": "Paul",
    "iss": "https://accounts.google.com",
    "aud": "your-client-id"
}

Your backend verifies the signature, issuer, audience, expiration, etc.

Access Token

Answers:

"What Google APIs is this user allowing my application to access?"

For example, if you want to access Google People API:


Your App
   ↓
Google OAuth
   ↓
Access Token
   ↓
Google People API

In your Node.js backend

The code you showed previously:


const loginTicket = await auth.verifyIdToken({
    idToken: id_token,
    audience: this.client_id
});

is Google ID-token authentication.

You're essentially telling Google:

"Google, please verify that this ID token was genuinely issued for my application."

Then:


const tokenPayload = loginTicket.getPayload();

gets information about the authenticated Google user.

Industry-standard architecture

For your Node.js + AWS Lambda setup, a common architecture is:


                ┌──────────────┐
                │    Google    │
                │    OAuth     │
                └──────┬───────┘
                       │
                 ID Token / Code
                       │
                       ▼
┌──────────┐     ┌──────────────┐
│ React /  │────▶│ API Gateway  │
│ iOS / RN │     └──────┬───────┘
└──────────┘            │
                        ▼
                 ┌──────────────┐
                 │ AWS Lambda   │
                 │ Node.js      │
                 └──────┬───────┘
                        │
                 Verify Google
                        │
                        ▼
                 ┌──────────────┐
                 │   MongoDB    │
                 └──────────────┘
                        │
                  Create YOUR JWT
                        │
                        ▼
                 Mobile/Web App

The key idea: Google proves who the user is. Your backend then establishes your application's authenticated session.

This is why OAuth ≠ JWT. OAuth is the authorization/authentication framework; JWT is one possible token format used within or after that flow.
