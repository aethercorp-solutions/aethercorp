Google People

Google People usually refers to Google's contacts service, which lets you store and manage people's contact information through your Google account.

What can you do with Google People?

  • Save contacts — Store names, phone numbers, email addresses, and profile photos.
  • Sync contacts — Keep your contacts synchronized across Android devices and Google services.
  • Organize people — Create contact groups and labels.
  • Manage contacts — Edit, merge duplicate contacts, or restore recently deleted contacts.
  • Access contacts — Use your contacts in Gmail, Google Meet, and other supported Google services.

Is Google People the same as Google Contacts?

Essentially, yes, but the names can refer to different things.

Name Meaning
Google People The contacts management system or underlying contacts functionality used by Google services.
Google Contacts The app and website used to manage your contacts.
Google People API A developer API for accessing and managing contact information and certain profile information with authorization.

Google People API for software developers

The Google People API is a REST API that allows your application to access and manage Google Contacts and certain profile information, provided the user grants the required permissions.

For example, if you're developing a mobile app with a Node.js backend, you can let users connect their Google account and import their Google contacts into your application.

1. What can you build with it?


Import Google Contacts
Retrieve contact names, email addresses, phone numbers, and other available contact fields.
            

Read the signed-in user's profile
Retrieve supported profile information, such as their name and email address, when the appropriate authorization is granted.
            

Synchronize contacts
Build features that synchronize contact data with your own application's database.
            

Build people-discovery features
Help users find people they already know by matching authorized contact information against your application's users.

Important: The API does not give your app unrestricted access to every Google user's contacts. Access depends on OAuth authorization, requested scopes, and Google's API policies.

2. How the architecture works

If you have a mobile application built with React Native or Flutter and a Node.js backend, a typical integration looks like this:


1. Mobile application
User taps "Import Google Contacts"
            

2. Google OAuth 2.0
User signs in and grants the requested permission
            

3. Node.js backend
Validates the session and securely accesses Google APIs
            

4. Google People API
Returns the authorized user's contact data
            

5. Application database
Optionally stores normalized contacts for application features

The API supports retrieving the authenticated user's contacts through people.connections.list.

3. Set up the Google People API

  1. Open the Google Cloud Console
  2. Create a project or select an existing project.
  3. Open APIs & Services → Library and enable the Google People API.
  4. Configure the OAuth consent screen and request the necessary scopes.
  5. Create OAuth credentials appropriate for your application.
  6. Implement the OAuth authorization flow and request the user's consent.

Official documentation: Google People API.

For read-only contact importing, the relevant scope is:

https://www.googleapis.com/auth/contacts.readonly

This allows your application to read the user's contacts without requesting permission to modify them.

4. Example implementation using Node.js

Once your OAuth flow has obtained a valid Google access token with the required scope, your backend can request contacts using the native fetch API.


async function getGoogleContacts(accessToken) {
    const url = new URL(
        "https://people.googleapis.com/v1/people/me/connections"
    );
    
    url.searchParams.set("personFields", "names,emailAddresses,phoneNumbers");
    url.searchParams.set("pageSize", "100");
    
    const response = await fetch(url, {
        headers: {
        Authorization: `Bearer ${accessToken}`,
        },
    });
    
    if (!response.ok) {
        throw new Error(
        `Google People API error: ${response.status} ${await response.text()}`
        );
    }
    
    const data = await response.json();
    
    return (data.connections || []).map((person) => ({
        name: person.names?.[0]?.displayName ?? null,
        email: person.emailAddresses?.[0]?.value ?? null,
        phone: person.phoneNumbers?.[0]?.value ?? null,
    }));
}

The sample demonstrates the API request and basic mapping. It assumes that authentication has already been completed; it does not implement OAuth itself. For production, also handle pagination using nextPageToken, token expiration, errors, and secure token storage.

5. Important OAuth distinction

Google People API is not the same as Google Sign-In.

Technology Primary purpose
Google Sign-In / OpenID Connect Authenticate the user and establish their identity
Google People API Retrieve or manage authorized contact and profile information
Google OAuth 2.0 Obtain permission to access the requested Google resources

You can use Google Sign-In without requesting access to a user's contacts. You need additional authorization if your app wants to import those contacts.

Also, contact access may require Google verification before a public application can request certain scopes in production. Review the OAuth verification requirements.
