Typical Express.js Application

In a typical Express.js application, these layers have different responsibilities:

1. App (app.js / server.js)

The app is the main entry point of your backend.

It:

  • creates the Express application
  • configures global middleware
  • connects routes
  • starts the server

Example:


const express = require('express');
const app = express();

app.use(express.json());

app.use('/auth', authRoutes);

app.listen(3000);

Think of it as:

“The main building where everything is connected.”

2. Router

A router organizes endpoints into modules.

Instead of putting all APIs in one file, routers group related routes.

Example:


const router = require('express').Router();

router.post('/login', authController.login);
router.post('/register', authController.register);

module.exports = router;

Mounted in app:


app.use('/auth', authRoutes);

Result:


POST /auth/login
POST /auth/register

Think of router as:

“Traffic director for URLs.”

It decides:

  • which endpoint exists
  • which middleware runs
  • which controller handles the request

3. Middleware

Middleware runs between request and response.

It can:

  • inspect request
  • modify request
  • authenticate users
  • validate data
  • log requests
  • stop request
  • continue request

Middleware signature:


(req, res, next)

Example:


const authMiddleware = (req, res, next) => {
    const token = req.headers.authorization;

    if (!token) {
        return res.status(401).json({
            message: 'Unauthorized'
        });
    }

    req.user = decodedUser;

    next();
};

Used like:


router.get('/profile', authMiddleware, profileController);

Flow:


Request
   ↓
Middleware
   ↓
Controller
   ↓
Response

Think of middleware as:

“Security guards or inspectors in the hallway.”

There are several middleware types:

Global Middleware

Runs for every request.


app.use(express.json());

Route Middleware

Runs only on specific routes.


router.get('/profile', authMiddleware, controller);

Error Middleware

Handles errors centrally.


app.use((err, req, res, next) => {
    res.status(500).json({
        message: err.message
    });
});

4. Controller

Controller handles the HTTP request/response logic.

It:

  • receives request data
  • calls services
  • returns API response

Example:


exports.login = async (req, res) => {
    const user = await authService.login(req.body);

    return res.json({
        status: true,
        data: user
    });
};

Controller should NOT contain:

  • database queries everywhere
  • large business logic
  • reusable core logic

Think of controller as:

“The waiter taking orders and returning food.”

Responsibilities:

  • request parsing
  • response formatting
  • calling services
  • handling HTTP status codes

5. Service

Service contains the business logic.

This is where the actual application behavior happens.

Example:


exports.login = async ({ email, password }) => {

    const user = await User.findOne({ email });

    if (!user) {
        throw new Error('User not found');
    }

    const valid = await bcrypt.compare(password, user.password);

    if (!valid) {
        throw new Error('Invalid password');
    }

    return generateToken(user);
};

Think of service as:

“The kitchen doing the real work.”

Services should:

  • contain reusable logic
  • interact with database
  • call external APIs
  • handle business rules

Services should NOT:

  • send HTTP responses
  • use res.json()
  • depend heavily on Express

Good services are reusable outside HTTP:

  • cron jobs
  • queues
  • CLI scripts
  • microservices

Full Flow Example

Request arrives


POST /auth/login

App receives request


app.use('/auth', authRoutes);

Router matches route


router.post('/login', validateLogin, authController.login);

Middleware executes


validateLogin

Checks:

  • email exists
  • password exists

Then:


next();

Controller executes


authController.login

Controller:

  • gets request body
  • calls service

const token = await authService.login(req.body);

Service executes


authService.login

Service:

  • queries database
  • validates password
  • generates JWT

Returns result to controller.

Controller sends response


res.json({
    token
});

Clean Architecture Example

Structure:


src/
 ├── app.js
 ├── routes/
 │    └── auth.routes.js
 ├── controllers/
 │    └── auth.controller.js
 ├── middleware/
 │    └── auth.middleware.js
 ├── services/
 │    └── auth.service.js
 ├── models/
 │    └── user.model.js

Real Analogy

Imagine a restaurant:

Layer Analogy Responsibility
App Building Connects everything
Router Receptionist Directs customers
Middleware Security guard Checks permissions
Controller Waiter Takes order
Service Kitchen Cooks food
Database Storage room Stores ingredients

Recommended Flow for Large Apps


Route
  ↓
Middleware
  ↓
Controller
  ↓
Service
  ↓
Model / Database

This separation makes:

  • cleaner code
  • easier debugging
  • reusable business logic
  • scalable architecture
  • easier testing
