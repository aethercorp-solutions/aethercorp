Send email from a Node.js + Express

A common way to send email from a Node.js + Express application is to use the popular email library Nodemailer.

Install Nodemailer


npm install nodemailer

Create an email utility


// email.js
const nodemailer = require("nodemailer");

const transporter = nodemailer.createTransport({
  service: "gmail",
  auth: {
    user: process.env.EMAIL_USER,
    pass: process.env.EMAIL_PASSWORD, // App Password for Gmail
  },
});

async function sendEmail(to, subject, html) {
  const info = await transporter.sendMail({
    from: `"My App" <${process.env.EMAIL_USER}>`,
    to,
    subject,
    html,
  });

  return info;
}

module.exports = sendEmail;

Create an Express route


// app.js
const express = require("express");
const sendEmail = require("./email");

const app = express();

app.use(express.json());

app.post("/send-email", async (req, res) => {
  try {
    const { to, subject, message } = req.body;

    await sendEmail(
      to,
      subject,
      `<h1>Hello!</h1><p>${message}</p>`
    );

    res.json({
      success: true,
      message: "Email sent successfully",
    });
  } catch (error) {
    console.error(error);
    res.status(500).json({
      success: false,
      error: error.message,
    });
  }
});

app.listen(3000, () => {
  console.log("Server running on port 3000");
});

Set environment variables

Create a .env file:


EMAIL_USER=your-email@gmail.com
EMAIL_PASSWORD=your-app-password

Then load it:


npm install dotenv
            

require("dotenv").config();

Gmail note

If you're using Gmail, use a Google App Password instead of your regular password. You can generate one from your Google Account security settings after enabling 2-Step Verification.

Production recommendation

For production applications, it's usually better to use a dedicated email provider rather than Gmail, such as:

  • SendGrid
  • Resend
  • Mailgun
  • Amazon SES

For example, with Resend:


npm install resend
            

const { Resend } = require("resend");

const resend = new Resend(process.env.RESEND_API_KEY);

await resend.emails.send({
  from: "noreply@yourdomain.com",
  to: "user@example.com",
  subject: "Welcome",
  html: "<h1>Welcome!</h1>",
});

If you're building a contact form, password reset flow, OTP system, or transactional email service, I can show a more complete production-ready example with templates, queues, retries, and rate limiting.

They're actually different things that work at different layers.

Nodemailer Dedicated Email Provider
A Node.js library An email delivery service
Runs in your application Runs on external infrastructure
Creates and sends email messages Delivers emails to recipients
Free/open-source Usually paid (with free tiers)
Needs an SMTP server or API behind it Provides SMTP servers and APIs

Analogy

Think of sending a package:

  • Nodemailer = the software you use to prepare the package and hand it off.
  • Resend, SendGrid, Mailgun, Amazon SES = the postal service that actually delivers it.

Option 1: Nodemailer + Gmail


const transporter = nodemailer.createTransport({
    service: "gmail",
    auth: {
        user: "you@gmail.com",
        pass: "app-password"
    }
});

Pros:

  • Easy to start
  • Good for development and small projects
  • No extra service to set up

Cons:

  • Sending limits
  • Emails may end up in spam more often
  • Not designed for high-volume transactional email
  • Harder to track delivery status

Option 2: Nodemailer + Dedicated Provider

You can still use Nodemailer, but connect it to a provider's SMTP server:


const transporter = nodemailer.createTransport({
    host: "smtp.sendgrid.net",
    port: 587,
    auth: {
        user: "apikey",
        pass: process.env.SENDGRID_API_KEY
    }
});

Pros:

  • Better deliverability
  • Domain authentication (SPF, DKIM, DMARC)
  • Analytics and logs
  • Higher sending limits

Cons:

  • Additional cost
  • Requires domain setup

Option 3: Provider SDK/API (No Nodemailer)

For example with Resend:


const { Resend } = require("resend");

const resend = new Resend(process.env.RESEND_API_KEY);

await resend.emails.send({
  from: "hello@yourdomain.com",
  to: "user@example.com",
  subject: "Welcome",
  html: "<h1>Hello</h1>"
});

Pros:

  • Simpler integration
  • Better error reporting
  • Modern APIs
  • Faster access to provider features

Cons:

  • Vendor-specific code
  • Need to learn each provider's API

What should you use?

For learning or small side projects

  • Nodemailer + Gmail is fine.

For production apps

  • Use a dedicated provider such as Resend, SendGrid, or Amazon SES
  • Prefer the provider's API/SDK over SMTP when available.

A common production stack today is:


Express API
    ↓
Resend SDK
    ↓
Resend Infrastructure
    ↓
Recipient Inbox

rather than:


Express API
    ↓
Nodemailer
    ↓
Gmail SMTP
    ↓
Recipient Inbox

The second approach works, but the first is generally more reliable and scalable once you have real users.
