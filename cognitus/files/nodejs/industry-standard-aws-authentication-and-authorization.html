Industry Standard Authentication and Authorization

In an industry-standard AWS + Node.js + Lambda architecture, authentication and authorization are separated into different responsibilities:

Industry Standard Authentication and Authorization

  • Authentication = “Who are you?”
  • Authorization = “What are you allowed to do?”

In serverless systems, these are commonly implemented using:

  • Amazon Web Services
  • AWS Lambda
  • Amazon API Gateway
  • Amazon Cognito
  • JWT access tokens
  • IAM policies
  • RBAC (Role-Based Access Control)

3. JWT Authentication Flow

Step 1 — User Logs In


POST /login
{
  "email": "admin@test.com",
  "password": "123456"
}

Step 2 — Server Validates Credentials

Example using bcrypt:


const bcrypt = require('bcrypt');

const isValid = await bcrypt.compare(password, user.passwordHash);

if (!isValid) {
   throw new Error('Invalid credentials');
}

Step 3 — Generate JWT


const jwt = require('jsonwebtoken');

const token = jwt.sign(
  {
    userId: user._id,
    role: user.role
  },
  process.env.JWT_SECRET,
  {
    expiresIn: '1h'
  }
);

JWT contains:


{
    "userId": "123",
    "role": "admin",
    "exp": 999999999
}

5. API Gateway Authentication

In AWS serverless:


Client
   ↓
API Gateway
   ↓
Lambda

API Gateway can validate JWT before Lambda executes.

Two common approaches:

OPTION A — API Gateway JWT Authorizer (Industry Standard)

Best modern approach.

Usually with:

  • Cognito
  • Auth0
  • Firebase
  • Azure AD

API Gateway validates:

  • Signature
  • Expiration
  • Issuer
  • Audience

If token invalid:


401 Unauthorized

Lambda never runs.

Flow


JWT Token
   ↓
API Gateway Authorizer
   ↓
Valid?
   ↓ yes
Lambda Executes

This reduces Lambda cost.

OPTION B — Lambda Middleware Validation

You manually validate token inside Lambda.

Example:


const jwt = require('jsonwebtoken');

exports.authMiddleware = async (event) => {

   const token = event.headers.Authorization;

   const decoded = jwt.verify(
      token.replace('Bearer ', ''),
      process.env.JWT_SECRET
   );

   return decoded;
};

Common when using:

  • Express.js inside Lambda
  • serverless-http
  • custom auth systems

6. Authorization (Permissions)

Authentication only says:


You ARE John.

Authorization says:


John CAN delete users.

This happens AFTER authentication.

7. Role-Based Access Control (RBAC)

Industry standard.

Example roles:


admin
manager
staff
customer

JWT Contains Role


{
    "userId": "123",
    "role": "admin"
}

Authorization Middleware


const authorize = (...roles) => {
    return (req, res, next) => {
    
        if (!roles.includes(req.user.role)) {
            return res.status(403).json({
                message: 'Forbidden'
            });
        }
    
        next();
    };
};

Usage


router.delete(
   '/users/:id',
   authenticate,
   authorize('admin'),
   deleteUser
);

8. Authentication vs Authorization

11. Lambda Authorizer

Custom authorization layer.

Used when:

  • Complex permission system
  • Multi-tenant SaaS
  • Dynamic permissions
  • External identity providers

Example


exports.handler = async (event) => {

    const token = event.authorizationToken;
    
    const decoded = jwt.verify(token, process.env.JWT_SECRET);
    
    return {
        principalId: decoded.userId,
        policyDocument: {
            Version: '2012-10-17',
            Statement: [
                {
                Action: 'execute-api:Invoke',
                Effect: 'Allow',
                Resource: event.methodArn
                }
            ]
        },
        context: {
            role: decoded.role
        }
    };
};

12. Best Practices (Industry Standard)

NEVER Store Sessions in Lambda Memory

Lambda is stateless.

Use:

  • JWT
  • Redis
  • DynamoDB

NOT:


global.user = ...

13. Use Access + Refresh Tokens

Standard architecture:

Token Lifetime
Access Token 15 mins–1 hour
Refresh Token Days/Months

14. Store Secrets Properly

Use:

  • AWS Secrets Manager
  • AWS Systems Manager Parameter Store

Lambda IAM roles should only access needed services.

21. Security Recommendations

Use HTTPS Only

Never allow plain HTTP.

Validate JWT Audience + Issuer

Prevents token spoofing.

Use Short Access Token Expiry

Example:


15 minutes

Implement Refresh Token Rotation

Enterprise-grade security.

22. Common Mistakes

Storing Passwords Plain Text

Always use:


bcrypt.hash(password, 10)

Trusting Client Roles

Never trust frontend role checks.

Backend must validate.

Putting Permissions Only in Frontend

Frontend checks are only UX.

Backend is real security.
