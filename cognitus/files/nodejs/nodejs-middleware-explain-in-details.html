Node.js, middleware

In Node.js, middleware is a function that runs between the incoming request and the final response in a web application. It acts like a processing layer that can inspect, modify, validate, log, authenticate, or even stop a request before it reaches the main route handler.

Middleware is most commonly used in Express.js applications.

Basic Flow of a Request

When a client sends a request:


Client Request
      ↓
Middleware 1
      ↓
Middleware 2
      ↓
Middleware 3
      ↓
Route Handler
      ↓
Response to Client

Each middleware decides whether to:

  • Continue to the next middleware
  • End the request immediately
  • Throw an error

Basic Middleware Syntax


function middleware(req, res, next) {
    console.log("Middleware executed");

    next();
}

Parameters

Parameter Meaning
req Incoming request object
res Response object
next Function that passes control to the next middleware

Example in Express.js


const express = require('express');
const app = express();

// Middleware
app.use((req, res, next) => {
    console.log('Request received:', req.method, req.url);

    next();
});

// Route
app.get('/', (req, res) => {
    res.send('Hello World');
});

app.listen(3000);

What Happens

  1. User visits /
  2. Middleware runs first
  3. Logs request info
  4. Calls next()
  5. Route handler executes
  6. Response sent

Why Middleware Is Important

Middleware is the backbone of most backend systems because it allows reusable logic.

Common uses:

Purpose Example
Authentication Verify JWT tokens
Logging Save API logs
Validation Check request body
Security Block malicious requests
Parsing Convert JSON body
CORS Allow frontend access
Error handling Catch server errors
Rate limiting Prevent spam requests

Types of Middleware

1. Application-Level Middleware

Runs for all routes or selected routes.


app.use((req, res, next) => {
    console.log('Global middleware');
    next();
});

2. Route-Level Middleware

Runs only on specific routes.


function auth(req, res, next) {
    console.log("Auth middleware");
    next();
}

app.get('/profile', auth, (req, res) => {
    res.send('Profile Page');
});

3. Built-in Middleware

Express already includes some middleware.

JSON Parser


app.use(express.json());

This converts incoming JSON into JavaScript objects.

Example request:


{
    "name": "Paul"
}

Accessible as:


req.body.name

4. Third-Party Middleware

Installed from npm.

Example:

CORS Middleware


npm install cors
            

const cors = require('cors');

app.use(cors());

Used when frontend and backend run on different domains.

5. Error-Handling Middleware

Special middleware with 4 parameters.


app.use((err, req, res, next) => {
    console.error(err.stack);

    res.status(500).json({
        message: 'Server Error'
    });
});

Understanding next()

next() is critical.

It tells Express:

"Continue to the next middleware."

Without it, the request hangs unless a response is sent.

Example WITHOUT next()


app.use((req, res, next) => {
    console.log("Middleware");
});

The browser waits forever because the request never continues.

Middleware Execution Order

Order matters.


app.use(middleware1);
app.use(middleware2);
app.use(middleware3);

Execution:


middleware1 → middleware2 → middleware3

If one middleware sends a response:


res.send("Blocked");

The chain stops.

Real Authentication Middleware Example

This is very common in APIs using JWT authentication.


const jwt = require('jsonwebtoken');

function verifyToken(req, res, next) {

    const token = req.headers.authorization;

    if (!token) {
        return res.status(401).json({
            message: 'Access denied'
        });
    }

    try {

        const verified = jwt.verify(
            token,
            process.env.JWT_SECRET
        );

        req.user = verified;

        next();

    } catch (err) {

        res.status(400).json({
            message: 'Invalid token'
        });
    }
}

Usage:


app.get('/dashboard', verifyToken, (req, res) => {

    res.json({
        user: req.user
    });

});

Middleware Chain Example


app.use(logger);
app.use(authenticate);
app.use(validateRequest);
app.use(compressResponse);

Async Middleware

Modern middleware often uses async/await.


app.use(async (req, res, next) => {

    try {

        const user = await User.findById(req.userId);

        req.user = user;

        next();

    } catch (err) {

        next(err);

    }
});

Advanced Concepts

Middleware Can Modify Requests


req.user = decodedToken;
req.requestTime = Date.now();

Data added in middleware becomes available later.

Middleware Can End Requests Early


if (!isAdmin) {
    return res.status(403).send('Forbidden');
}

Useful for security.

Difference Between Middleware and Route Handler

Middleware Route Handler
Pre-process request Final logic
Usually calls next() Usually sends response
Reusable Specific endpoint
Chainable Endpoint-specific

Example Full API Flow


app.post(
    '/api/orders',

    authenticate,
    validateOrder,
    checkInventory,

    async (req, res) => {

        const order = await createOrder(req.body);

        res.json(order);

    }
);

Flow:


Authenticate user
    ↓
Validate order data
    ↓
Check inventory
    ↓
Create order
    ↓
Return response

Best Practices

Keep Middleware Focused

Good:


authMiddleware()

Bad:


authAndLoggingAndValidationMiddleware()

Always Handle Errors


try {
    next();
} catch(err) {
    next(err);
}

Avoid Heavy Logic

Middleware should be lightweight and reusable.

Summary

Middleware in Node.js/Express is:

  • A function executed during request processing
  • Used to intercept and process requests
  • Essential for authentication, validation, logging, and security
  • Connected using the next() function
  • Executed in sequence
  • One of the core architectural concepts in backend development

Think of middleware as:

“Checkpoint layers” between the client request and your business logic.
