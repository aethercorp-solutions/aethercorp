The event loop in Node.js

The event loop in Node.js is what allows Node.js to handle many operations efficiently using a single thread. It’s the core mechanism behind Node’s non-blocking, asynchronous behavior.

🧠 Big idea (simple explanation)

Instead of waiting for tasks (like reading files or API calls) to finish, Node.js:

  • Starts the task
  • Moves on to other work
  • Comes back to handle the result later

The event loop is the system that keeps checking:

“Is anything finished? If yes, run its callback.”

🔄 How it works (step by step)

  1. Your code runs on the main thread
  2. When it hits an async operation (e.g., setTimeout, file read, HTTP request):
    • The task is handed off to the system (or thread pool)
  3. Once the task is done:
    • Its callback is placed into a queue
  4. The event loop:
    • Continuously checks the queue
    • Executes callbacks one by one when the main stack is free

🔁 Event loop phases (simplified)

The loop runs in cycles, with key phases like:

  1. Timers → executes setTimeout, setInterval
  2. I/O callbacks → handles system-level callbacks
  3. Idle/prepare
  4. Poll → retrieves new I/O events
  5. Check → executes setImmediate
  6. Close callbacks

Between these phases, Node also processes:

  • Microtasks (like Promise.then, process.nextTick) — these run before the next phase

🧪 Example


console.log("Start");

setTimeout(() => {
  console.log("Timeout");
}, 0);

Promise.resolve().then(() => {
  console.log("Promise");
});

console.log("End");

Output:


Start
End
Promise
Timeout

Why?

  • Synchronous code runs first (Start, End)
  • Microtasks (Promise) run before timers
  • Then the event loop processes the timer queue

⚡ Why it matters

The event loop lets Node.js:

  • Handle thousands of connections efficiently
  • Avoid blocking operations
  • Be ideal for I/O-heavy applications (APIs, real-time apps, streaming)

🧩 Key takeaway

The event loop is basically:

A continuous loop that manages and executes asynchronous callbacks when the call stack is empty.
