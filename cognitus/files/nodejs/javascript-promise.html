A JavaScript Promise

A JavaScript Promise is an object that represents the eventual completion (or failure) of an asynchronous operation and its resulting value.

Instead of blocking code while waiting for something (like a network request), Promises let your code continue running and handle the result later.

🔹 Basic Idea

A Promise has 3 states:

  • Pending → initial state (waiting)
  • Fulfilled → operation completed successfully
  • Rejected → operation failed

🔹 Creating a Promise


const myPromise = new Promise((resolve, reject) => {
    let success = true;
    
    if (success) {
        resolve("Operation successful!");
    } else {
        reject("Something went wrong.");
    }
});

🔹 Consuming a Promise


myPromise
  .then(result => {
    console.log(result); // if resolved
  })
  .catch(error => {
    console.error(error); // if rejected
});

🔹 Example with async task


function fetchData() {
    return new Promise((resolve, reject) => {
        setTimeout(() => {
            resolve("Data received!");
        }, 2000);
    });
}
    
fetchData().then(data => console.log(data));

🔹 Using async/await (modern way)


async function getData() {
    try {
        const result = await fetchData();
        console.log(result);
    } catch (error) {
        console.error(error);
    }
}
    
getData();

🔹 Why use Promises?

  • Avoid "callback hell"
  • Better readability and structure
  • Easier error handling
  • Works well with async/await

🔹 Quick Comparison

Callback style Promise style
Nested functions Chained .then()
Harder to read Cleaner
Error handling messy .catch()

async/await

In modern JavaScript, async/await is a cleaner way to work with Promises and asynchronous code. It makes async code look and behave more like synchronous code, which improves readability and debugging.

🔹 What is async?

An async function always returns a Promise.


async function greet() {
    return "Hello";
}
    
greet().then(console.log); // Hello

Even though you return a string, it’s wrapped in a Promise automatically.

🔹 What is await?

await pauses execution until a Promise is resolved (or rejected).


function delay(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
}
    
async function run() {
    console.log("Start");
    await delay(2000); // waits 2 seconds
    console.log("End");
}
    
run();

🔹 Example: Fetching data


async function getUser() {
    try {
        const response = await fetch("https://api.example.com/user");
        const data = await response.json();
        console.log(data);
    } catch (error) {
        console.error("Error:", error);
    }
}

🔹 Error handling

Use try...catch with await:


async function example() {
    try {
        let result = await Promise.reject("Something went wrong");
    } catch (err) {
        console.log(err);
    }
}

🔹 Parallel vs Sequential

Sequential (slower)


await task1();
await task2();

Parallel (faster)


await Promise.all([task1(), task2()]);

🔹 Key rules

  • await can only be used inside async functions (or top-level in modern environments)
  • async/await is just syntactic sugar over Promises
  • It does not block the main thread, only pauses within the function

🔹 When to use

Use async/await when:

  • You have multiple async operations
  • You want cleaner, more readable code
  • You need easier error handling than .then().catch()

Here are real-world JavaScript fetch() API examples using Promises so you can see how it’s used in actual applications.

🌐 1. Basic GET Request (Fetch Data from API)

Example using a public test API:


fetch("https://jsonplaceholder.typicode.com/posts/1")
  .then(response => {
    if (!response.ok) {
      throw new Error("Network response was not ok");
    }
    return response.json(); // convert response to JSON
  })
  .then(data => {
    console.log("Post:", data);
  })
  .catch(error => {
    console.error("Fetch error:", error);
});

🔹 What’s happening:

  • fetch() sends request
  • .then() handles response
  • response.json() parses JSON body
  • .catch() handles errors

🌐 2. POST Request (Send Data to Server)


fetch("https://jsonplaceholder.typicode.com/posts", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        title: "Hello World",
        body: "This is a test post",
        userId: 1
        })
    })
    .then(response => response.json())
    .then(data => {
        console.log("Created:", data);
    })
    .catch(error => {
        console.error("Error:", error);
});

🌐 3. Using async/await (Cleaner version)


async function getPost() {
    try {
        const response = await fetch("https://jsonplaceholder.typicode.com/posts/1");
    
        if (!response.ok) {
            throw new Error("HTTP error!");
        }
    
        const data = await response.json();
        console.log("Post:", data);
    } catch (error) {
        console.error("Error:", error);
    }
}
    
getPost();

🌐 4. Real App Example: Load list of users


async function loadUsers() {
    try {
        const response = await fetch("https://jsonplaceholder.typicode.com/users");
        const users = await response.json();
    
        users.forEach(user => {
            console.log(`${user.name} - ${user.email}`);
        });
    } catch (error) {
        console.error("Failed to load users:", error);
    }
}
    
loadUsers();

You must check manually:


if (!response.ok) throw new Error("HTTP error");

A fetch retry mechanism is used when an API request fails (network error, timeout, or temporary server issue) and you want to automatically try again before giving up.

🔁 1. Basic Fetch Retry (fixed number of attempts)


async function fetchWithRetry(url, options = {}, retries = 3) {
    try {
        const response = await fetch(url, options);
    
        if (!response.ok) {
            throw new Error(`HTTP error! status: ${response.status}`);
        }
    
        return await response.json();
    } catch (error) {
        if (retries > 0) {
            console.log(`Retrying... attempts left: ${retries}`);
        
            return fetchWithRetry(url, options, retries - 1);
        } else {
            throw error;
        }
    }
}

✅ Usage:


fetchWithRetry("https://jsonplaceholder.typicode.com/posts/1")
  .then(data => console.log("Success:", data))
  .catch(err => console.error("Failed after retries:", err));

⏱ 2. Retry with Delay (safer approach)

This avoids hammering the server instantly.


function wait(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
}
    
async function fetchWithRetry(url, options = {}, retries = 3, delay = 1000) {
    try {
        const response = await fetch(url, options);
    
        if (!response.ok) {
        throw new Error(`HTTP error! status: ${response.status}`);
        }
    
        return await response.json();
    } catch (error) {
        if (retries > 0) {
        console.log(`Retrying in ${delay}ms... (${retries} left)`);
    
        await wait(delay);
    
        return fetchWithRetry(url, options, retries - 1, delay);
        }
    
        throw error;
    }
}

📈 3. Exponential Backoff (best practice)

Each retry waits longer than the previous one:


function wait(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
}
    
async function fetchWithExponentialBackoff(url, options = {}, retries = 3, delay = 500) {
    try {
        const response = await fetch(url, options);
    
        if (!response.ok) {
        throw new Error(`HTTP error: ${response.status}`);
        }
    
        return await response.json();
    } catch (error) {
        if (retries > 0) {
        console.log(`Retrying in ${delay}ms...`);
    
        await wait(delay);
    
        return fetchWithExponentialBackoff(
            url,
            options,
            retries - 1,
            delay * 2 // exponential increase
        );
        }
    
        throw error;
    }
}

Example timing:

  • 1st retry → 500ms
  • 2nd retry → 1000ms
  • 3rd retry → 2000ms

⚠️ When NOT to retry

Avoid retrying when:

  • ❌ 400 Bad Request (client error)
  • ❌ 401 Unauthorized (bad token)
  • ❌ 403 Forbidden

Retry only for:

  • ⚠️ Network errors
  • ⚠️ 5xx server errors
  • ⚠️ Timeouts

🚀 Bonus: Smart retry condition


if (response.status >= 500) {
    // retry only server errors
}
