Authentication API

This code is an authentication API using Express.js, JWT, bcrypt, Firebase Admin SDK, and MongoDB/Mongoose.

This file defines authentication routes for an Express.js backend using:

  • Express.js for routing
  • JSON Web Token for authentication tokens
  • bcrypt for password hashing
  • Firebase Admin SDK for Google authentication
  • MongoDB/Mongoose User model for storing users

It supports:

  • User registration (/register)
  • User login (/login)
  • Google sign-in (/google)

Response


{
    "status": false,
    "message": "Email and password are required"

Searches MongoDB:


db.users.findOne({ email: email })

If user exists:


return res.status(400).json({
    status: false,
    message: 'User already exists',

STEP 5 — Hash Password


const hashedPassword = await bcrypt.hash(password, 10);

Important

10 = salt rounds.

Higher = more secure but slower.

Hashing process:


password -> salt -> encrypted hash

STEP 6 — Create User


const user = await User.create({
    email,
    password: hashedPassword,
    providers: { local: true },
});

Saves user into MongoDB.

Example saved document:


{
    "_id": "...",
    "email": "john@gmail.com",
    "password": "$2b$10$....",
    "providers": {
        "local": true
    }
}

    status: true,
    message: 'User registered successfully',
    data: {

        email: user.email,

catch (error)

Handles unexpected errors.

Duplicate MongoDB Key Error

MongoDB unique index violation.

Example:

{
    "status": false,
    "message": "Email already exists"

Generic Server Error

    status: false,
    message: 'Server error',
});

500 = backend failure.

Finally Block

    console.log('================ REGISTER REQUEST END ================');

Good for cleanup/logging.

A JWT has:

Frontend stores token:

  • AsyncStorage
  • cookies

Then sends token with requests:

Backend verifies token for protected routes.

let user = await User.findOneAndUpdate(

This is the most advanced part.

WHAT IS UPSERT?

Combination of:


UPDATE + INSERT

Meaning:

  • If user exists → update
  • If not → create

QUERY


{ email }

Find user by email.

$setOnInsert


$setOnInsert: {
    email,
    name,
    picture,
    firebaseUid: uid
},

Only applied when creating new user.

$set


$set: {
    'providers.google': true
}

Always applied.

Marks account as Google-authenticated.

OPTIONS


{
    upsert: true,
    returnDocument: 'after'
}

upsert: true

Create if not exists.

returnDocument: 'after'

Return updated document after changes.

WHY THIS FIX IS IMPORTANT

Without atomic upsert:


findOne()
create()

can cause race conditions.

Two requests could create duplicate users simultaneously.

Atomic upsert prevents that.

Excellent production-grade fix.
