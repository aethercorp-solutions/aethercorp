Zod

Zod is not specific to Next.js

Zod is a TypeScript-first schema validation library that can be used anywhere JavaScript or TypeScript runs:

  • ✅ Next.js
  • ✅ React
  • ✅ React Native
  • ✅ Node.js
  • ✅ Express.js
  • ✅ AWS Lambda
  • ✅ NestJS
  • ✅ Vue
  • ✅ Angular
  • ✅ CLI applications

Why use Zod?

It validates data at runtime and provides TypeScript type inference.

Example:


import { z } from "zod";

const UserSchema = z.object({
  name: z.string(),
  email: z.email(),
  age: z.number().min(18),
});

const result = UserSchema.safeParse({
  name: "Paul",
  email: "paul@example.com",
  age: 25,
});

if (!result.success) {
  console.log(result.error);
}

AWS Lambda Example


import { z } from "zod";

const QuoteSchema = z.object({
  name: z.string().min(2),
  email: z.email(),
  project: z.string().min(10),
});

export const handler = async (event) => {
  const body = JSON.parse(event.body);

  const validated = QuoteSchema.safeParse(body);

  if (!validated.success) {
    return {
      statusCode: 400,
      body: JSON.stringify(validated.error.flatten()),
    };
  }

  // Safe validated data
  const quote = validated.data;

  return {
    statusCode: 200,
    body: JSON.stringify({ message: "Success" }),
  };
};

Industry Standard Usage

For your AWS serverless projects (Lambda + API Gateway + DynamoDB), a common stack is:


Frontend (Next.js / React Native)
          ↓
      API Gateway
          ↓
      AWS Lambda
          ↓
    Zod Validation
          ↓
 DynamoDB / MongoDB

The key idea is: never trust client input. Validate every request in Lambda using Zod before writing to DynamoDB or processing business logic.

For a Request-for-Quote system, using Zod in the Lambda layer is considered an industry-standard approach.
