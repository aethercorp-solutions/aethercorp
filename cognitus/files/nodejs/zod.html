Zod

Zod is not specific to Next.js

Zod is a TypeScript-first schema validation library that can be used anywhere JavaScript or TypeScript runs:

  • ✅ Next.js
  • ✅ React
  • ✅ React Native
  • ✅ Node.js
  • ✅ Express.js
  • ✅ AWS Lambda
  • ✅ NestJS
  • ✅ Vue
  • ✅ Angular
  • ✅ CLI applications

Why use Zod?

It validates data at runtime and provides TypeScript type inference.

Example:


import { z } from "zod";

const UserSchema = z.object({
  name: z.string(),
  email: z.email(),
  age: z.number().min(18),
});

const result = UserSchema.safeParse({
  name: "Paul",
  email: "paul@example.com",
  age: 25,
});

if (!result.success) {
  console.log(result.error);
}

AWS Lambda Example


import { z } from "zod";

const QuoteSchema = z.object({
  name: z.string().min(2),
  email: z.email(),
  project: z.string().min(10),
});

export const handler = async (event) => {
  const body = JSON.parse(event.body);

  const validated = QuoteSchema.safeParse(body);

  if (!validated.success) {
    return {
      statusCode: 400,
      body: JSON.stringify(validated.error.flatten()),
    };
  }

  // Safe validated data
  const quote = validated.data;

  return {
    statusCode: 200,
    body: JSON.stringify({ message: "Success" }),
  };
};

Industry Standard Usage

For your AWS serverless projects (Lambda + API Gateway + DynamoDB), a common stack is:


Frontend (Next.js / React Native)
          ↓
      API Gateway
          ↓
      AWS Lambda
          ↓
    Zod Validation
          ↓
 DynamoDB / MongoDB

The key idea is: never trust client input. Validate every request in Lambda using Zod before writing to DynamoDB or processing business logic.

For a Request-for-Quote system, using Zod in the Lambda layer is considered an industry-standard approach.

This line of JavaScript:


const { z } = require("zod");

Simply means: load the z tool from the zod library so you can validate data.

Let's break it down.

1. What does each part mean?

  • require("zod") — loads the Zod library, which helps check whether data is valid.
  • { z } — extracts the z object from the library.
  • const — declares a variable that cannot be reassigned.

2. Simple example

Imagine your Castanet backend receives a contact's information. You want to make sure the contact has a valid name and email.


const { z } = require("zod");

const contactSchema = z.object({
  name: z.string(),
  email: z.string().email()
});

Here's what this means:

  • z.object() — defines the expected structure of the contact.
  • z.string() — requires a value to be text.
  • z.string().email() — requires a valid email format.

For example:

Valid Contact


{ name: "Paul", email: "paul@example.com" }

Invalid contact


{ name: 123, email: "not-an-email" }

The second example fails because the name is a number and the email format is invalid.

3. How do you actually validate the data?

Defining a schema describes the rules. To check data against those rules, use .parse():


const contact = {
    name: "Paul",
    email: "paul@example.com"
};

const result = contactSchema.parse(contact);

If the data is valid, .parse() returns it. If the data is invalid, it throws an error.

Remember it this way

Zod is like a security guard for your data. It checks whether incoming data matches the rules you defined before your application processes it.

For a Node.js API such as Castanet's, you can use Zod to validate request bodies, query parameters, and other incoming data before saving it to MongoDB.
