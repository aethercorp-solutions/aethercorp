Authentication and Authorization

In backend systems like Node.js + Express.js APIs, authentication and authorization solve two completely different problems.

1. Authentication = “Who are you?”

Authentication verifies identity.

When you see:


"authentication": "JWT validation"

it means:

The server checks whether the JWT token is real, valid, signed correctly, and not expired.

The system is asking:

  • Did this token come from a trusted server?
  • Is the user logged in?
  • Is the token expired?
  • Was the token tampered with?

If valid → user is authenticated.

JWT Authentication Flow

Step 1 — User logs in


Email + Password

Server verifies credentials.

Step 2 — Server creates JWT

Example:


const token = jwt.sign(
  {
    userId: "123",
    email: "paul@email.com"
  },
  SECRET_KEY,
  { expiresIn: '1h' }
);

Step 3 — Client sends token


Authorization: Bearer eyJhbGciOi...

Step 4 — Middleware validates JWT


const jwt = require('jsonwebtoken');

function authenticate(req, res, next) {
    const authHeader = req.headers.authorization;

    if (!authHeader) {
        return res.status(401).json({
            message: 'No token'
        });
    }

    const token = authHeader.split(' ')[1];

    try {
        const decoded = jwt.verify(token, SECRET_KEY);

        req.user = decoded;

        next();
    } catch (err) {
        return res.status(401).json({
            message: 'Invalid token'
        });
    }
}

This is:

Authentication

The server now knows:


req.user = {
    userId: "123",
    email: "paul@email.com"
}

But the server still does NOT know what the user is allowed to do.

That is authorization.

2. Authorization = “What are you allowed to do?”

Authorization checks permissions AFTER authentication succeeds.

When you see:


"authorization": "role-based access"

it means:

The system decides access based on user roles.

Example roles:


admin
manager
staff
customer

The system asks:

  • Can this user access admin routes?
  • Can this user delete users?
  • Can this user edit products?
  • Can this user view reports?

Role-Based Access Control (RBAC)

Example JWT payload:


{
    userId: "123",
    role: "admin"
}

Authorization middleware:


function authorize(roles = []) {
    return (req, res, next) => {

        if (!roles.includes(req.user.role)) {
            return res.status(403).json({
                message: 'Forbidden'
            });
        }

        next();
    };
}

Usage:


app.delete(
   '/users/:id',
   authenticate,
   authorize(['admin']),
   deleteUserController
);

Request Flow


1. User sends JWT
        ↓
2. Authentication middleware validates JWT
        ↓
3. req.user created
        ↓
4. Authorization middleware checks role
        ↓
5. Access granted or denied

Real-World Analogy

Authentication

Security guard checks your ID card.


"Are you really Paul?"

Authorization

After identity is verified:


"Are you allowed inside the server room?"

You may be authenticated but still forbidden.

Common HTTP Status Codes

Authentication Failure


401 Unauthorized

Means:


"You are NOT logged in."

Examples:

  • Missing token
  • Invalid JWT
  • Expired JWT

Authorization Failure


403 Forbidden

Means:


"You are logged in BUT not allowed."

Example:

  • Normal user accessing admin panel

Full Example


app.get(
   '/admin/dashboard',
   authenticate,
   authorize(['admin']),
   adminDashboardController
);

Case 1 — Invalid Token

Fails at authentication.

Response:


401 Unauthorized

Case 2 — Valid Token but role=user

Fails at authorization.

Response:


403 Forbidden

Simple Summary

Concept Purpose Question
Authentication Verify identity “Who are you?”
Authorization Verify permissions “What can you do?”

JWT Validation vs Role-Based Access

Feature JWT Validation Role-Based Access
Type Authentication Authorization
Checks Token validity User permissions
Uses jwt.verify() role checking
Result Logged in Access granted
Failure Code 401 403
