API authentication with Bearer tokens and JWTs (JSON Web Tokens)

API authentication with Bearer tokens and JWTs (JSON Web Tokens) is one of the most common patterns in modern web and mobile applications.

How it works

Step 1: User logs in

The client sends credentials to the backend:


const response = await fetch("https://api.example.com/login", {
    method: "POST",
    headers: {
        "Content-Type": "application/json"
    },
    body: JSON.stringify({
        email: "user@example.com",
        password: "password123"
    })
});

const data = await response.json();

console.log(data.token);

Example response:


{
    "token": "eyJhbGciOiJIUzI1NiIs..."
}

This token is usually a JWT.

Step 2: Store the token

React Native

Avoid storing tokens in AsyncStorage for sensitive apps. Consider using secure storage solutions such as:

  • react-native-keychain
  • expo-secure-store

Example:


import * as Keychain from 'react-native-keychain';

await Keychain.setGenericPassword(
  'token',
  data.token
);

Step 3: Send the token in requests

The token goes in the Authorization header.


const token = "eyJhbGciOiJIUzI1NiIs...";

const response = await fetch(
  "https://api.example.com/profile",
  {
    headers: {
      Authorization: `Bearer ${token}`
    }
  }
);

const profile = await response.json();

console.log(profile);

HTTP request:


GET /profile HTTP/1.1
Host: api.example.com
Authorization: Bearer eyJhbGciOiJIUzI1NiIs...

Complete Fetch Wrapper

Instead of repeating the Authorization header everywhere:


async function apiFetch(url, options = {}) {
    const token = await getToken();
    
    const response = await fetch(url, {
        ...options,
        headers: {
        ...options.headers,
        Authorization: `Bearer ${token}`,
        "Content-Type": "application/json"
        }
    });
    
    if (!response.ok) {
        throw new Error(`HTTP Error: ${response.status}`);
    }
    
    return response.json();
}

Usage:


const user = await apiFetch(
  "https://api.example.com/profile"
);

console.log(user);

JWT Structure

A JWT consists of three parts:


xxxxx.yyyyy.zzzzz
  • Header
  • Payload
  • Signature

Example:


eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9
.
eyJ1c2VySWQiOjEyMywicm9sZSI6ImFkbWluIn0
.
abc123xyz456

The payload often contains:


{
    "userId": 123,
    "email": "user@example.com",
    "role": "admin",
    "exp": 1780000000
}

Node.js Backend Example

Using jsonwebtoken:


const jwt = require("jsonwebtoken");

app.post("/login", (req, res) => {
  const user = {
    id: 123,
    email: "user@example.com"
  };

  const token = jwt.sign(
    user,
    process.env.JWT_SECRET,
    { expiresIn: "1h" }
  );

  res.json({ token });
});

Verifying JWT on Protected Routes


const jwt = require("jsonwebtoken");

function authenticate(req, res, next) {
  const authHeader = req.headers.authorization;

  if (!authHeader) {
    return res.sendStatus(401);
  }

  const token = authHeader.split(" ")[1];

  jwt.verify(
    token,
    process.env.JWT_SECRET,
    (err, user) => {
      if (err) {
        return res.sendStatus(403);
      }

      req.user = user;
      next();
    }
  );
}

Protected endpoint:


app.get(
  "/profile",
  authenticate,
  (req, res) => {
    res.json({
      user: req.user
    });
  }
);

Token Refresh Pattern (Production)

Access tokens should be short-lived:


Access Token  : 15 minutes
Refresh Token : 30 days

Flow:


Login
  ↓
Access Token expires
  ↓
Client sends Refresh Token
  ↓
Server issues new Access Token
  ↓
Continue using API

This is the pattern used by many services, including Auth0, Firebase Authentication, and Amazon Cognito.

For your AWS Lambda + API Gateway setup

A common architecture is:


React Native
    ↓
Amazon Cognito
    ↓
JWT Access Token
    ↓
API Gateway Authorizer
    ↓
AWS Lambda
    ↓
MongoDB

In this setup, API Gateway validates the JWT before the request reaches Lambda, reducing custom authentication code in your functions.
