Namespaced APIs and Modular APIs

The terms Namespaced APIs and Modular APIs are commonly used when talking about libraries such as Firebase, especially when migrating from the older Firebase JavaScript SDK to the modern SDK.

The main difference is how you import and access functionality.

1. Namespaced API — older style

Everything is accessed through a central object/namespace.


import firebase from 'firebase/app';
import 'firebase/auth';
import 'firebase/firestore';

firebase.initializeApp(config);

const auth = firebase.auth();
const db = firebase.firestore();

firebase.auth().signInWithEmailAndPassword(email, password);

firebase.firestore()
  .collection('users')
  .doc(userId)
  .get();

The important characteristic is:


firebase
   ├── auth()
   ├── firestore()
   ├── storage()
   └── messaging()

You access functionality through the firebase namespace.

This was the traditional Firebase JavaScript API.

2. Modular API — modern style

Functionality is imported individually and used directly.


import { initializeApp } from 'firebase/app';
import { getAuth, signInWithEmailAndPassword } from 'firebase/auth';
import { getFirestore, collection, doc, getDoc } from 'firebase/firestore';

const app = initializeApp(config);

const auth = getAuth(app);
const db = getFirestore(app);

await signInWithEmailAndPassword(auth, email, password);

const userDoc = await getDoc(
  doc(db, 'users', userId)
);

Instead of:


firebase.auth()
firebase.firestore()

you use:


getAuth(app)
getFirestore(app)

And instead of methods chained from objects:


firebase.firestore()
  .collection('users')
  .doc(userId)
  .get()

you use individual functions:


getDoc(
  doc(
    collection(db, 'users'),
    userId
  )
)

The easiest way to visualize it

Namespaced


firebase
   │
   ├── auth()
   │     └── signInWithEmailAndPassword()
   │
   ├── firestore()
   │     └── collection()
   │           └── doc()
   │                 └── get()
   │
   └── storage()

You start from a big namespace and navigate downward.

Modular


    initializeApp()
       │
       ├── getAuth()
       │      └── signInWithEmailAndPassword()
       │
       └── getFirestore()
              ├── collection()
              ├── doc()
              └── getDoc()

You import only the functions you need.

Why Firebase moved to Modular APIs

One of the biggest reasons is tree shaking and bundle size.

With a namespaced API, your code tends to revolve around a large Firebase object:


firebase.firestore()
firebase.auth()
firebase.storage()

The modular API makes dependencies much more explicit:


import { getAuth } from 'firebase/auth';
import { getFirestore, getDoc, doc } from 'firebase/firestore';

A bundler can determine more precisely which pieces of Firebase your application actually uses and remove unused code.

For example:


import { getAuth } from 'firebase/auth';

is much more explicit than:


import firebase from 'firebase';

This can improve bundle size, tree-shaking, and maintainability.

Side-by-side Firebase example

Operation Namespaced API Modular API
Initialize firebase.initializeApp() initializeApp()
Auth firebase.auth() getAuth(app)
Firestore firebase.firestore() getFirestore(app)
Get document .doc().get() getDoc(doc())
Query .collection().where() query(collection(), where())
Add document .add() addDoc()
Update .update() updateDoc()
Delete .delete() deleteDoc()

Example: Firestore

Namespaced:


const db = firebase.firestore();

db.collection('users')
  .doc('123')
  .get()
  .then(doc => {
    console.log(doc.data());
  });

Modular:


const db = getFirestore(app);

const userRef = doc(db, 'users', '123');

const snapshot = await getDoc(userRef);

console.log(snapshot.data());

One important distinction

Namespaced vs Modular is not the same thing as Firebase version itself.

For example:


Old Firebase SDK
        ↓
Namespaced API

versus:


Modern Firebase SDK
        ↓
Modular API

The modern Firebase SDK introduced the modular API while also retaining compatibility with the older namespaced API for a period.

So you may encounter code like:


firebase.auth()

in an application using a relatively recent Firebase version. That doesn't necessarily mean the entire Firebase SDK is ancient—it may simply mean the application is still using the compatibility/namespaced style.

In short

Namespaced API:

"Give me the Firebase object, then I'll call methods on it."


firebase.auth().currentUser

Modular API:

"Give me the specific Firebase functions I need, and I'll compose them."


getAuth(app).currentUser

For a modern React/React Native project, Modular APIs are generally the style you will encounter in current Firebase documentation and new code.
