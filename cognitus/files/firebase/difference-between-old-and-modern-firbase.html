Difference between Old and Modern Firebase

The biggest difference is that “old Firebase” usually refers to the older Firebase SDK/API patterns and architecture, while modern Firebase uses the modular SDKs, newer APIs, better tooling, and current Google Cloud integrations.

For a React Native / iOS / Node.js developer, the differences look like this:

Area Older Firebase Modern Firebase
SDK style Namespaced APIs Modular APIs
JavaScript firebase.database() getDatabase(app)
Initialization Often global Firebase object Explicit initializeApp()
React Native Older react-native-firebase patterns @react-native-firebase/* or Firebase JS modular SDK depending on feature
Authentication Older auth APIs Modern modular Auth APIs
Firestore Namespaced API Modular Firestore API
Realtime Database firebase.database() getDatabase()
Cloud Functions Older Functions SDK/runtime patterns Modern Functions SDK + newer Node runtimes
Cloud Messaging Older FCM implementations Current FCM/APNs integration
Analytics Older Firebase Analytics APIs Current Google Analytics for Firebase
Deployment Older Firebase CLI/tooling Modern Firebase CLI + Cloud tooling
Cloud backend More Firebase-centric Firebase + Google Cloud integration
Security Older rules/API practices Current Security Rules + App Check + IAM integration
Architecture Firebase as mostly standalone platform Firebase as frontend platform integrated with Google Cloud

1. The biggest JavaScript difference: namespaced → modular

Old Firebase:


import firebase from 'firebase/app';
import 'firebase/firestore';

const db = firebase.firestore();

db.collection('users')
  .doc(userId)
  .get();

Modern Firebase:


import { initializeApp } from 'firebase/app';
import { getFirestore, doc, getDoc } from 'firebase/firestore';

const app = initializeApp(firebaseConfig);
const db = getFirestore(app);

const userDoc = await getDoc(doc(db, 'users', userId));

The modern approach imports only the functionality you need.

That makes dependencies easier to reason about and can improve tree-shaking/bundle size.

2. Realtime Database

Old style:


const database = firebase.database();

database
  .ref('users/' + userId)
  .once('value');

Modern style:


import {
    getDatabase,
    ref,
    get
} from 'firebase/database';

const db = getDatabase();

const snapshot = await get(
    ref(db, `users/${userId}`)
);

The underlying Firebase Realtime Database concept is still essentially the same.

It's mostly the SDK/API style that changed.

3. Firestore

Old:


firebase.firestore()
  .collection('users')
  .where('active', '==', true)
  .get();

Modern:


const usersRef = collection(db, 'users');

const q = query(
  usersRef,
  where('active', '==', true)
);

const snapshot = await getDocs(q);

Modern Firestore separates operations into explicit functions:


collection()
doc()
query()
where()
orderBy()
getDocs()
addDoc()
updateDoc()
deleteDoc()

This is one of the most noticeable changes when maintaining an older Firebase project.

4. Firebase Authentication

Old:


firebase.auth()
  .signInWithEmailAndPassword(email, password);

Modern:


import {
    getAuth,
    signInWithEmailAndPassword
} from 'firebase/auth';

const auth = getAuth();

await signInWithEmailAndPassword(
    auth,
    email,
    password
);

Again, the authentication service itself hasn't fundamentally changed.

The client SDK API has become more modular.

5. Cloud Functions changed considerably

This is more important for your Castanet backend.

Older Firebase Functions commonly looked like:


const functions = require('firebase-functions');

exports.myFunction = functions.https.onRequest(
  (req, res) => {
    res.send('Hello');
  }
);

Modern Functions commonly use newer SDK patterns:


const { onRequest } =
  require('firebase-functions/v2/https');

exports.myFunction = onRequest(
  (req, res) => {
    res.send('Hello');
  }
);

Modern Cloud Functions support 2nd generation functions, which are built on newer Google Cloud infrastructure.

That brings things such as:

  • better scalability
  • concurrency
  • longer execution options
  • more configurable CPU/memory
  • better integration with Cloud Run
  • improved deployment behavior

So this isn't merely a syntax change.

6. Node.js versions matter

This is especially important for older Firebase projects.

An old project might have been built around:


Node.js 12
Node.js 14
Node.js 16

Modern Firebase/Google Cloud projects use currently supported Node.js runtimes.

So when upgrading an old project, you may have to update:


Node.js
Firebase Functions SDK
Firebase CLI
package.json
Cloud Functions API
deployment configuration

This can expose compatibility problems in old dependencies.

7. Firebase Console also evolved

The Firebase Console is still recognizable:


    Firebase Console
       │
       ├── Authentication
       ├── Firestore
       ├── Realtime Database
       ├── Storage
       ├── Functions
       ├── Messaging
       ├── Analytics
       └── Crashlytics

But modern Firebase is much more closely integrated with Google Cloud.

For example:


Firebase
   │
   └── Google Cloud
         ├── Cloud Functions
         ├── Cloud Run
         ├── IAM
         ├── Cloud Logging
         ├── Secret Manager
         ├── Pub/Sub
         └── Cloud Monitoring

This is particularly useful for larger applications.

9. App Check is an important modern concept

Older Firebase applications often relied primarily on:


Firebase Authentication
+
Security Rules

Modern Firebase can additionally use Firebase App Check.

Conceptually:


Old

Mobile App
    │
    ▼
Firebase Auth
    │
    ▼
Firebase

Modern:


Mobile App
    │
    ├── Authentication
    │
    └── App Check
          │
          ▼
       Firebase

App Check helps services distinguish requests coming from your legitimate application from requests coming from unauthorized clients.

10. FCM changed too

Firebase Cloud Messaging has evolved significantly.

Older mobile implementations often had more Firebase-specific setup directly in the application.

Modern FCM integrates more explicitly with:


Android
   ↓
FCM

iOS
   ↓
APNs
   ↓
FCM

For iOS, Firebase still ultimately works with Apple's APNs infrastructure.

This is particularly relevant to your Castanet React Native app, because you're dealing with:


Firebase
FCM
APNs
React Native
iOS
UIScene

The Firebase SDK itself isn't what requires your UIScene migration. That's an Apple/iOS lifecycle change, separate from Firebase.

11. Firebase SDK versions are now much more important

For example, your older Castanet environment has Firebase SDKs around the older generation.

You might encounter something like:


Old:

Firebase 9.x
React Native Firebase older version
React Native 0.68.x
older iOS integration

versus a modern stack:


Modern:

Current Firebase iOS SDK
Current React Native Firebase
React Native newer version
Xcode current
iOS current
APNs/FCM current integration

You shouldn't assume that simply upgrading Firebase will solve everything.

There are several independent layers:


            Your App
                │
         React Native
                │
      React Native Firebase
                │
         Firebase SDK
                │
      Apple / Google APIs
                │
         iOS / Android

An upgrade at one layer can require changes at another.

12. One important misconception

Modern Firebase does NOT mean that Firebase services themselves were completely redesigned.

For example:


Firebase Realtime Database

is still fundamentally a JSON tree database.

And:


Firestore

is still a document database.

The major changes are often:


SDK APIs
+
runtime versions
+
Cloud Functions architecture
+
security capabilities
+
Google Cloud integration
+
mobile platform requirements
+
developer tooling

For your Castanet project specifically

Your architecture is roughly:


                Castanet Mobile
                React Native
                     │
          ┌──────────┼──────────┐
          │          │          │
      Firebase    FCM/Auth    Analytics
          │
          ▼
    Firebase / Google Cloud
          │
          ▼
    Castanet API
          │
          ▼
    AWS Lambda / MongoDB

So if you're asking because you're upgrading the old Castanet Firebase implementation, I'd separate the work into four categories:

Upgrade What changes
Firebase SDK APIs/dependencies
React Native Firebase Native module compatibility
iOS/Xcode AppDelegate → UIScene, SDK compatibility
Firebase backend Functions/runtime/CLI/security

The UIScene issue you're currently working on is primarily an iOS 26/27 + Xcode lifecycle compatibility issue, not a "modern Firebase" requirement. Firebase can be modernized separately.
