Axios Architecture

A common production structure looks like this:


src/
 ├── api/
 │    ├── axios.ts          // axios instance
 │    ├── auth.ts           // login/logout APIs
 │    ├── users.ts          // user APIs
 │    └── products.ts
 │
 ├── services/
 │    └── TokenStorage.ts
 │
 ├── hooks/
 │    └── useAuth.ts
 │
 └── middleware/
      └── authMiddleware.ts

Never call axios.get() directly throughout your app.

Instead:


UI
   ↓
API Service
   ↓
Axios Instance
   ↓
Server

This keeps authentication logic centralized.

1. Create an Axios Instance


import axios from "axios";

const api = axios.create({
    baseURL: process.env.NEXT_PUBLIC_API_URL,
    timeout: 10000,
    headers: {
        "Content-Type": "application/json"
    }
});

export default api;

Every request now shares the same configuration.

2. Request Interceptors

Request interceptors run before sending the request.

Typical uses:

  • Attach access token
  • Attach language
  • Logging
  • Add request ID
  • Modify headers

Example:


api.interceptors.request.use(async (config) => {

    const token = await TokenStorage.getToken();

    if (token) {
        config.headers.Authorization = `Bearer ${token}`;
    }

    return config;
});

3. Response Interceptors

Runs after every response.

Good for

  • Global error handling
  • Token expiration
  • Logging
  • Retry logic

Example


api.interceptors.response.use(

    response => response,

    error => {

        if (error.response?.status === 401) {

        }

        return Promise.reject(error);
    }

);

10. Handling Multiple Requests During Refresh

This is one of the trickiest parts.

Imagine:


Request A

↓

401

At the same moment:


Request B

↓

401

Without coordination:


Refresh #1

Refresh #2

Refresh #3

Refresh #4

This creates unnecessary load and race conditions.

Instead:


First request

↓

Refresh Token

↓

Other requests WAIT

↓

New Token

↓

All waiting requests continue

Implementation


let isRefreshing = false;

let failedQueue = [];

If already refreshing:


if (isRefreshing) {

    return new Promise((resolve,reject)=>{

        failedQueue.push({
            resolve,
            reject
        });

    });

}

After Refresh Completes


failedQueue.forEach(p=>{

    p.resolve(newToken);

});

failedQueue = [];

Waiting requests automatically continue.

Best Practices

  • Use one Axios instance for authenticated requests.
  • Store access tokens in memory or secure storage (depending on your platform), and keep refresh tokens in the most secure storage available.
  • Add the access token only in a request interceptor.
  • Handle 401 Unauthorized only in a response interceptor.
  • Mark retried requests (for example, with an _retry flag) to avoid infinite refresh loops.
  • Ensure only one refresh request is in flight at a time by queueing failed requests.
  • Retry the original request automatically after obtaining a new access token.
  • If the refresh token is invalid or expired, clear authentication state and redirect the user to sign in again.
  • Consider rotating refresh tokens if your backend supports it, replacing the stored refresh token whenever the server issues a new one.

This pattern is widely used in React, Next.js, React Native, Vue, Angular, and Node.js applications because it provides a seamless authentication experience while keeping token management centralized.

Core Features

Axios is heavily preferred over JavaScript's built-in fetch API because it drastically reduces boilerplate code:

  • Promise-Based: Built entirely on the modern ES6 Promise API, enabling clean async/await syntax.
  • Automatic JSON Transformation: Automatically serializes outgoing data and parses incoming JSON responses into JavaScript objects.
  • Interceptors: Global hooks that let you intercept, alter, or log requests and responses before they hit .then() or .catch() blocks.
  • Isomorphic Nature: Runs seamlessly across both frontend browsers (via XMLHttpRequests) and backend environments (via Node.js network modules).
  • Request Management: Features built-in configurations for setting client-side timeouts, canceling active requests, and protecting against Cross-Site Request Forgery (XSRF).

Basic Code Examples

official Axios API requires very minimal configuration:

Making a GET Request:


const axios = require('axios');

async function getUser() {
  try {
    // Automatically parses response into a usable JSON object
    const response = await axios.get('https://example.com');
    console.log(response.data);
  } catch (error) {
    console.error('Request failed:', error.message);
  }
}

Making a POST Request:


async function createUser() {
    try {
        const response = await axios.post('https://example.com', {
        firstName: 'Jane',
        lastName: 'Doe'
        });
        console.log('User created:', response.status); // e.g., 201 Created
    } catch (error) {
        console.error(error);
    }
}

If you are integrating Axios into a production app, verify your dependencies immediately.
