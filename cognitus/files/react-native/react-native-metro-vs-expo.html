React Native Metro vs Expo

React Native Metro vs Expo, they are related but serve very different purposes.

Metro

Metro is the JavaScript bundler used by React Native.

Its main job is to take your JavaScript/TypeScript source code and dependencies and turn them into a bundle that your React Native app can execute.


Your JS/TS code
      ↓
    Metro
      ↓
JavaScript bundle
      ↓
React Native runtime
      ↓
iOS / Android

Metro handles things such as:

  • Bundling JavaScript/TypeScript
  • Resolving imports
  • Fast Refresh
  • Development server
  • Watching files
  • Source maps
  • React Native module resolution

For example, in a typical React Native project:


npx react-native start

starts Metro.

You can then build the native application separately:


npx react-native run-ios

or


npx react-native run-android

Expo

Expo is a development platform/toolchain built around React Native.

Expo provides much more than a bundler. It gives you libraries, development tools, configuration, build services, and APIs that make React Native development easier.

For example:


                Expo
                │
   ┌────────────┼─────────────┐
   ↓            ↓             ↓
Expo SDK      Expo CLI      EAS Build
   │                          │
   ↓                          ↓
Camera, GPS,              iOS / Android
Notifications, etc.          builds
   │
   ↓
React Native
   │
   ↓
 Metro

Expo projects still use Metro for JavaScript bundling.

So an important point is:

Expo does not replace Metro. Expo normally uses Metro underneath.

Simple comparison

Metro Expo
What is it? JavaScript bundler React Native development platform
Bundles JS ✅ Uses Metro
Fast Refresh ✅ ✅
iOS/Android development Supports it Supports it
Native APIs No Many Expo APIs
Build service ❌ EAS Build
App configuration Limited Expo config
OTA updates ❌ by itself Expo Updates
Camera/location/etc. Not provided Expo SDK
Native customization N/A Can use native projects/modules
Can use bare React Native? ✅ Expo can be added to existing RN projects

You are using React Native CLI + Metro, not an Expo-managed project.

If you migrated toward Expo, it could look more like:


    Castanet Mobile

The easiest way to remember it

Metro = the engine that bundles your React Native JavaScript.

Expo = a larger development platform that makes building React Native applications easier, and it uses Metro underneath.

For your RN 0.68 Castanet app, Metro is not something you would normally replace with Expo just to solve your current iOS 27/UIScene issue. The UIScene/AppDelegate problem is on the native iOS/Xcode side, not a Metro problem.

The key distinction is:

React Native is the core framework for building cross-platform mobile apps. Expo is a platform/toolchain built on top of React Native that provides additional APIs, tooling, configuration, and build services.

Think of it like this:


                EXPO
                ┌─────────────────────────┐
                │ Expo SDK                │
                │ Expo Router             │
                │ Expo Modules            │
                │ Expo CLI                │
                │ EAS Build / Submit      │
                │ Expo Updates            │

                             │
                        ┌────▼────┐
                        │  Metro  │
                        └────┬────┘
                             │
                 ┌───────────┴───────────┐
                 ▼                       ▼
               iOS                    Android

1. React Native

React Native is the actual application framework.

You write:


<View>
    <Text>Hello World</Text>
    <Button title="Login" />
</View>

React Native connects those JavaScript/TypeScript components to native iOS and Android functionality.

Technically, you have:


TypeScript / JavaScript
          ↓
      React Native
          ↓
   Native platform APIs
     ↙          ↘
   iOS        Android

For iOS:


React Native
     ↓
Objective-C / Swift
     ↓
UIKit / Foundation / native APIs

For Android:


React Native
     ↓
Java / Kotlin
     ↓
Android SDK

React Native itself gives you the fundamental pieces:

  • React components
  • Native components
  • JavaScript/TypeScript runtime integration
  • Native modules
  • Native UI
  • iOS/Android projects
  • Metro bundling
  • Fast Refresh
  • React Native CLI tooling

2. Expo

Expo is an ecosystem built around React Native.

Instead of having to configure many things yourself, Expo provides ready-made solutions.

For example:


React Native
     +
Expo Camera
Expo Location
Expo Notifications
Expo SecureStore
Expo ImagePicker
Expo FileSystem
Expo Router
Expo Updates
EAS Build
EAS Submit
     ↓
  Expo ecosystem

So if you need the camera, instead of implementing a native module yourself, you can use something like:


import { CameraView } from 'expo-camera';

Expo provides the native implementation behind that API.

3. The biggest difference

Here's the easiest comparison:

React Native Expo
Type Framework Platform/toolchain/ecosystem
Built on React ✅ ✅
Cross-platform ✅ ✅
Uses Metro ✅ ✅
Native iOS project ✅ ✅
Native Android project ✅ ✅
Camera API Can use native libraries Expo provides one
Notifications Can use native libraries Expo provides one
Location Can use native libraries Expo provides one
File system Can use native libraries Expo provides one
Build service ❌ EAS
App distribution tools Limited EAS Submit
OTA updates Not built into core Expo Updates
Routing You choose library Expo Router available
Configuration More manual More automated
Native customization Very flexible Also possible, but Expo adds its own layer

4. React Native does NOT mean "no Expo"

This is an important misconception.

You can have:

Pure React Native


React Native
├── Metro
├── iOS
└── Android

or:

React Native + Expo


Expo
├── Expo SDK
├── Expo tooling
├── React Native
│   └── Metro
├── iOS
└── Android

Expo is therefore not an alternative programming language or a replacement for React Native.

Expo uses React Native.

5. Example: Camera

Suppose you need barcode scanning.

React Native approach

You might install a third-party native library:


npm install react-native-vision-camera

Then you may need to configure:


iOS
├── Podfile
├── Info.plist
├── permissions
└── native dependencies

Android
├── Gradle
├── AndroidManifest.xml
└── permissions

Then your JavaScript talks to the native implementation.

Expo approach

You could use an Expo-supported camera module:


npx expo install expo-camera

Then:


import { CameraView } from 'expo-camera';

Expo handles much of the integration for you.

6. Build system is a major difference

This is one of the biggest practical differences.

With traditional React Native:


Developer
   │
   ├── Xcode
   ├── CocoaPods
   ├── Gradle
   ├── Android SDK
   └── React Native CLI

You are responsible for much of the native build environment.

With Expo, you can use:


Developer
   │
   └── EAS
        ├── Build iOS
        ├── Build Android
        ├── Submit to App Store
        └── Submit to Google Play

For example:


eas build --platform ios

can build the iOS application using Expo's build infrastructure.

7. Native code is where things get interesting

People sometimes say:

"Expo doesn't let you write native code."

That's no longer an accurate description.

Modern Expo can work with native projects.

You can have:


Expo
  ↓
React Native
  ↓
Native iOS / Android
  ↓
Your custom native code

You can also generate native projects:


npx expo prebuild

which creates:


ios/
android/

You can then customize native code when necessary.

So the distinction is increasingly:

Expo gives you more abstraction and tooling; React Native gives you the underlying application framework.

9. A useful analogy

Think of React Native as the engine:


            React Native
                ↓
     ┌──────────┴──────────┐
     ↓                     ↓
    iOS                 Android

Expo is more like a complete development platform around that engine:


                            Expo
                ┌────────────┼─────────────┐
                ↓            ↓             ↓
              SDK          Tools          EAS
                │            │             │
                └────────────┼─────────────┘
                             ↓
                        React Native
                             ↓
                        iOS / Android

In one sentence

React Native gives you the framework for building the mobile application; Expo gives you a higher-level ecosystem around React Native that simplifies native APIs, project configuration, development, updates, and app builds.

For someone working on your Castanet RN 0.68 application, the most important practical distinction is that moving from React Native CLI to Expo is a project/tooling architecture change—not simply replacing Metro—and it would not by itself fix the iOS 27 UIScene issue you're currently working through.
