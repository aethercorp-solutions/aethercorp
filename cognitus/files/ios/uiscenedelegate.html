UIApplicationDelegate vs UISceneDelegate

The simplest way to think about it is:

UIApplicationDelegate = manages the whole application

UISceneDelegate = manages an individual window/scene of the application

This distinction is especially important for your React Native Castanet project, because newer iOS SDKs require scene-based lifecycle support.

1. UIApplicationDelegate

Your AppDelegate.m traditionally handled almost everything:


@implementation AppDelegate

- (BOOL)application:(UIApplication *)application
    didFinishLaunchingWithOptions:(NSDictionary *)launchOptions
{
    // App initialization
    return YES;
}

- (UIWindow *)window
{
    // Main application window
}

@end

It is responsible for application-level events, such as:

  • App finished launching
  • Push notification registration
  • Background/foreground transitions
  • Opening URLs
  • Universal links
  • Firebase initialization
  • Global application configuration
  • React Native bridge setup

Think:


        UIApplication
                │
          AppDelegate
                │
   ┌────────────┴────────────┐
   │                         │
Scene A                   Scene B

The AppDelegate represents the application itself.

2. UISceneDelegate

UISceneDelegate was introduced with iOS 13 to separate UI/window lifecycle from the application lifecycle.

For example:


@implementation SceneDelegate

- (void)scene:(UIScene *)scene
    willConnectToSession:(UISceneSession *)session
    options:(UISceneConnectionOptions *)connectionOptions
{
    // Configure the UIWindow / root view controller
}

- (void)sceneDidBecomeActive:(UIScene *)scene
{
}

- (void)sceneWillResignActive:(UIScene *)scene
{
}

- (void)sceneDidEnterBackground:(UIScene *)scene
{
}

@end

The scene delegate handles things such as:

  • Creating/configuring the UIWindow
  • Connecting the root view controller
  • Scene becoming active
  • Scene entering background
  • Scene becoming inactive
  • Scene disconnection
  • Multiple windows/scenes

Think:


UIApplication
     │
     └── AppDelegate
             │
             ├── SceneDelegate #1
             │       └── UIWindow
             │
             └── SceneDelegate #2
                     └── UIWindow

This allows an iPad app, for example, to have multiple windows of the same application.

3. The important difference

UIApplicationDelegate UISceneDelegate
Represents Entire application One UI scene/window
Introduced Original iOS lifecycle iOS 13
App initialization ✅ ❌
Firebase setup Usually ✅ Usually ❌
Push notification setup ✅ ❌
React Native bridge Usually AppDelegate Usually coordinated with Scene
UIWindow Legacy responsibility ✅
Root UIViewController Legacy responsibility ✅
Scene foreground/background Application-level events ✅
Multiple windows Not designed for it ✅
Required by newer SDK/runtime App delegate still exists Yes for scene-based apps

4. Old Objective-C application

Your old project probably looks roughly like this:


// AppDelegate.m

- (BOOL)application:(UIApplication *)application
    didFinishLaunchingWithOptions:(NSDictionary *)launchOptions
{
    self.window = [[UIWindow alloc] initWithFrame:
                   [UIScreen mainScreen].bounds];

    self.window.rootViewController = ...;

    [self.window makeKeyAndVisible];

    return YES;
}

The flow was:


UIApplication
      ↓
AppDelegate
      ↓
Create UIWindow
      ↓
Create RootViewController
      ↓
makeKeyAndVisible
      ↓
Application UI

That was the traditional iOS architecture.

5. Modern scene-based application

Now the flow is more like:


UIApplication
      │
      ↓
AppDelegate
      │
      │ application-level setup
      │
      ↓
UIScene
      │
      ↓
SceneDelegate
      │
      ↓
UIWindow
      │
      ↓
RootViewController

So the window creation moves from:


AppDelegate

to:


SceneDelegate

For example:


// SceneDelegate.m

- (void)scene:(UIScene *)scene
    willConnectToSession:(UISceneSession *)session
    options:(UISceneConnectionOptions *)connectionOptions
{
    if (![scene isKindOfClass:[UIWindowScene class]]) {
        return;
    }

    UIWindowScene *windowScene = (UIWindowScene *)scene;

    self.window = [[UIWindow alloc] initWithWindowScene:windowScene];

    self.window.rootViewController = ...;

    [self.window makeKeyAndVisible];
}

6. What happens to AppDelegate?

This is where many legacy projects get confused.

You don't delete AppDelegate.

Instead, you divide its responsibilities.

AppDelegate


@implementation AppDelegate

- (BOOL)application:(UIApplication *)application
    didFinishLaunchingWithOptions:(NSDictionary *)launchOptions
{
    // Firebase
    // React Native initialization
    // Push notifications
    // Global application configuration

    return YES;
}

@end

SceneDelegate


@implementation SceneDelegate

- (void)scene:(UIScene *)scene
    willConnectToSession:(UISceneSession *)session
    options:(UISceneConnectionOptions *)connectionOptions
{
    // UIWindow
    // Root View Controller
    // React Native root view
}

7. For your React Native Castanet project

This is particularly relevant to the error you've been seeing:


Application failed to launch:
UIScene life cycle is required for apps built with this SDK.

Your project is essentially being told:


"Your application is built against a modern iOS SDK,
but you're still using the old application-only lifecycle."

So you need this architecture:


            Castanet
                │
         ┌──────┴──────┐
         │             │
   AppDelegate     SceneDelegate
         │             │
 Application setup    UI setup
         │             │
 Firebase            UIWindow
 React Native        Root View
 Notifications       RCTRootView
 URL handling        React Native UI

The key point is:

Don't move everything from AppDelegate into SceneDelegate.

Instead:

Keep in AppDelegate


didFinishLaunchingWithOptions

for things like:


Firebase
React Native initialization
push notification registration
application-wide services

Put in SceneDelegate


scene:willConnectToSession:options:

for:


UIWindow
RCTRootView
rootViewController
makeKeyAndVisible

One important React Native detail

For your project, SceneDelegate does not mean you need to create a completely separate React Native application.

You still have:


React Native
     ↓
RCTBridge
     ↓
RCTRootView
     ↓
UIViewController
     ↓
UIWindow
     ↓
SceneDelegate

So the scene lifecycle is basically the UIKit container around your existing React Native application.

Your current error is therefore not saying:

"React Native is broken."

It's saying:

"UIKit needs your application to participate in the scene lifecycle."

And that is why your recent SceneDelegate.m work is the correct direction.
