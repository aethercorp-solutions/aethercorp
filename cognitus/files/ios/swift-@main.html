@main

In Swift, @main is an attribute that tells the compiler:

“This is the starting point of the app.”

It defines where the application begins execution.

In modern iOS development — especially with SwiftUI — @main replaces the older AppDelegate entry setup that used UIApplicationMain.

Basic Example


import SwiftUI

@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

This is the entry point of the app.

When the app launches:

  1. iOS starts the process
  2. Swift runtime looks for @main
  3. Creates the MyApp object
  4. Executes the app lifecycle
  5. Displays ContentView

What @main Actually Does

Before Swift had @main, apps needed a main() function like in C/C++.

Example:


int main() {
    return UIApplicationMain(...);
}

Swift hides this complexity.

When you write:


@main
struct MyApp: App

Swift automatically generates the equivalent startup code behind the scenes.

Think of It Like This

@main = “Start execution here.”

Similar concepts in other languages:

Language Entry Point
C main()
Java public static void main()
Kotlin fun main()
Swift @main

In SwiftUI Apps

Most modern iOS apps use:


@main
struct MyApp: App

The struct conforms to the App protocol.

Understanding the App Protocol

Example:


@main
struct DemoApp: App {
    var body: some Scene {
        WindowGroup {
            HomeView()
        }
    }
}

Components

struct DemoApp

This protocol manages:

  • App lifecycle
  • Scene management
  • Window creation
  • Environment setup

What Happens During Launch

Step-by-step


@main
struct MyApp: App

Step 1 — App Starts

iOS launches the executable.

Step 2 — Swift Finds @main

Compiler identifies the app entry type.

Step 3 — Creates App Instance


let app = MyApp()

Step 4 — Loads Scene


body

is evaluated.

Step 5 — Creates WindowGroup

Window system initializes.

Step 6 — Displays Root View


ContentView()

appears onscreen.

How It Replaced Old UIKit Setup

Before SwiftUI, apps commonly used:


@UIApplicationMain
class AppDelegate: UIResponder, UIApplicationDelegate

or manually:


UIApplicationMain(
    CommandLine.argc,
    CommandLine.unsafeArgv,
    nil,
    NSStringFromClass(AppDelegate.self)
)

Modern SwiftUI simplifies this into:


@main
struct MyApp: App

Difference Between @main and @UIApplicationMain

@main @UIApplicationMain
Modern Swift Older UIKit approach
Works with SwiftUI UIKit lifecycle
More flexible Specific to UIApplication
Recommended now Legacy style

Can @main Be Used Outside iOS?

Yes.

Swift supports @main for:

  • Console apps
  • macOS apps
  • Server-side Swift
  • Command-line tools

Example:


@main
struct Program {
    static func main() {
        print("Hello")
    }
}

Equivalent to:


func main() {
    print("Hello")
}

Rules of @main

Only One Allowed

You can only have ONE entry point.

Invalid:


@main
struct App1 {}

@main
struct App2 {}

Compiler error occurs.

@main Can Be Applied To

Usually:

  • Struct
  • Class
  • Enum

But it must provide a valid entry mechanism.

SwiftUI Lifecycle vs UIKit Lifecycle

SwiftUI (@main)


@main
struct MyApp: App

Lifecycle handled declaratively.

UIKit


class AppDelegate: UIResponder

Lifecycle handled manually.

Combining @main with AppDelegate

Sometimes you still need UIKit delegates.

Example:


import SwiftUI

@main
struct DemoApp: App {

    @UIApplicationDelegateAdaptor(AppDelegate.self)
    var appDelegate

    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

Useful for:

  • Push notifications
  • Firebase setup
  • Deep links
  • Legacy SDKs

Internal Compiler Behavior

The compiler synthesizes startup code similar to:


static func main() {
    UIApplicationMain(...)
}

You don’t see it, but it is generated automatically.

Why Apple Introduced @main

Goals:

  • Simplify app startup
  • Reduce boilerplate
  • Support declarative UI
  • Modernize lifecycle management
  • Improve readability

Real-World SwiftUI App Structure


@main
struct BankingApp: App {

    @StateObject var authManager = AuthManager()

    var body: some Scene {
        WindowGroup {
            LoginView()
                .environmentObject(authManager)
        }
    }
}

This becomes the root container for:

  • Global state
  • Dependency injection
  • App configuration
  • Scene setup

Important Concepts Related to @main

App Lifecycle

Events like:

  • App launch
  • Background
  • Foreground
  • Termination

Handled within SwiftUI scene phases.

Example:


@Environment(\.scenePhase) var scenePhase

Multiple Windows Support

WindowGroup supports multiwindow apps on:

  • iPadOS
  • macOS

Common Beginner Confusion

“Why no main() function?”

Swift generates it automatically.

@main replaces it.

“Why does SwiftUI app start without AppDelegate?”

Because the App protocol now manages lifecycle behavior.

Summary

@main in Swift:

  • Marks the application entry point
  • Replaces manual main() setup
  • Commonly used with SwiftUI
  • Works with the App protocol
  • Simplifies app lifecycle management
  • Modern replacement for @UIApplicationMain

Core example:


@main
struct MyApp: App {
    var body: some Scene {
        WindowGroup {
            ContentView()
        }
    }
}

This tells iOS:

“Launch the app starting from this SwiftUI application structure.”
