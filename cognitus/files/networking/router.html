Router

A router is a network device whose main job is to move IP packets between different networks. Your home router is actually several networking devices combined into one: a router, Ethernet switch, Wi-Fi access point, DHCP server, NAT gateway, firewall, and often DNS forwarder.

Here is the complete flow from your Mac/iPhone to a website.

1. The basic idea

Suppose your Mac has:


    Mac
192.168.1.10
     |
     | Ethernet / Wi-Fi
     |
192.168.1.1
Home Router
     |
     | WAN
     |
ISP
     |
Internet
     |
Web Server
142.250.x.x

Your Mac and router are on your local network:


192.168.1.0/24

The Internet is a collection of many other networks.

The router's fundamental job is:

Look at the destination IP address of a packet and decide which network/interface should receive it next.

2. What happens when your computer connects to Wi-Fi?

When your Mac connects to your router's Wi-Fi, several things happen.

Your router normally provides:


IP address
Subnet mask
Default gateway
DNS server

For example:


Mac
IP:       192.168.1.10
Mask:     255.255.255.0
Gateway:  192.168.1.1
DNS:      192.168.1.1

The subnet mask tells the computer which addresses are local.

For:


192.168.1.10/24

the local network is:


192.168.1.0 - 192.168.1.255

So:


192.168.1.20

is local.

But:


142.250.72.14

is not local.

Therefore the Mac sends traffic for 142.250.72.14 to its default gateway:


192.168.1.1

3. DHCP gives your computer its configuration

Usually your computer doesn't manually configure all of this.

It uses DHCP.

The basic DHCP process is commonly described as:


Mac                  Router
 |                      |
 | DHCP Discover        |
 |--------------------->|
 |                      |
 | DHCP Offer           |
 |<---------------------|
 |                      |
 | DHCP Request         |
 |--------------------->|
 |                      |
 | DHCP ACK             |
 |<---------------------|

The router might assign:


IP address:     192.168.1.10
Subnet mask:    255.255.255.0
Gateway:        192.168.1.1
DNS:            192.168.1.1
Lease:          24 hours

Now your Mac knows how to communicate.

4. Router vs switch

This is an important distinction.

A switch primarily operates at Layer 2.

A router operates primarily at Layer 3.

For example:


Mac A
192.168.1.10
   |
   |
Switch
   |
   +---- Mac B
   |     192.168.1.20
   |
   +---- Router
         192.168.1.1

The switch looks primarily at MAC addresses.

The router looks primarily at IP addresses.

MAC address

Example:


A4:83:E7:12:34:56

IP address

Example:


192.168.1.10

MAC addresses are used for delivery on the local Layer-2 network.

IP addresses are used for communication between networks.

5. Let's access Google

Suppose you type:


https://www.google.com

There are actually many networking steps involved.

First:


www.google.com

is a domain name.

Your computer needs an IP address.

So it performs a DNS lookup.

For example:


www.google.com
        |
        v
DNS
        |
        v
142.250.x.x

The actual returned addresses can vary.

Now your computer knows the destination IP.

6. Your computer determines whether the destination is local

Suppose:


Mac:
192.168.1.10/24

Destination:
142.250.72.14

The Mac calculates whether:


142.250.72.14

belongs to:


192.168.1.0/24

It doesn't.

Therefore:


Destination is remote
        |
        v
Send packet to default gateway
        |
        v
192.168.1.1

7. But there is a problem: Ethernet needs a MAC address

The Mac knows:


Gateway IP = 192.168.1.1

But Ethernet/Wi-Fi needs a destination MAC address.

So the computer uses ARP for IPv4.

It asks:


Who has 192.168.1.1?

The router responds:


192.168.1.1 is at
AA:BB:CC:DD:EE:FF

The Mac can now construct a Layer-2 frame.

Conceptually:


Ethernet/Wi-Fi Frame
+--------------------------------+
| Destination MAC                |
| AA:BB:CC:DD:EE:FF              |
+--------------------------------+
| Source MAC                     |
| Mac's MAC                      |
+--------------------------------+
| Payload                        |
| IP Packet                      |
+--------------------------------+

Inside that frame is the IP packet.

8. The IP packet

The IP packet contains something like:


Source IP:
192.168.1.10

Destination IP:
142.250.72.14

The important thing is:

The destination IP remains the ultimate destination while the packet travels through routers.

The Layer-2 frame, however, changes at every network hop.

9. The packet reaches your router

Your router receives the frame.

It examines:


Destination MAC

and recognizes:

This frame is for me.

It removes the Layer-2 encapsulation and examines the IP packet.

It sees:


Source:
192.168.1.10

Destination:
142.250.72.14

Now the router performs a routing lookup.

10. The routing table

Routers have a routing table.

A simplified example:


Destination       Gateway          Interface

192.168.1.0/24    directly connected LAN
10.0.0.0/8        10.0.0.1         WAN
0.0.0.0/0         ISP gateway      WAN

The most important entry is:


0.0.0.0/0

This is the default route.

It basically means:

If I don't have a more specific route, send it here.

So:


142.250.72.14

doesn't match:


192.168.1.0/24

Therefore the router uses:


0.0.0.0/0

and sends the packet toward the ISP.

11. Longest-prefix matching

This is one of the most important concepts in routing.

Suppose the router has:


10.0.0.0/8
10.10.0.0/16
10.10.20.0/24
0.0.0.0/0

Destination:


10.10.20.50

It matches all of these:


10.0.0.0/8
10.10.0.0/16
10.10.20.0/24
0.0.0.0/0

The router chooses:


10.10.20.0/24

because /24 is the most specific match.

This is called:

Longest Prefix Match.
