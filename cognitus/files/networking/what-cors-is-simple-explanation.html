What CORS is (simple explanation)

CORS (Cross-Origin Resource Sharing) is a browser security rule.

It controls whether a web page running on one origin (domain) is allowed to request data from another origin.

An origin = protocol + domain + port

Example:

  • http://localhost:3000 (Next.js frontend)
  • http://localhost:5000 (Node/Express API)

These are different origins, so the browser blocks requests by default unless the API explicitly allows them.

Why CORS exists

Without CORS:

  • Any website could call your API in the background
  • Steal data from logged-in users (cookies/tokens)
  • Perform unauthorized actions

So the browser says:

“I will only allow this request if the server says it’s safe.”

How CORS works (behind the scenes)

  1. Your frontend sends a request: 
    
GET /api/data
Origin: http://localhost:3000
  2. If it’s a “non-simple request” (like POST with JSON or Authorization header), the browser first sends a preflight request: 
    
OPTIONS /api/data
Origin: http://localhost:3000
  3. Server responds with allowed rules: 
    
Access-Control-Allow-Origin: http://localhost:3000
Access-Control-Allow-Methods: GET, POST
Access-Control-Allow-Headers: Content-Type, Authorization
  4. If allowed → browser sends real request.

✅ Setup CORS in Node.js + Express

  1. Install middleware 
    
npm install cors
  2. Basic setup (allow all origins — dev only) 
    
import express from "express";
import cors from "cors";

const app = express();

app.use(cors());

app.get("/api/data", (req, res) => {
  res.json({ message: "Hello world" });
});

app.listen(5000);
  3. Secure setup (recommended) 
    
app.use(
  cors({
    origin: "http://localhost:3000",
    methods: ["GET", "POST", "PUT", "DELETE"],
    credentials: true, // if using cookies/auth
  })
);
  4. If using multiple environments 
    
const allowedOrigins = [
  "http://localhost:3000",
  "https://your-production-site.com",
];

app.use(
  cors({
    origin: function (origin, callback) {
      if (!origin || allowedOrigins.includes(origin)) {
        callback(null, true);
      } else {
        callback(new Error("Not allowed by CORS"));
      }
    },
    credentials: true,
  })
);

✅ Setup CORS in Next.js

Option 1: If calling external API (Express backend)

You don’t “enable CORS” in Next.js — you just call the API:


const res = await fetch("http://localhost:5000/api/data");
const data = await res.json();

But your Express server must allow Next.js origin.

Option 2: Proxy via Next.js API routes (best practice)

This avoids CORS completely.


/pages/api/data.js
            

export default async function handler(req, res) {
    const response = await fetch("http://localhost:5000/api/data");
    const data = await response.json();
    
    res.status(200).json(data);
}

Now frontend calls:


fetch("/api/data");

👉 No CORS needed because it’s same-origin.

Option 3: Next.js rewrite proxy (cleanest)

next.config.js


module.exports = {
    async rewrites() {
        return [
        {
            source: "/api/:path*",
            destination: "http://localhost:5000/api/:path*",
        },
        ];
    },
};

Now:


fetch("/api/data");

🔥 Best practices

  1. Never use * in production with auth

    Bad:

    
origin: "*"
  2. Use credentials: true only if needed

    If you're using cookies or sessions.

  3. Prefer Next.js proxy (rewrite or API route)

    It avoids:

    • CORS issues
    • exposed backend URLs
    • authentication headaches

🚀 Summary

  • CORS = browser security rule, not backend limitation
  • Express must explicitly allow frontend origin
  • Next.js doesn’t “fix CORS” — it avoids it via proxying
  • Best solution: Next.js rewrite or API routes
