Refactoring React Components

When a React component becomes large (300–1000+ lines), the goal of refactoring is separation of concerns. A component should mainly describe the UI, while business logic, API calls, and utilities live elsewhere. React itself encourages extracting reusable logic into custom hooks rather than keeping everything in one component.

Before Refactoring

Everything is inside one component.

function Dashboard() {
    const [users, setUsers] = useState([]);
    const [loading, setLoading] = useState(false);
    const [search, setSearch] = useState("");

    useEffect(() => {
        async function loadUsers() {
            setLoading(true);

            const response = await fetch("/api/users");
            const data = await response.json();

            setUsers(data);
            setLoading(false);
        }

        loadUsers();
    }, []);

    function removeUser(id) {
        setUsers(users.filter(user => user.id !== id));
    }

    function filteredUsers() {
        return users.filter(user =>
            user.name.toLowerCase().includes(search.toLowerCase())
        );
    }

    return (
        <>
            <input
                value={search}
                onChange={(e) => setSearch(e.target.value)}
            />

            {loading && <p>Loading...</p>}

            {filteredUsers().map(user => (
                <div key={user.id}>
                    {user.name}

                    <button
                        onClick={() => removeUser(user.id)}
                    >
                        Delete
                    </button>
                </div>
            ))}
        </>
    );
}

The component is responsible for:

  • fetching data
  • searching
  • deleting
  • rendering UI

Too many responsibilities.

After Refactoring

1. API Service


// services/userService.ts

export async function getUsers() {
    const response = await fetch("/api/users");
    return response.json();
}

2. Custom Hook


// hooks/useUsers.ts

import { useState, useEffect } from "react";
import { getUsers } from "../services/userService";

export function useUsers() {
    const [users, setUsers] = useState([]);
    const [loading, setLoading] = useState(false);

    useEffect(() => {
        async function load() {
            setLoading(true);
            const data = await getUsers();
            setUsers(data);
            setLoading(false);
        }

        load();
    }, []);

    function removeUser(id) {
        setUsers(prev =>
            prev.filter(user => user.id !== id)
        );
    }

    return {
        users,
        loading,
        removeUser
    };
}

3. Search Hook


// hooks/useSearch.ts

import { useState } from "react";

export function useSearch(items) {
    const [search, setSearch] = useState("");

    const filtered = items.filter(item =>
        item.name
            .toLowerCase()
            .includes(search.toLowerCase())
    );

    return {
        search,
        setSearch,
        filtered
    };
}

4. UI Component

function Dashboard() {

    const {
        users,
        loading,
        removeUser
    } = useUsers();

    const {
        search,
        setSearch,
        filtered
    } = useSearch(users);

    return (
        <>
            <SearchBar
                value={search}
                onChange={setSearch}
            />

            {loading && <p>Loading...</p>}

            <UserList
                users={filtered}
                onDelete={removeUser}
            />
        </>
    );
}

Now the component is only about displaying UI.

Another Example (Upload Hook)


// hooks/useUpload.ts

export function useUpload() {

    const [files, setFiles] = useState([]);
    const [loading, setLoading] = useState(false);

    function addFiles(newFiles) {
        setFiles(prev => [...prev, ...newFiles]);
    }

    function removeFile(index) {
        setFiles(prev =>
            prev.filter((_, i) => i !== index)
        );
    }

    async function upload() {
        setLoading(true);

        // upload logic

        setLoading(false);
    }

    return {
        files,
        loading,
        addFiles,
        removeFile,
        upload
    };
}

Component:


const {
    files,
    loading,
    addFiles,
    removeFile,
    upload
} = useUpload();

Much cleaner.

Good Refactoring Rules

Move to... What belongs there
hooks/ useState, useEffect, business logic
services/ API calls, Axios, Fetch
components/ Reusable UI
utils/ Pure helper functions
constants/ URLs, enums, configuration
types/ TypeScript interfaces

The result is a Dashboard.tsx that is often under 100 lines and mostly reads like:

function Dashboard() {

    const dashboard = useDashboard();
    const upload = useUpload();

    return (
        <>
            <Header />

            <UploadCard {...upload} />

            <UserTable
                users={dashboard.users}
            />

            <Pagination />
        </>
    );
}

This style is common in large React applications because it improves readability, makes logic reusable, and simplifies testing. A useful guideline is to extract reusable stateful logic into custom hooks, API communication into service modules, and presentation into smaller components, while keeping hooks pure and following the Rules of Hooks.
