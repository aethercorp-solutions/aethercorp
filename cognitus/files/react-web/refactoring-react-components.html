Refactoring React components

Refactoring React components means breaking a large component into smaller, reusable pieces so the code is easier to read, maintain, and test.

Before Refactoring

Imagine everything is inside one file:


function Dashboard() {
    return (
        <div>
        <header>Header</header>

        <section>
            <h1>Welcome</h1>
            <button>Upload</button>
        </section>

        <div>
            <p>24 Publications</p>
            <p>128 Researchers</p>
        </div>

        <table>
            {/* publications */}
        </table>

        <footer>Footer</footer>
        </div>
    );
}

This component keeps getting longer as you add features.

After Refactoring

Split it into smaller components.


Dashboard/
│
├── Dashboard.tsx
├── Header.tsx
├── Hero.tsx
├── StatsGrid.tsx
├── PublicationsTable.tsx
└── Footer.tsx

Now Dashboard.tsx becomes:


export default function Dashboard() {
    return (
        <>
        <Header />
        <Hero />
        <StatsGrid />
        <PublicationsTable />
        <Footer />
        </>
    );
}

Each component is responsible for only one part of the UI.

Why refactor?

1. Easier to Read

Instead of 500 lines:


function Dashboard() {
    // 500 lines...
}

You have:


function Dashboard() {
    return (
    <>
        <Header />
        <Hero />
        <StatsGrid />
        <PublicationsTable />
    </>
    );
}

2. Reusable

Instead of writing this button everywhere:


<button className="bg-blue-600 text-white rounded">
    Upload
</button>

Create:


function Button({ children }) {
    return (
        <button className="bg-blue-600 text-white rounded">
        {children}
        </button>
    );
}

Now use it anywhere:


<Button>Upload</Button>
<Button>Save</Button>
<Button>Delete</Button>

3. Easier to Fix

If the upload card has a bug:


UploadCard.tsx ❌

You only edit:


UploadCard.tsx

Not a huge Dashboard.tsx.

4. Easier to Test

You can test one component:


<StatsGrid />

without loading the whole dashboard.

Passing Data with Props

Parent:


<Header username="Paul" />

Child:


function Header({ username }) {
    return <h1>Hello {username}</h1>
}

Output:


Hello Paul

Moving Logic into Hooks

If your component contains lots of state and functions:


const [selectedFiles, setSelectedFiles] = useState([]);
const [loading, setLoading] = useState(false);

function uploadFiles() {}
function removeFile() {}
function validatePdf() {}

Move them into a custom hook:


const {
    selectedFiles,
    loading,
    uploadFiles,
    removeFile,
} = useUpload();

Now the component focuses on rendering the UI.

Rule of Thumb

A component should have one main responsibility.

For example:

  • Header.tsx → navigation only
  • Hero.tsx → welcome section only
  • UploadCard.tsx → upload UI only
  • PublicationsTable.tsx → display publications only
  • AlertModal.tsx → show alerts only
  • useUpload.ts → upload logic only
  • ApiService.ts → API requests only

This separation makes your application cleaner and easier to extend.

Simple analogy

Think of building a car:

  • Before refactoring: One person builds the entire car from start to finish.
  • After refactoring: Different specialists build the engine, wheels, doors, and seats. Each part is independent, easier to improve, and can be replaced without affecting the whole car.

That's exactly what React component refactoring does: it breaks a large, hard-to-manage component into smaller, focused components that work together.
