AWS Serverless Framework

If you mean AWS Serverless Framework, it’s a way to build and deploy serverless applications on AWS using configuration/code rather than manually creating each AWS resource.

Typical stack:

  • AWS Lambda — runs your application code
  • Amazon API Gateway — exposes HTTP APIs
  • Amazon DynamoDB — serverless database
  • Amazon S3 — object storage
  • Amazon EventBridge / SQS / SNS — event-driven workflows
  • CloudFormation — provisions the infrastructure

A common Serverless Framework project might look like:


service: my-api

provider:
  name: aws
  runtime: nodejs22.x
  region: ap-southeast-1

functions:
  hello:
    handler: src/handler.hello
    events:
      - httpApi:
          path: /hello
          method: get

Then you can deploy with:


serverless deploy

The framework handles packaging your Lambda, creating/updating the AWS infrastructure, and wiring the resources together.

We can build it progressively:

  1. Prerequisites
    • Node.js
    • AWS account
    • AWS CLI
    • AWS IAM user/role
    • AWS credentials
  2. Create a Serverless project 
    
mkdir serverless-api
cd serverless-api
npm init -y
npm install -D serverless
  3. Create a Lambda function
    • Understand handler
    • Understand Lambda events
    • Test locally
  4. Add API Gateway 
    
functions:
  api:
    handler: src/handler.handler
    events:
      - httpApi:
          path: /{proxy+}
          method: ANY
  5. Deploy to AWS 
    
npx serverless deploy
  6. Add DynamoDB
    • Table definition
    • CRUD operations
    • Environment-specific tables
  7. Understand IAM
    • Lambda execution roles
    • Permissions such as:
      • dynamodb:GetItem
      • dynamodb:PutItem
      • dynamodb:UpdateItem
      • dynamodb:DeleteItem
  8. Create environments 
    
developer
uat
production

    For example:

    
npx serverless deploy --stage developer
npx serverless deploy --stage uat
npx serverless deploy --stage production
  9. Environment-specific configuration 
    
provider:
  environment:
    NODE_ENV: ${sls:stage}
  10. Then connect it to your Castanet architecture

    We can eventually reproduce your current setup:

       │

 MongoDB   AWS services

    And compare that with your current:

  name: aws

The learning path I'd recommend

Don't start with DynamoDB immediately. Start with the smallest possible Node.js → Lambda → API Gateway → AWS deployment, so you understand what Serverless Framework is actually generating.

Then we add IAM → environment variables → SSM Parameter Store → DynamoDB → multiple stages → CI/CD.

That will also make it much easier to understand exactly what your existing castanet-api serverless.yml is doing.
