What is @aws-sdk/client-ses

Let's start with the simplest explanation and gradually go deeper.

Level 1: What is @aws-sdk/client-ses?

Imagine you have a company and you want your app to send emails.

Instead of creating your own email server (which is difficult), you ask Amazon to send emails for you.

Amazon SES (Simple Email Service) is Amazon's email sending service.

@aws-sdk/client-ses is simply the JavaScript library that lets your Node.js application talk to Amazon SES.

Think of it like this:


Your App
    │
    │ "Please send this email."
    ▼
@aws-sdk/client-ses
    │
    ▼
Amazon SES
    │
    ▼
Recipient receives email

So:

  • Your app creates the email.
  • @aws-sdk/client-ses sends the request.
  • Amazon SES delivers the email.

Level 2: What does AWS SDK mean?

AWS has hundreds of services.

Examples:

  • S3 → store files
  • DynamoDB → database
  • Lambda → serverless functions
  • SES → email
  • SNS → notifications

Instead of writing HTTP requests yourself, AWS provides an SDK (Software Development Kit).

The SDK already knows:

  • API URLs
  • Authentication
  • Request formatting
  • Error handling
  • Response parsing

So instead of writing:


POST https://email.us-east-1.amazonaws.com
Authorization: ...
Content-Type: ...
...

You simply write:


const client = new SESClient(...);

The SDK handles the rest.

Level 3: Why is it called client?

Your Node.js application is the client.

Amazon SES is the server.


Node.js App (Client)
        │
        ▼
Amazon SES Server

The client sends requests.

The server performs the work.

That's why the package is named


@aws-sdk/client-ses

It is the SES client.

Level 4: Why @aws-sdk?

This is the package namespace.


@aws-sdk/
    client-s3
    client-ses
    client-lambda
    client-dynamodb

Each AWS service has its own package.

Example:


import { SESClient } from "@aws-sdk/client-ses";
import { S3Client } from "@aws-sdk/client-s3";
import { DynamoDBClient } from "@aws-sdk/client-dynamodb";

Instead of installing one huge SDK, you install only what you need.

Level 5: Installing


npm install @aws-sdk/client-ses

Now your project knows how to communicate with SES.

Level 6: Creating the client


import { SESClient } from "@aws-sdk/client-ses";

const client = new SESClient({
    region: "us-east-1"
});

What happens here?


Your Code
      │
      ▼
Create SES Client
      │
      ▼
Store configuration
    Region
    Credentials
    Retry settings

Notice:

This does not send anything yet.

It just prepares the connection.

Level 7: Authentication

Amazon must know who is making the request.

The client automatically signs every request using:


AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY

Example:


const client = new SESClient({
    region: "us-east-1",
    credentials: {
        accessKeyId: process.env.AWS_ACCESS_KEY_ID,
        secretAccessKey: process.env.AWS_SECRET_ACCESS_KEY
    }
});

Before every request:


Request
+
Access Key
+
Secret Key
=
Signed Request

Amazon verifies the signature.

Level 8: Sending an email

Example:


import {
    SESClient,
    SendEmailCommand
} from "@aws-sdk/client-ses";

const client = new SESClient({
    region: "us-east-1"
});

const command = new SendEmailCommand({
    Source: "me@example.com",
    Destination: {
        ToAddresses: ["john@example.com"]
    },
    Message: {
        Subject: {
            Data: "Hello"
        },
        Body: {
            Text: {
                Data: "Welcome!"
            }
        }
    }
});

await client.send(command);

Level 9: Why use a Command?

AWS SDK v3 uses the Command Pattern.

Instead of:


client.sendEmail(...)

you create a command.


Create Command
        │
        ▼
Client.send(command)

The command describes what you want to do.

Examples:


SendEmailCommand

DeleteIdentityCommand

VerifyEmailIdentityCommand

ListIdentitiesCommand

Each command represents one SES API operation.

Level 10: What happens internally?

When you call:


await client.send(command);

the SDK performs many steps for you.


Your Code
      │
      ▼
Create JSON request
      │
      ▼
Sign request
      │
      ▼
Convert to HTTP
      │
      ▼
HTTPS
      │
      ▼
Amazon SES
      │
      ▼
Validate
      │
      ▼
Queue email
      │
      ▼
Return response

All of this happens automatically.

Level 11: The HTTP request behind the scenes

Your code:


await client.send(command);

is roughly equivalent to manually making an HTTPS request like:


POST https://email.us-east-1.amazonaws.com

with a payload similar to:


{
    "Source": "me@example.com",
    "Destination": {
        "ToAddresses": [
            "john@example.com"
        ]
    },
    "Message": {
        "Subject": {
            "Data": "Hello"
        },
        "Body": {
            "Text": {
                "Data": "Welcome!"
            }
        }
    }
}

The SDK also:

  • Adds authentication headers
  • Signs the request
  • Handles retries
  • Parses the response
  • Throws meaningful errors

Level 12: Common commands

The SES client supports many operations, such as:

Command Purpose
SendEmailCommand Send a simple email
SendRawEmailCommand Send a fully customized MIME email (attachments, HTML, etc.)
VerifyEmailIdentityCommand Verify an email address with SES
VerifyDomainIdentityCommand Verify ownership of a domain
ListIdentitiesCommand List verified email identities
DeleteIdentityCommand Remove a verified identity

Key takeaway

@aws-sdk/client-ses is the official AWS JavaScript library for communicating with Amazon SES. It handles authentication, request formatting, retries, and response parsing, allowing your application to send emails with simple JavaScript code instead of manually constructing and signing HTTPS requests. In AWS SDK v3, each API operation is represented by a command (such as SendEmailCommand), and the SESClient executes those commands by communicating securely with the SES service.
