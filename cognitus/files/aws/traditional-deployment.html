Traditional Deployment

You can implement essentially the same architecture without AWS, Serverless Framework, Lambda, API Gateway, or SSM using a bare-metal server plus normal Linux software.

Your current AWS setup: 


service: castanet-api

provider:
  name: aws
  runtime: nodejs22.x
  region: us-east-2

  environment:
    NODE_ENV: ${sls:stage}
    MONGO_URI: ${ssm:/castanet/${sls:stage}/mongo-uri}

functions:
  api:
    handler: src/handler.handler

    events:
      - httpApi:
          path: /{proxy+}
          method: ANY

can become a Node.js + Express + Nginx + MongoDB + systemd architecture.

1. AWS architecture vs bare metal

AWS version Bare-metal equivalent
EC2/Lambda Linux server
Lambda Node.js process
API Gateway Nginx
Serverless Framework systemd + deployment scripts
AWS SSM Parameter Store .env / environment file / Vault
CloudWatch journald + Prometheus/Grafana
Lambda scaling Node.js cluster / multiple processes
AWS region Your physical server/datacenter
nodejs22.x Node.js 22
API Gateway HTTP API Nginx → Express
MongoDB Atlas MongoDB installed locally
IAM Linux users/firewall/application authentication

Ubuntu Server 24.04 LTS

3. Your Node.js application

Instead of Lambda:


export const handler = async (event) => {
    ...
};

you can have a normal HTTP server:


const express = require("express");

const app = express();

app.use(express.json());

app.get("/health", (req, res) => {
    res.json({
        status: "ok"
    });
});

app.get("/contacts", async (req, res) => {
    // MongoDB query
});

app.listen(3000, "127.0.0.1", () => {
    console.log("Castanet API listening on port 3000");
});

Then:


http://127.0.0.1:3000

is your API.

4. Replace Lambda handler

If your current project looks like:


castanet-api/
├── src/
│   ├── handler.js
│   ├── contacts.js
│   └── ...
├── serverless.yml
└── package.json

you could change it to:


castanet-api/
├── src/
│   ├── server.js
│   ├── routes/
│   │   ├── contacts.js
│   │   ├── auth.js
│   │   └── users.js
│   ├── controllers/
│   ├── services/
│   └── models/
├── .env
├── package.json
└── ...

server.js:


require("dotenv").config();

const express = require("express");

const app = express();

app.use(express.json());

app.get("/health", (req, res) => {
    res.json({
        status: "ok",
        environment: process.env.NODE_ENV
    });
});

app.use("/contacts", require("./routes/contacts"));

const PORT = process.env.PORT || 3000;

app.listen(PORT, "127.0.0.1", () => {
    console.log(`Castanet API running on port ${PORT}`);
});

5. Replace ${sls:stage}

Your AWS configuration:


NODE_ENV: ${sls:stage}

means Serverless gives you something like:


development
uat
production

On bare metal, you simply define it yourself.

For example:

Development


NODE_ENV=development

UAT


NODE_ENV=uat

Production


NODE_ENV=production

6. Replace AWS SSM Parameter Store

Currently:


MONGO_URI: ${ssm:/castanet/${sls:stage}/mongo-uri}

means:


/castanet/development/mongo-uri
/castanet/uat/mongo-uri
/castanet/production/mongo-uri

AWS SSM stores the actual MongoDB connection string.

On bare metal, the simplest replacement is an environment file.

For example:


/etc/castanet/production.env

containing:


NODE_ENV=production
PORT=3000

MONGO_URI=mongodb://127.0.0.1:27017/castanet

Then:


chmod 600 /etc/castanet/production.env

This is much better than putting the password directly into your source code.

7. Better alternative: HashiCorp Vault

If you want something closer to AWS SSM/Secrets Manager:


Node.js
   |
   v
HashiCorp Vault
   |
   +---- MongoDB credentials
   +---- JWT secret
   +---- Google OAuth credentials
   +---- Firebase credentials

You could use:


HashiCorp Vault

on your own infrastructure.

Then your bare-metal environment can be much closer to AWS:


AWS SSM
     ↓
/castanet/production/mongo-uri

becomes:


Vault
     ↓
secret/castanet/production

For a small Castanet deployment, however, an appropriately protected environment file is considerably simpler.
