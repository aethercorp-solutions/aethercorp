ESLint

ESLint is a static code analysis tool (a linter) for JavaScript and TypeScript. It analyzes your code without running it and reports problems such as errors, bad practices, and style issues.

What ESLint helps with

  • Finds bugs 
    
const name = "Alice";
console.log(nam); // ❌ ESLint: 'nam' is not defined
  • Enforces coding standards 
    
if (x == 5) {
    // ESLint can require === instead of ==
}
  • Keeps code consistent
    • Semicolons or no semicolons
    • Single quotes vs. double quotes
    • Indentation
    • Spacing

Example

Suppose you write:


function greet(name) {
    console.log("Hello " + user);
}

ESLint would report:


'user' is not defined. (no-undef)

because user doesn't exist—it should probably be name.

How it works

  1. You install ESLint in your project.
  2. You configure rules in an ESLint configuration file (such as eslint.config.js).
  3. ESLint scans your source files.
  4. It reports issues and can automatically fix many of them.

Installing ESLint

Using npm:


npm install --save-dev eslint

Initialize a configuration:


npx eslint --init

Run ESLint:


npx eslint .

Automatically fix issues when possible:

Common rules

  • no-unused-vars – Warn about variables you never use.
  • no-undef – Prevent using undefined variables.
  • eqeqeq – Require === instead of ==.
  • semi – Enforce or disallow semicolons.
  • quotes – Enforce single or double quotes.

Why developers use ESLint

  • Catches mistakes before running the code.
  • Makes code easier to read and maintain.
  • Ensures everyone on a team follows the same coding standards.
  • Integrates with editors like VS Code to show problems as you type.
  • Can run automatically in CI/CD pipelines to prevent problematic code from being merged.

In short, ESLint is like a spell checker for JavaScript and TypeScript code—it catches mistakes, enforces best practices, and helps keep your codebase clean and consistent.
