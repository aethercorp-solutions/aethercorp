Bitbucket Pipelines

Bitbucket Cloud has a built-in CI/CD service called Bitbucket Pipelines. You define your pipeline in a bitbucket-pipelines.yml file at the root of your repository, and Bitbucket automatically runs it when code is pushed, a pull request is created, or another configured trigger occurs.

Step 1. Enable Bitbucket Pipelines

  1. Open your Bitbucket repository.
  2. Go to Repository Settings → Pipelines.
  3. Click Enable Pipelines.
  4. Commit a bitbucket-pipelines.yml file to the root of your repository.

Step 2. Create bitbucket-pipelines.yml

Example: Node.js (React, Express, Next.js)


image: node:22

pipelines:
  default:
    - step:
        name: Install & Test
        caches:
          - node
        script:
          - npm ci
          - npm run lint
          - npm test
          - npm run build

Whenever you push code:


git push origin main

Bitbucket automatically:

  • Creates a temporary container
  • Installs dependencies
  • Runs tests
  • Builds the project
  • Reports success or failure

Step 3. Add Environment Variables

Never commit secrets.

Go to:


Repository Settings
    ↓
Repository Variables

Example:


AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
SUPABASE_URL
SUPABASE_KEY
FIREBASE_TOKEN
APPLE_API_KEY

Access them in the pipeline:


script:
  - echo $SUPABASE_URL

Step 4. Cache Dependencies

Caching makes builds much faster.


caches:
  - node

or


caches:
  - pip

or


caches:
  - gradle

Example: iOS (Using Self-hosted macOS Runner)

Because Bitbucket Cloud runners are Linux by default, iOS builds require a self-hosted macOS runner connected to a Mac with Xcode installed.


pipelines:
  default:
    - step:
        runs-on:
          - self.hosted
          - macos
        script:
          - xcodebuild \
            -workspace MyApp.xcworkspace \
            -scheme MyApp \
            -sdk iphoneos \
            archive

Example: Deploy to AWS


image: amazon/aws-cli

pipelines:
  branches:
    main:
      - step:
          name: Deploy
          script:
            - aws s3 sync build s3://mybucket

Example: Deploy via SSH


pipelines:
  branches:
    main:
      - step:
          script:
            - apt-get update
            - apt-get install -y openssh-client
            - scp -r build/* user@server:/var/www/html

Run Different Pipelines Per Branch


pipelines:
  branches:

    develop:
      - step:
          script:
            - npm test

    staging:
      - step:
          script:
            - npm run build

    main:
      - step:
          script:
            - npm run build
            - npm run deploy

This lets you:

  • develop → Run tests
  • staging → Build and deploy to staging
  • main → Deploy to production

Manual Deployments

You can define a pipeline that only runs when manually triggered:


pipelines:
  custom:
    deploy-production:
      - step:
          script:
            - ./deploy.sh

You can start it from the Bitbucket UI whenever you're ready.
