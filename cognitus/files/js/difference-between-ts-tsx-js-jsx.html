Difference between .ts, .tsx, .js, and .jsx

The difference is mainly what the file contains and whether it uses TypeScript or JavaScript.

Think of it like this

  • JavaScript (JS) = Plain English
  • TypeScript (TS) = English with grammar checking

And:

  • X = JSX (HTML inside JavaScript)

So:

  • JS = JavaScript
  • JSX = JavaScript + HTML
  • TS = TypeScript
  • TSX = TypeScript + HTML
File Language Can use HTML-like JSX? Best For
.js JavaScript ❌ Usually no Normal JavaScript files
.jsx JavaScript ✅ Yes React components
.ts TypeScript ❌ No TypeScript logic, utilities, APIs
.tsx TypeScript ✅ Yes React components with TypeScript

1. .js (JavaScript)

Use this for normal JavaScript code.


function add(a, b) {
    return a + b;
}
    
console.log(add(2, 3));

No HTML/React UI.

2. .jsx (JavaScript + JSX)

Use this when creating React components.


function App() {
    return (
        <h1>Hello World</h1>
    );
}
    
export default App;

Notice the HTML-like syntax:


<h1>Hello World</h1>

That is JSX.

3. .ts (TypeScript)

Same as JavaScript, but you can specify data types.


function add(a: number, b: number): number {
    return a + b;
}

If you accidentally do:


add("hello", 5);

TypeScript immediately reports an error before you run the program.

Great for:

  • APIs
  • Utility functions
  • Database code
  • Backend (Node.js)
  • Services

4. .tsx (TypeScript + JSX)

This is the most common file type in modern React projects.


type Props = {
    name: string;
};

function Greeting({ name }: Props) {
    return <h1>Hello {name}</h1>
}

export default Greeting;

You get:

  • React UI
  • Type safety
  • Better autocomplete
  • Fewer bugs

Why do we need JSX?

Without JSX:


React.createElement("h1", null, "Hello");

With JSX:


<h1>Hello</h1>

Much easier to read.

Why do we need TypeScript?

Imagine this function:


function multiply(a, b) {
    return a * b;
}

Someone calls:


multiply("hello", 5);

You may not notice the mistake until runtime.

With TypeScript:


function multiply(a: number, b: number) {
    return a * b;
}

Calling:


multiply("hello", 5);

shows an error immediately in your editor.

Which file should I use?

React component?

Use:


Button.tsx

Example:


export default function Button() {
    return <button>Click Me</button>
}

API or utility function?

Use:


api.ts

Example:


export async function login() {
    // API call
}

Simple JavaScript project?

Use:


JavaScript

React project without TypeScript?

Use:


JavaScript

Modern Next.js projects

Typical structure:


app/
    page.tsx
    layout.tsx
    loading.tsx

components/
    Navbar.tsx
    Footer.tsx

services/
    auth.ts
    api.ts

types/
    user.ts

utils/
    helpers.ts

Notice:

  • UI components → .tsx
  • Business logic, API calls, helpers, types → .ts

Simple rule to remember

  • .js → JavaScript only
  • .jsx → JavaScript + React UI (JSX)
  • .ts → TypeScript only
  • .tsx → TypeScript + React UI (JSX)

In modern React and Next.js development, you'll most commonly use:

  • .tsx for pages and components
  • .ts for everything else (services, utilities, types, API logic)

This combination provides better type checking, editor support, and maintainability than plain JavaScript.
