require() and module.exports

In Node.js, require() and module.exports are part of the CommonJS module system. They allow you to split code into reusable files (modules) and share functionality between them.

1. What is a Module?

A module is simply a file.

Example:


math.js
app.js

Each file has its own scope.

Variables inside one file are NOT automatically available in another file.

2. What is module.exports?

module.exports is used to expose data or functionality from a file so other files can use it.

Think of it like:

“What should this file make available to the outside world?”

Example

math.js


function add(a, b) {
    return a + b;
}

module.exports = add;

This exports the add function.

3. What is require()?

require() imports another module.

Think of it like:

“Load this file and give me whatever it exported.”

Example

app.js


const add = require('./math');

console.log(add(2, 3));

Output:


5

4. How It Works Internally

When Node.js sees:


require('./math')

It does roughly this internally:

  1. Finds math.js
  2. Executes the file
  3. Looks at module.exports
  4. Returns that exported value

So this:


module.exports = add;

becomes:


const add = require('./math');

5. Every File Has a Hidden Module Wrapper

Node.js secretly wraps every file like this:


(function(exports, require, module, __filename, __dirname) {

    // your code here

});

That is why these variables exist automatically:

  • require
  • module
  • exports
  • __filename
  • __dirname

6. exports vs module.exports

This confuses many developers.

They Initially Point to the Same Object

Internally:


exports = module.exports

Valid Usage

user.js


exports.name = 'Paul';
exports.age = 30;

Equivalent to:


module.exports.name = 'Paul';
module.exports.age = 30;

Import:


const user = require('./user');

console.log(user.name);

7. The Dangerous Part

This DOES NOT work correctly:


exports = function() {
    console.log('hello');
};

Why?

Because you replaced the reference.

You changed exports, but NOT module.exports.

Node only returns:


module.exports

8. Correct Way to Export a Function/Class

Use:


module.exports = function() {
    console.log('hello');
};

or:


module.exports = MyClass;

9. Exporting Multiple Functions

math.js


function add(a, b) {
    return a + b;
}

function subtract(a, b) {
    return a - b;
}

module.exports = {
    add,
    subtract
};

app.js


const math = require('./math');

console.log(math.add(5, 2));
console.log(math.subtract(5, 2));

10. Destructuring Imports

Instead of:


const math = require('./math');

You can do:


const { add, subtract } = require('./math');

This extracts properties from the exported object.

11. Real Express.js Example

In Express.js apps:

routes/userRoutes.js


const express = require('express');
const router = express.Router();

router.get('/', (req, res) => {
    res.send('Users');
});

module.exports = router;

app.js


const express = require('express');
const app = express();

const userRoutes = require('./routes/userRoutes');

app.use('/users', userRoutes);

12. Why This Pattern Exists

Benefits:

Separation of Concerns

Split code into files.

Reusability

Reuse logic anywhere.

Maintainability

Cleaner architecture.

Encapsulation

Private variables stay hidden unless exported.

Example:


const secret = 'hidden';

module.exports = {
    visible: 'shown'
};

secret cannot be accessed outside.

13. Module Caching

Node.js caches required modules.

Example:


const math1 = require('./math');
const math2 = require('./math');

math.js executes ONLY ONCE.

This is important for:

  • database connections
  • singleton services
  • config files

14. Circular Dependency Problem

Example:


// a.js
const b = require('./b');

// b.js
const a = require('./a');

This can cause partially loaded modules.

Avoid circular imports when possible.

15. CommonJS vs ES Modules

Modern JavaScript also supports ES Modules.

CommonJS:


const math = require('./math');
module.exports = math;

ES Modules:


import math from './math.js';
export default math;

16. When to Use Which

CommonJS (require)

Traditionally used in:

  • Node.js backend apps
  • Older projects
  • Express.js apps

ES Modules (import/export)

Modern standard:

  • React
  • Frontend apps
  • Modern Node.js
  • TypeScript

17. Architecture Pattern in Real Apps

Typical structure:


controllers/
services/
routes/
models/
middlewares/
utils/

Each file exports something:


module.exports = controller;
module.exports = router;
module.exports = service;

Then imported with:


require(...)

This creates a modular backend architecture.

18. Simple Mental Model

Think of a module like a box.


module.exports = {
    item1,
    item2
};

require() opens the box and gives you its contents.

19. Summary

Concept Meaning
require() Import another module
module.exports Export something from a module
exports Shortcut reference to module.exports
Each file Independent module
Node.js Wraps each file automatically
Modules cached Loaded once then reused

20. Best Practices

✅ Use:


module.exports = ...

for single exports.

✅ Use:


module.exports = {
    ...
}

for multiple exports.

✅ Keep modules focused on one responsibility.

✅ Avoid circular dependencies.

✅ Use folder separation:

  • routes
  • controllers
  • services
  • models
  • middleware

for scalable architecture.
