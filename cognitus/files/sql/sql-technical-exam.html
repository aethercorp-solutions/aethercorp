SQL technical exam

A SQL technical exam is a test that checks whether you can use SQL (Structured Query Language) to work with data in databases.

What Employers Usually Test

1. Basic Queries

Retrieve data from a table.


SELECT first_name, last_name
FROM employees;

Meaning: Show employee names.

2. Filtering Data (WHERE)

Find specific records.


SELECT *
FROM employees
WHERE salary > 50000;

Meaning: Show employees earning more than 50,000.

3. Sorting (ORDER BY)

Arrange results.


SELECT *
FROM employees
ORDER BY salary DESC;

Meaning: Highest salary first.

4. Grouping and Aggregation

Calculate totals, averages, counts.


SELECT department,
       COUNT(*) AS employee_count,
       AVG(salary) AS avg_salary
FROM employees
GROUP BY department;

Meaning: Count employees and average salary per department.

This SQL query summarizes employee data by department.

Query


SELECT department,
       COUNT(*) AS employee_count,
       AVG(salary) AS avg_salary
FROM employees
GROUP BY department;

Step-by-step

1. FROM employees

Use data from the employees table.

Example:

name department salary
John IT 5000
Mary IT 6000
Bob HR 4000
Alice HR 5000

2. GROUP BY department

Put employees into groups based on their department.

IT Group

  • John
  • Mary

HR Group

  • Bob
  • Alice

3. COUNT(*) AS employee_count

Count how many employees are in each department.

  • IT → 2 employees
  • HR → 2 employees

4. AVG(salary) AS avg_salary

Calculate the average salary for each department.

IT


(5000 + 6000) / 2 = 5500

HR


(4000 + 5000) / 2 = 4500

Result

department employee_count avg_salary
IT 2 5500
HR 2 4500

Simple Explanation

Think of GROUP BY as saying:

"Put employees into buckets based on department, then tell me how many people are in each bucket and what their average salary is."

This is one of the most common SQL interview questions because it demonstrates aggregation (COUNT, AVG) and grouping (GROUP BY).

5. Joins

Combine data from multiple tables.

Employees Table

id name department_id
1 John 10
2 John 20

Department Table

id department
10 IT
20 HR 

SELECT e.name, d.department
FROM employees e
JOIN departments d
ON e.department_id = d.id;

Result

name department
John IT
Mary HR

This SQL query combines data from two tables: employees and departments.

Query


SELECT e.name, d.department
FROM employees e
JOIN departments d
ON e.department_id = d.id;

Simple Explanation

Imagine you have these tables:

employees

id name department_id
1 John 101
2 Mary 102
3 Bob 101

departments

id department
101 Engineering
102 HR

What happens?


JOIN departments d
ON e.department_id = d.id

This tells SQL:

"Match each employee's department_id with the department table's id."

So:

  • John's department_id = 101 → Engineering
  • Mary's department_id = 102 → HR
  • Bob's department_id = 101 → Engineering

Result

name department
John Engineering
Mary HR
Bob Engineering

Breaking it down


SELECT e.name, d.department

Show:

  • Employee name
  • Department name

FROM employees e

Use the employees table.

e is just a short nickname (alias) for employees.


JOIN departments d

Combine with the departments table.

d is a nickname for departments.


ON e.department_id = d.id

Match rows where the department IDs are the same.

Real-world analogy

Think of:

  • employees table = people with department numbers
  • departments table = list of department numbers and names

The JOIN looks up the department name for each employee so you see:

"John works in Engineering" instead of "John works in department 101".

This is one of the most common SQL operations because data is often split into multiple related tables.

6. Subqueries

Query inside another query.


SELECT *
FROM employees
WHERE salary >
(
    SELECT AVG(salary)
    FROM employees
);

Meaning: Employees earning above average salary.

7. Common SQL Exam Question

Table: Orders

order_id customer amount
1 Paul 100
2 John 200
3 Paul 150

Question: Find total amount spent by each customer.


SELECT customer,
       SUM(amount) AS total_spent
FROM orders
GROUP BY customer;

Result

customer total_spent
Paul 250
John 200

For a Senior/Staff Engineer Role

Expect questions like:

  • Find the 2nd highest salary.
  • Explain indexes and when to use them.
  • Optimize a slow query.
  • Design a database schema.
  • Explain normalization vs denormalization.
  • Use window functions (ROW_NUMBER, RANK, DENSE_RANK).

Example:


SELECT *
FROM (
    SELECT salary,
           DENSE_RANK() OVER (ORDER BY salary DESC) AS rank_num
    FROM employees
) t
WHERE rank_num = 2;

Meaning: Find the second highest salary.

Since you're a Full Stack / Backend developer, most interviews will focus heavily on:

  1. Joins
  2. GROUP BY and aggregations
  3. Subqueries
  4. Indexes
  5. Query optimization
  6. Database design

Master those six areas and you'll pass most SQL technical exams.
