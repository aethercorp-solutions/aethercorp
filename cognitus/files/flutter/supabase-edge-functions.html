Supabase Edge Functions

Supabase Edge Functions let you run backend code without managing servers. They are similar to AWS Lambda, Google Cloud Functions, or Vercel Functions, but are designed to work closely with your Supabase project.

If you've worked with AWS Lambda + API Gateway, you'll find Edge Functions very familiar.

What are Edge Functions?

Instead of putting sensitive logic in your frontend:


React App
    │
    ├── Database
    └── Stripe API ❌ (secret key exposed)

You put it in an Edge Function:


React App
      │
      ▼
Supabase Edge Function
      │
      ├── PostgreSQL
      ├── Stripe
      ├── OpenAI
      ├── SendGrid
      └── Any REST API

The browser never sees your secret keys.

Environment Variables

Never hardcode API keys.

Set a secret:


supabase secrets set OPENAI_API_KEY=sk-xxxx

Read it in your function:


const apiKey = Deno.env.get("OPENAI_API_KEY")

Calling OpenAI


const response = await fetch(
    "https://api.openai.com/v1/responses",
    {
        method: "POST",
        headers: {
            Authorization: `Bearer ${apiKey}`,
            "Content-Type": "application/json"
        },
        body: JSON.stringify({
            model: "gpt-5",
            input: "Hello"
        })
    }
)

const data = await response.json()

return Response.json(data)

Accessing Supabase Database

Install the client:


import { createClient } from "jsr:@supabase/supabase-js@2"

const supabase = createClient(
    Deno.env.get("SUPABASE_URL")!,
    Deno.env.get("SUPABASE_SERVICE_ROLE_KEY")!
)

const { data } = await supabase
    .from("users")
    .select("*")

return Response.json(data)

Important: The SUPABASE_SERVICE_ROLE_KEY bypasses Row Level Security (RLS). Only use it in trusted server-side code like Edge Functions. Never expose it to your frontend.

Common Use Cases

  • Process payments with Stripe.
  • Send transactional emails.
  • Generate AI responses with OpenAI.
  • Verify JWTs or perform custom authorization.
  • Execute scheduled jobs (with cron).
  • Resize images or process uploaded files.
  • Integrate with third-party APIs.
  • Perform database operations that require elevated privileges.

Best Practices

  • Keep functions focused on one responsibility.
  • Store secrets using supabase secrets, not in source code.
  • Validate all request inputs before processing.
  • Return appropriate HTTP status codes and helpful error messages.
  • Prefer the anonymous key (anon) plus RLS when possible; use the service role key only when you truly need elevated access.
  • Log errors and avoid exposing sensitive details in responses.

A Complete Example: Contact Form

Suppose you have a React app where users submit a contact form.

Frontend


const { data, error } = await supabase.functions.invoke("contact", {
    body: {
        name: "Paul",
        email: "paul@example.com",
        message: "Hello!"
    }
})
    
if (error) {
    console.error(error)
} else {
    console.log(data)
}

Edge Function (functions/contact/index.ts)


import "jsr:@supabase/functions-js/edge-runtime.d.ts"

Deno.serve(async (req) => {
  try {
    const { name, email, message } = await req.json()

    if (!name || !email || !message) {
      return new Response(
        JSON.stringify({ error: "Missing required fields" }),
        {
          status: 400,
          headers: { "Content-Type": "application/json" }
        }
      )
    }

    // Save to the database or call another API here.

    return Response.json({
      success: true,
      message: "Contact form submitted successfully"
    })
  } catch {
    return new Response(
      JSON.stringify({ error: "Invalid request body" }),
      {
        status: 400,
        headers: { "Content-Type": "application/json" }
      }
    )
  }
})

This pattern scales well for tasks like sending emails, integrating AI, or processing payments because all sensitive logic stays on the server.
