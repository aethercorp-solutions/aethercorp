String.fromEnvironment()

In Flutter, String.fromEnvironment() is used to read compile-time environment variables when building your application. It's commonly used to configure different environments, such as Development, QA, UAT, and Production, without changing your Dart source code.

1. Basic example 


const String environment =
    String.fromEnvironment('ENV');

void main() {
  print(environment);
}

You can pass the environment value when running Flutter:


flutter run --dart-define=ENV=development

Output:


development

If you build your app for production:


flutter build appbundle --dart-define=ENV=production

The same Dart code can read production instead.

2. How it works


1. CI/CD Pipeline
Bitbucket Pipelines, for example
            

2. Pass environment variables
--dart-define=ENV=qa
            

3. Flutter build process
Embeds compile-time values into the app
            

4. Dart application
Reads the value using String.fromEnvironment()

The important point is that the value is supplied during compilation or app startup in the Flutter tool's compile-time configuration, not fetched automatically from your server.

3. Practical example: API base URLs

Suppose your application has three environments.

Environment API base URL
Development https://dev-api.example.com
QA https://qa-api.example.com
Production https://api.example.com

You can create an environment configuration class:


class AppConfig {
    static const String environment =
        String.fromEnvironment(
        'ENV',
        defaultValue: 'development',
    );
    
    static const String apiUrl =
        String.fromEnvironment(
        'API_URL',
        defaultValue: 'https://dev-api.example.com',
    );
}

Use the configuration in your API service:


final String baseUrl = AppConfig.apiUrl;

print('Environment: ${AppConfig.environment}');
print('API URL: $baseUrl');

Build for QA:


flutter build appbundle \
  --dart-define=ENV=qa \
  --dart-define=API_URL=https://qa-api.example.com

Build for Production:


flutter build appbundle \
  --dart-define=ENV=production \
  --dart-define=API_URL=https://api.example.com

Both builds use the same source code but have different configurations.

4. What does defaultValue mean?

Consider this code:


const String apiUrl = String.fromEnvironment(
  'API_URL',
  defaultValue: 'http://localhost:3000',
);
  • If API_URL is provided through --dart-define, Flutter uses that value.
  • If it isn't provided, the code uses http://localhost:3000.

This makes local development easier. However, be careful: localhost on an Android device refers to the device itself, not necessarily your computer.

5. Difference between String.fromEnvironment() and Platform.environment

Feature String.fromEnvironment() Platform.environment
Purpose Read compile-time declarations Read operating-system environment variables
Flutter web Supported for compile-time declarations Not supported
Typical use API URLs, feature flags, app configuration Server-side process configuration
Set using --dart-define OS or process environment

For Flutter application configuration, String.fromEnvironment() is often the appropriate choice.

6. How this fits into your CI/CD pipeline

For example, in Bitbucket Pipelines, you can define a QA build step:


- step:
    name: Build QA Android App
    script:
      - flutter pub get
      - flutter build appbundle
          --release
          --dart-define=ENV=qa
          --dart-define=API_URL=https://qa-api.example.com

Your pipeline can supply different values for Development, QA, UAT, and Production.

One security warning: --dart-define is not a secure secrets manager. Values embedded in a mobile application can potentially be extracted. Never use it to store database passwords, private API keys, or other confidential credentials.

In short: String.fromEnvironment() lets you configure your Flutter app at build time, so your CI/CD pipeline can produce different environment-specific builds without modifying your Dart code.
