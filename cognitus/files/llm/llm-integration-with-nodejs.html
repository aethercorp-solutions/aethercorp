LLM Integration with Node.js

LLM integration in Node.js means connecting your JavaScript backend to a Large Language Model (LLM), such as Claude, GPT, or Gemini, so your application can understand natural language, generate content, analyze documents, extract structured data, and automate tasks.

For an AI Engineer role, you should understand how to connect an LLM API, design prompts, validate responses, manage conversation history, implement RAG, and deploy the integration securely.

1. How LLM integration works 


1. Client application
React, React Native, Flutter, or iOS
            

2. Node.js backend
Express API, authentication, validation, business logic
            

3. LLM API
Claude, OpenAI GPT, or Gemini
            

4. Application response
Return generated text, structured JSON, or results from tools and databases

For example, imagine you are adding AI to a contact management application like Castanet:

  1. The user asks, "Summarize my last conversation with John."
  2. The React or React Native client sends the request to your Node.js API.
  3. Node.js authenticates the user and retrieves the relevant notes from MongoDB.
  4. Node.js sends the notes and instructions to Claude or GPT.
  5. The model generates a summary.
  6. The backend returns the result to the application.

Important: The LLM does not automatically know your database contents. Your backend must provide relevant information or connect the model to authorized tools.

2. Basic implementation using Node.js and Claude

Let's build a small API using Express and Anthropic's Claude API.

Step 1: Install dependencies


mkdir node-llm-demo
cd node-llm-demo

npm init -y
npm install express @anthropic-ai/sdk dotenv

Step 2: Configure environment variables

Create a .env file:


ANTHROPIC_API_KEY=your_api_key_here
PORT=3000

Obtain your API key from the Anthropic Console.

Never expose the API key in your frontend or commit .env to Git.

Step 3: Create the Node.js API

Create server.js:



require("dotenv").config();

const express = require("express");
const Anthropic = require("@anthropic-ai/sdk");

const app = express();
const client = new Anthropic({
  apiKey: process.env.ANTHROPIC_API_KEY,
});

app.use(express.json());

app.post("/api/ai/summarize", async (req, res) => {
  try {
    const { text } = req.body;

    if (typeof text !== "string" || !text.trim()) {
      return res.status(400).json({
        error: "Text is required",
      });
    }

    const response = await client.messages.create({
      model: "claude-sonnet-4-5",
      max_tokens: 500,
      messages: [
        {
          role: "user",
          content: `Summarize the following notes
in 3 concise bullet points:

${text}`,
        },
      ],
    });

    const summary = response.content
      .filter((item) => item.type === "text")
      .map((item) => item.text)
      .join("\n");

    res.json({ summary });
  } catch (error) {
    console.error("LLM request failed:", error.message);

    res.status(500).json({
      error: "Unable to generate summary",
    });
  }
});

app.listen(process.env.PORT || 3000, () => {
  console.log("LLM API server is running");
});

Run the server:


node server.js

Test it using curl:


curl -X POST http://localhost:3000/api/ai/summarize \
  -H "Content-Type: application/json" \
  -d '{"text":"John is a product manager. We discussed the project launch next Monday and agreed to follow up on Friday."}'

Example response:


{
    "summary": "- John is a product manager.\n- The project launch is planned for next Monday.\n- Follow up on Friday."
}

The model name is an example; check Anthropic's documentation for a currently supported model available to your account.

3. The five major types of LLM integration


1. Chat completion

Send a user's question to the LLM and return an answer. Maintain conversation history when context from previous messages is required.

Use cases: chatbots, customer support, coding assistants.
            

2. RAG (Retrieval-Augmented Generation)

Retrieve relevant information from documents or a database and pass it to the LLM to generate a grounded answer.

Use cases: internal knowledge assistants, immigration-document search, company policy Q&A.
            

3. Structured output

Extract information into a predictable schema, such as a person's name, case status, deadlines, and missing documents. Validate the output with Zod.

Use cases: document processing, CRM automation, data migration.
            

4. Tool calling

Allow the model to request specific backend functions, such as looking up a contact, checking an application status, or creating a follow-up task. Your server executes the authorized function.

Use cases: AI agents, workflow automation, intelligent assistants.
            

5. Streaming responses

Send generated text to the client incrementally using streaming APIs and Server-Sent Events (SSE), instead of waiting for the entire response.

Use cases: real-time chat interfaces and AI coding tools.

4. How RAG works with Node.js, Claude, and MongoDB

This is particularly valuable if you're preparing for an AI Engineer interview.


Documents and business data

PDFs, case notes, CRM records
            

Chunking and embeddings

Split documents and convert text into vectors
            

Vector search

Retrieve relevant chunks using MongoDB Atlas Vector Search or another vector database
            

Claude API

Question + retrieved context → grounded answer
            

Node.js API response

Answer with source references and appropriate error handling

For example, a user asks:

What documents are still missing from this client's visa application?

Your Node.js service would:

  1. Authenticate the user and verify access to the client's records.
  2. Search the authorized documents and application notes.
  3. Retrieve the most relevant passages.
  4. Send those passages to Claude with clear instructions.
  5. Generate a list of missing documents based on the supplied evidence.
  6. 1. Return the answer with source references, while avoiding unsupported claims.

Unlike basic LLM integration, RAG requires an additional retrieval pipeline, an embedding model, document processing, and a searchable index.

5. How to make an LLM integration production-ready

Concern Recommended approach
Security Keep API keys on the backend; authenticate users and enforce authorization
Input validation Use Zod or another schema-validation library
Reliability Add timeouts, bounded retries, and rate-limit handling
Cost control Limit input/output tokens and monitor usage
Accuracy Use RAG, source references, and output validation where appropriate
Observability Log latency, model errors, token usage, and request IDs without leaking sensitive data
Testing Mock LLM calls and test invalid inputs, failures, and edge cases
Privacy Minimize personal data sent to providers and apply retention policies

Do not blindly trust model-generated JSON, execute arbitrary generated code, or let tool calling bypass your normal permission checks.

6. What you should know for an AI Engineer interview

Given your Node.js, MongoDB, AWS, and full-stack background, concentrate on these concepts:

  • LLM APIs: prompts, system instructions, message roles, tokens, context windows.
  • Prompt engineering: clear instructions, examples, constraints, and output formats.
  • RAG: chunking, embeddings, vector similarity, retrieval quality, and grounding.
  • Tool calling: connecting the model to business APIs through controlled server-side functions.
  • Structured extraction: JSON schemas, Zod validation, and handling malformed outputs.
  • Production engineering: retries, rate limits, caching, monitoring, privacy, and cost optimization.
  • -Deployment: exposing your Express service through AWS Lambda/API Gateway or another backend platform.

The key distinction to communicate in an interview is that integrating an LLM is not just calling an API. It means building a reliable software system around the model, including data retrieval, validation, security, evaluation, and monitoring.
