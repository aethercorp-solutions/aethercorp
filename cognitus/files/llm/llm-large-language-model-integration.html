LLM (Large Language Model) integration

LLM (Large Language Model) integration with an application means connecting an AI model to your existing software so it can understand user requests, generate responses, analyze data, and perform tasks.

For example, you can integrate an LLM into a web application, mobile app, CRM, ERP, chatbot, or internal business system.

1. How LLM integration works 


User / Application UI
Web app, mobile app, or desktop software
            

Backend / Application Server

Authentication, business logic, prompt construction
            

LLM API

OpenAI, Anthropic, Google, or a self-hosted model
            

Data and Tools

SQL database, internal APIs, documents, business services

The backend sends the user's request to the model, receives the response, and returns the result to the application. When necessary, it can also retrieve relevant data or invoke approved application functions.

2. Common integration approaches


A. LLM API integration
Connect directly to a hosted model using an API.
- Best for: chatbots, content generation, summarization.
- Complexity: Low to medium.
- Example: A customer support chatbot using the OpenAI API.
            

B. RAG (Retrieval-Augmented Generation)
Let the LLM answer questions using your company's documents and data.
- Best for: internal knowledge bases, policies, manuals, technical documentation.
- Components: document processing, embeddings, vector database, retrieval, LLM.
- Example: An employee asks questions about company policies.
            

C. LLM with tools and function calling
Allow the model to request specific operations through your backend.
- Best for: business process automation.
- Example: Checking an order, creating a support ticket, or generating a report.
- Important: Your application must validate and authorize each operation.

3. Example: Integrating an LLM into a web application

Suppose you have a Node.js backend and want to add an AI assistant.

Install the official OpenAI SDK:


npm install openai express

Create a basic Express endpoint:


import express from "express";
import OpenAI from "openai";

const app = express();
app.use(express.json());

const client = new OpenAI({
  apiKey: process.env.OPENAI_API_KEY,
});

app.post("/api/ai", async (req, res) => {
  try {
    const { message } = req.body;

    if (typeof message !== "string" || !message.trim()) {
      return res.status(400).json({
        error: "A message is required",
      });
    }

    const response = await client.responses.create({
      model: process.env.OPENAI_MODEL || "gpt-5",
      input: message,
    });

    res.json({
      answer: response.output_text,
    });
  } catch (error) {
    console.error("LLM request failed");
    res.status(500).json({
      error: "Unable to process your request",
    });
  }
});

app.listen(3000);

Set your API key and a model available to your account in environment variables. Keep the API key on the server, never in browser or mobile application code. The model identifier above is an example and may need to be changed to a currently available model.

Your frontend can call the endpoint with:


const response = await fetch("/api/ai", {
    method: "POST",
    headers: {
        "Content-Type": "application/json",
    },
    body: JSON.stringify({
        message: "Summarize the latest customer feedback",
    }),
});

const result = await response.json();
console.log(result.answer);

This is a minimal starting point. A production integration should also include authentication, rate limits, input validation, usage monitoring, and appropriate error handling.

4. Recommended architecture by use case

Requirement Recommended approach
Chatbot or virtual assistant LLM API
Ask questions about company documents RAG + LLM
Query business data LLM + controlled backend tools
Generate SQL queries LLM + SQL validation and read-only permissions
Automate multi-step workflows LLM + tools or agent orchestration
Run AI on private infrastructure Self-hosted model, subject to hardware and model requirements
