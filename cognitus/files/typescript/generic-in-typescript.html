Generic in TypeScript

A generic in TypeScript is a way to make code work with different types without rewriting it.

Think of it as a placeholder for a type.

Without Generics

Imagine a function that returns a string.


function getValue(value: string): string {
    return value;
}

It only works with strings.

If you want numbers too:


function getNumber(value: number): number {
    return value;
}

Now you're repeating code.

With Generics

Instead of specifying the type, use a placeholder (T).


function getValue(value: T): T {
    return value;
}

T means "whatever type the caller gives me."

Examples:


getValue<string>("Hello");

T = string

Returns:


"Hello"
            

getValue<number>(100);

Returns:


100

You usually don't even need to specify it.

TypeScript figures it out.


getValue("Hello"); // T = string
getValue(100);     // T = number
getValue(true);    // T = boolean

Why use Generics?

One function works for every type.

Without generics:


function printString(value: string) {
    console.log(value);
}

function printNumber(value: number) {
    console.log(value);
}

function printBoolean(value: boolean) {
    console.log(value);
}

With generics:


function print(value: T) {
    console.log(value);
}

Now it works for anything.

Generic Arrays

Instead of saying:


string[]

you can write


Array<string>

Examples:


const names: Array<string> = ["John", "Jane"];

const numbers: Array<number> = [1, 2, 3];

Generic Interfaces

Without generics:


interface UserResponse {
    data: User;
}

If you need posts:


interface PostResponse {
    data: Post;
}

Lots of duplication.

With generics:


interface ApiResponse<T> {
    data: T;
}

Use it like this:


const user: ApiResponse<User> = {
    data: {
        id: 1,
        name: "John",
    },
};

const post: ApiResponse<Post> = {
    data: {
        id: 10,
        title: "Hello",
    },
};

Same interface, different types.

Generic Functions (Real Example)


async function fetchData(url: string): Promise {
    const response = await fetch(url);
    return response.json();
}

Suppose you have:


type User = {
    id: number;
    name: string;
};

Call it like this:


const user = await fetchData<User>("/api/user");

TypeScript knows:


user.id
user.name

and provides autocomplete.

Multiple Generic Types

You can have more than one placeholder.


function pair<T, U>(first: T, second: U) {
    return {
        first,
        second,
    };
}

Example:


const result = pair("John", 25);

TypeScript infers:


T = string
U = number

Result:


{
    first: "John",
    second: 25
}

Generic Constraints

Sometimes you want to limit what types are allowed.

Without a constraint:


function printLength(item: T) {
    console.log(item.length); // ❌ Error
}

T could be a number, which doesn't have a length property.

Add a constraint:


function printLength<T extends { length: number }>(item: T) {
    console.log(item.length);
}

Now these work:


printLength("Hello");
printLength([1, 2, 3]);

But this doesn't:


printLength(100); // ❌ number has no length

Real-World Axios Example


type User = {
    id: number;
    name: string;
};

const response = await axios.get<User>("/users/1");

Here:


<User>

is the generic.

It tells Axios:

"The server will return a User."

Now TypeScript knows:


response.data.id
response.data.name

Easy Way to Remember

Think of a generic as a type variable, just like variables hold values.


let x = 10;

x is a placeholder for a value.

Similarly:


function identity(value: T): T {
    return value;
}

T is a placeholder for a type.

If you call:


identity("Hello");

then:


T = string

If you call:


identity(123);

then:


T = number

The function logic stays the same—it simply adapts to the type you pass in.

A simple analogy

Imagine a gift box 📦.

  • The box is your generic function.
  • The item inside can be anything.

function box(item: T): T {
    return item;
}

You can put in:


box("Book");     // T = string
box(42);         // T = number
box(true);       // T = boolean

The box doesn't care what's inside—it just keeps the item's type intact. That's exactly what generics do: they let you write reusable code while preserving type safety.
