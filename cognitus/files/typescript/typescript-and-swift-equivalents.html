Typescript and Swift equivalents

Since you already know Swift, the easiest way to learn TypeScript is to map its features to their Swift equivalents. Many concepts are surprisingly similar.

Typescript vs Swift

TypeScript Swift Description
interface protocol Defines the shape of an object.
type typealias (sometimes) Creates a custom type or combines types.
class class Object-oriented class.
extends Inheritance (:) Child class inherits from parent.
implements Protocol conformance Class promises to implement an interface/protocol.
enum enum Enumeration values.
readonly let Immutable property.
const let Immutable variable.
let var Mutable variable.
any Any Can hold any type.
unknown Any (must cast before use) Safer version of any.
never Never Function never returns.
null/undefined nil Missing value.
? Optional (?) Value may be absent.
?? ?? Nil coalescing.
?. ?. Optional chaining.

1. Variables

TypeScript


let name = "Paul";
const age = 30;

Swift


var name = "Paul"
let age = 30

Very similar:

  • let (Swift) ≈ const (TypeScript)
  • var (Swift) ≈ let (TypeScript)

2. Interfaces = Protocols

TypeScript


interface User {
    name: string;
    age: number;
}

Swift


protocol User {
    var name: String { get }
    var age: Int { get }
}

Interfaces only describe structure.

3. Classes

TypeScript


class Animal {
    speak() {
        console.log("...");
    }
}

Swift


class Animal {
    func speak() {
        print("...")
    }
}

Nearly identical.

4. Inheritance

TypeScript


class Dog extends Animal {
    speak() {
        console.log("Woof");
    }
}

Swift


class Dog: Animal {
    override func speak() {
        print("Woof")
    }
}

extends = : ParentClass

5. Implements = Protocol Conformance

TypeScript


interface Flyable {
    fly(): void;
}

class Bird implements Flyable {
    fly() {
        console.log("Flying");
    }
}

Swift


protocol Flyable {
    func fly()
}

class Bird: Flyable {
    func fly() {
        print("Flying")
    }
}

6. Optional Values

TypeScript


let name: string | null = null;

or


let name?: string;

Swift


var name: String?

Both mean the value might not exist.

7. Optional Chaining

TypeScript


user?.address?.city

Swift


user?.address?.city

Exactly the same syntax.

8. Nil Coalescing

TypeScript


const username = name ?? "Guest";

Swift


let username = name ?? "Guest"

Again, identical.

9. Generics

TypeScript


function printItem<T>(item: T) {
    console.log(item);
}

Swift


func printItem<T>(_ item: T) {
    print(item)
}

Same idea: T can be any type.

10. Generic Constraints

TypeScript


function printLength<T extends { length: number }>(item: T) {
    console.log(item.length);
}

Swift


protocol HasLength {
    var length: Int { get }
}

func printLength<T: HasLength>(_ item: T) {
    print(item.length)
}

extends in generics is like Swift's protocol constraint.

11. keyof

One of TypeScript's most powerful features.

TypeScript


interface User {
    name: string;
    age: number;
}

type Keys = keyof User;

Keys becomes:


"name" | "age"

Swift doesn't have a direct equivalent. The closest is KeyPath.


let keyPath = \User.name

or


                PartialKeyPath<User>

12. Mapped Types

TypeScript


type ReadonlyUser = {
    readonly [K in keyof User]: User[K];
};

This loops over every property and makes it readonly.

Swift has no direct equivalent.

You'd have to manually write:


struct User {
    let name: String
    let age: Int
}

TypeScript can generate new types automatically.

13. Union Types

TypeScript


let value: string | number;

Can hold either.

Swift doesn't support arbitrary union types.

Closest:


enum Value {
    case text(String)
    case number(Int)
}

14. Literal Types

TypeScript


type Direction = "left" | "right";

Only two allowed values.

Swift equivalent:


enum Direction {
    case left
    case right
}

15. Utility Types

TypeScript provides built-in helpers.


Partial<User>

All properties become optional.

Swift has no built-in equivalent.


Readonly<User>

All properties become immutable.

Swift:


let

or immutable structs.


Pick<User, "name">

Keeps only selected properties.

No direct Swift equivalent.

16. Async/Await

TypeScript


const user = await fetchUser();

Swift


let user = try await fetchUser()

Swift additionally requires try for throwing functions.

17. Type Inference

TypeScript


let age = 25;

Compiler knows it's a number.

Swift


let age = 25

Compiler knows it's an Int.

18. Type Guards

TypeScript


if (typeof value === "string") {
    console.log(value.toUpperCase());
}

Swift


if let value = value as? String {
    print(value.uppercased())
}

Both safely narrow the type before using it.

19. Function Overloads

TypeScript


function add(a: number, b: number): number;
function add(a: string, b: string): string;

Swift


func add(_ a: Int, _ b: Int) -> Int

func add(_ a: String, _ b: String) -> String

20. Extensions

TypeScript


interface User {
    age: number;
}

interface User {
    name: string;
}

Interfaces merge automatically.

Swift uses explicit extensions:


extension User {
    func greet() {}
}

Mental Mapping

If you know Swift... Think of TypeScript as...
protocol interface
typealias type
let const
var let
Optional (?) ? or undefined
nil null/undefined
enum enum
func<T> function<T>
T: Protocol T extends Interface
KeyPath keyof (closest concept)
Any any
Any with casting unknown
Never never

The biggest TypeScript features that don't have close Swift equivalents are union types (A | B), mapped types ([K in keyof T]), conditional types, and utility types (Partial, Pick, Omit, Readonly). These are part of TypeScript's advanced type system for transforming types at compile time.
