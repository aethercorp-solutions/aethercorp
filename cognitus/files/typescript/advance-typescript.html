Advance TypeScript

The biggest mistake people make is trying to memorize every feature. Instead, learn why each feature exists.

If you already understand:

  • ✅ types (string, number, etc.)
  • ✅ interfaces
  • ✅ functions
  • ✅ async/await
  • ✅ basic generics ()

then you're ready for advanced TypeScript.

Level 1: Generics (The Foundation)

Everything else builds on generics.

Without generics:


function identity(value: any) {
    return value;
}

const x = identity(5); // any

With generics:


function identity(value: T): T {
    return value;
}

const x = identity(5); // number
const y = identity("Hello"); // string

Think of as

"I don't know the type yet. Tell me later."

Multiple Generics


function pair(first: T, second: U) {
    return { first, second };
}

pair(1, "Paul");

Result


{
    first: number
    second: string
}

Level 2: Constraints

Sometimes you don't want any type.

Example:


function printLength(item: T) {
    console.log(item.length);
}

Error.

Because


T could be number.

5.length?

Tell TypeScript the rule.


function printLength<T extends { length: number }>(item: T) {
    console.log(item.length);
}

Now these work:


printLength("Hello");

printLength([1,2,3]);

printLength({
    length: 100
});

Think


extends = must satisfy this shape

NOT inheritance.

Level 3: keyof

Suppose


const user = {
    id:1,
    name:"Paul",
    age:40
};

You only want valid property names.


function getValue<T, K extends keyof T>(
    obj:T,
    key:K
){
    return obj[key];
}

Now


getValue(user,"name");

Works.

But


getValue(user,"salary");

Error.

Because


keyof user

=

"id" | "name" | "age"

Level 4: Indexed Access Types

You can access a property's type.


type User = {
    id:number;
    name:string;
};

type Name = User["name"];

Result


string

Multiple keys


type Info = User["id" | "name"];

Result


number | string

Level 5: Union Types


type Status =
    | "loading"
    | "success"
    | "error";

Usage


let status: Status;

status = "loading";

status = "done"; // Error

Perfect for APIs.

string

Level 7: Type Narrowing

Suppose


type User =
    | string
    | number;

How do you know which?


function print(value: string | number) {

    if(typeof value === "string"){

        console.log(value.toUpperCase());

    }else{

        console.log(value.toFixed(2));

    }

}

TypeScript understands.

This is called narrowing.

Level 8: Discriminated Unions

One of the most useful features.


type Circle = {
    type:"circle";
    radius:number;
};

type Rectangle = {
    type:"rectangle";
    width:number;
    height:number;
};

Now


type Shape =
    | Circle
    | Rectangle;

Usage


function area(shape:Shape){

    if(shape.type==="circle"){

        return Math.PI * shape.radius **2;

    }

    return shape.width * shape.height;

}

No casting needed.

Level 9: Utility Types

Instead of creating new types manually.

Original


interface User{
    id:number;
    name:string;
    age:number;
}

Partial

Everything optional.


Partial<User>

Equivalent


{
    id?;
    name?;
    age?;
}

Useful for updates.

Required

Everything required.


Required<User>

Pick


type UserPreview =
Pick<User,"id" | "name">

Result


{
    id:number;
    name:string;
}

Omit


Omit<User,"age">

Result


{
    id:number;
    name:string;
}

Record


type Scores =
Record<string,number>

Equivalent


{
    [key:string]:number;
}

Level 10: Mapped Types

Transform every property.


type User = {

    id:number;
    name:string;

};

Mapped type


type ReadonlyUser = {

    readonly [K in keyof User]:

    User[K];

};

Equivalent


{

    readonly id:number;
    
    readonly name:string;
    
}

TypeScript's built-in Readonly is implemented using this idea.

Level 11: Conditional Types

"If this type...

then...

otherwise..."


type IsString<T> =
    T extends string
        ? true
        : false;

Example


type A = IsString<string>

Result


true

Level 12: infer

Extract types automatically.


type Return<T> =
    T extends (...args:any[])=>infer R
        ? R
        : never;

Example


function add(){

    return 10;

}
            

type Result =
Return<typeof add>

Result


number

Level 13: Template Literal Types


type Event =
    "click"
    | "hover";

Build new strings.


type EventHandler =
`on${Capitalize<Event>}`;

Result


"onClick"

"onHover"

Level 14: Generic API Example


interface ApiResponse<T> {
    success: boolean;
    data: T;
}

interface User {
    id: number;
    name: string;
}

async function fetchUser(): Promise<ApiResponse<User>> {
    return {
        success: true,
        data: {
            id: 1,
            name: "Paul"
        }
    };
}

The API wrapper (ApiResponse<T>) stays the same, while T changes depending on the data you fetch.

Level 15: Putting It All Together


function getValue<T, K extends keyof T>(
    obj: T,
    key: K
): T[K] {
    return obj[key];
}

interface User {
    id: number;
    name: string;
    age: number;
}

const user: User = {
    id: 1,
    name: "Paul",
    age: 40
};

const name = getValue(user, "name"); // string
const age = getValue(user, "age");   // number

This combines:

  • Generic types (T, K)
  • Constraints (K extends keyof T)
  • Indexed access types (T[K])
  • Type inference (no need to specify <User, "name">)

A Roadmap to Master TypeScript

Learn these topics in order because each builds on the previous one:

  1. Generics (<T>)
  2. Generic Constraints (extends)
  3. keyof
  4. Indexed Access Types (T[K])
  5. Union & Intersection Types
  6. Literal Types
  7. Type Narrowing
  8. Discriminated Unions
  9. Utility Types (Partial, Pick, Omit, Record, Readonly)
  10. Mapped Types
  11. Conditional Types
  12. infer
  13. Template Literal Types
  14. Real-world patterns (typed API clients, React hooks, Axios wrappers, repositories, event systems)

How to truly master it

Reading isn't enough—you need to build things that force you to use these features repeatedly. Since you're working with React, Node.js, Axios, and APIs, try implementing:

  • A fully typed Axios client with request/response generics.
  • A reusable API service (ApiService<T>) that supports CRUD operations.
  • Generic React hooks like useFetch<T>() or useForm<T>().
  • A repository pattern where entities are generic.
  • Utility types for transforming DTOs into UI models.

By solving real problems with these concepts, you'll start recognizing when each feature is the right tool instead of trying to memorize syntax. That's the point where advanced TypeScript becomes intuitive.
