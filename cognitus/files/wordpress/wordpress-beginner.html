1. Understand what WordPress actually is

WordPress is essentially a PHP web application + MySQL database.

A simplified architecture:


Browser
   │
   ▼
Web Server
(Nginx/Apache)
   │
   ▼
PHP
   │
   ▼
WordPress
   │
   ├── Themes
   ├── Plugins
   ├── Media
   ├── Users
   └── WordPress Core
          │
          ▼
       MySQL

Compare this with something you're already familiar with:


React frontend
      │
      ▼
Node.js / Express API
      │
      ▼
MongoDB

WordPress:


PHP/Theme
      │
      ▼
WordPress Core
      │
      ▼
MySQL

The important difference is that WordPress already provides much of the application infrastructure that you'd normally build yourself.

You'll find themes here:


wp-content/themes/

For example:


wp-content/themes/mytheme/

A traditional theme might contain:

Part 6 — Create your first theme

Create:


wp-content/themes/my-first-theme/

Then:


style.css
index.php
functions.php

style.css contains the theme metadata.

For example:


/*
Theme Name: My First Theme
Author: Paul
Version: 1.0
*/

Then WordPress can recognize the directory as a theme.

Your first PHP template can be:


<?php

get_header();

if (have_posts()) {
    while (have_posts()) {
        the_post();

        the_title();
        the_content();
    }
}

get_footer();

This introduces one of the most important WordPress concepts:

The WordPress Loop


if (have_posts()) {

    while (have_posts()) {

        the_post();

        the_title();
        the_content();

    }
}

Conceptually:


Query database
      ↓
Are there posts?
      ↓
     YES
      ↓
Load post
      ↓
Display post
      ↓
Next post

Part 8 — functions.php

This is where you register functionality for your theme.

For example:


<?php

function mytheme_setup() {

    add_theme_support('title-tag');

    add_theme_support('post-thumbnails');

    register_nav_menus([
        'primary' => 'Primary Menu'
    ]);
}

add_action('after_setup_theme', 'mytheme_setup');

Notice something important:


add_action(...)

This introduces the WordPress Hooks system.

Part 9 — Hooks

WordPress has two major hook types:


Actions
Filters

Action

Do something when something happens.


add_action('init', function () {
    // do something
});

Filter

Modify existing data.


add_filter('the_title', function ($title) {

    return $title . ' - My Site';

});

This is extremely important for WordPress plugin development.

Part 10 — Plugins

my-plugin.php

Plugin Name: My First Plugin

Part 11 — Custom Post Types

    'public' => true,
    'label'  => 'Projects',
    'supports' => [
        'title',
        'editor',
        'thumbnail'
    ]
]);

Now WordPress has:

Part 13 — WordPress REST API

This part should be especially interesting for you because of your React/Node experience.

WordPress provides an API such as:


/wp-json/wp/v2/posts

A React application can request:


React
   │
   │ HTTP GET
   ▼
WordPress REST API
   │
   ▼
MySQL

For example:


fetch(
  'https://example.com/wp-json/wp/v2/posts'
)
.then(response => response.json())
.then(posts => {
    console.log(posts);
});

Now WordPress can act as a headless CMS.
