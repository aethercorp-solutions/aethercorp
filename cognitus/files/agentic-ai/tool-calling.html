Tool calling

Tool calling is a feature that allows an AI model to use external functions, APIs, databases, and other software to perform actions instead of only generating text.

Think of it this way: the AI decides what needs to be done, calls a tool to do it, receives the result, and then responds to the user.

1. How tool calling works 


1. User asks a question
"Find the current status of application REF-123"
            

2. AI selects a tool
Decides to call getApplicationStatus().
            

3. Tool executes
Your backend calls the API or queries the database.
            

4. AI returns the result
"Application REF-123 is awaiting review."

2. Example using Node.js and an AI API

Suppose you're building an immigration services platform and want an AI assistant to look up application statuses.

First, define a tool the AI is allowed to request:


const tools = [
  {
    type: "function",
    name: "get_application_status",
    description: "Get an application's current status",
    parameters: {
      type: "object",
      properties: {
        referenceNumber: {
          type: "string",
          description: "Application reference number"
        }
      },
      required: ["referenceNumber"],
      additionalProperties: false
    },
    strict: true
  }
];

The AI can request a call with arguments like:


{
    "referenceNumber": "REF-123"
}

Your application executes the corresponding function:


async function getApplicationStatus(referenceNumber) {
    const response = await fetch(
        `https://api.example.com/applications/${encodeURIComponent(referenceNumber)}`,
        {
        headers: {
            Authorization: `Bearer ${process.env.API_TOKEN}`
        }
        }
    );
    
    if (!response.ok) {
        throw new Error("Unable to retrieve application status");
    }
    
    const application = await response.json();
    
    return {
        referenceNumber: application.referenceNumber,
        status: application.status,
        updatedAt: application.updatedAt
    };
}

Important: defining a tool does not execute it automatically. Your application must handle the AI's tool-call request, validate the arguments, execute the function, and send the result back to the model so it can formulate its answer. The example function is illustrative and would need to be connected to your actual API.

3. Tool calling vs. a normal AI response

Normal AI response AI with tool calling
Generates text from its available context Can request real operations
May not know current database values Can retrieve current data
Cannot send an email by merely describing it Can request an email-sending function
Can suggest a calculation Can call a calculator or execute code
Answers based on provided information Can retrieve information and then answer

Tool calling does not mean the AI can access everything on your computer or server. It can only use tools that your application or platform makes available, subject to their permissions.

4. Tool calling vs. MCP vs. agentic AI

These three concepts are related but different.

Tool calling

The mechanism an AI uses to request a function, such as searchClients() or sendEmail().

MCP (Model Context Protocol)

A standard way for AI applications to discover and interact with tools and resources exposed by MCP servers.

Agentic AI

An AI system that can plan and perform multiple steps, using tools repeatedly to work toward a goal.

5. How you could use it in a production system

For an immigration services platform like the one you're exploring, you could expose tools such as:

  • get_client_details() — retrieve authorized client records.
  • search_immigration_rules() — find relevant official guidance in a RAG knowledge base.
  • extract_document_fields() — request structured extraction from a document.
  • check_missing_documents() — compare client records with a required-document checklist.
  • create_follow_up_draft() — prepare an email for a caseworker to review.
  • update_case_status() — update a case after authorization and validation.

The AI chooses when to request a tool, but your backend should enforce access controls, validate inputs, log important actions, and require human approval for consequential operations.

Interview-ready explanation:

Tool calling allows an LLM to interact with external systems through predefined functions. I define each tool with a clear description and schema, let the model request the appropriate function, validate the arguments on the backend, execute the API or database operation, and return the result to the model. In production, I also implement authentication, authorization, error handling, retries where appropriate, and audit logging. This enables AI applications to do useful work while keeping business logic and security under application control.
