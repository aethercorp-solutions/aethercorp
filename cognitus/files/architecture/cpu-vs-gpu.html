CPU vs GPU

The simplest way to think about it:

CPU = a few very smart workers

GPU = thousands of simpler workers

🧠 CPU — Central Processing Unit

The CPU is the general-purpose brain of the computer.

It is very good at doing different kinds of tasks, one after another, and making decisions.

For example:


CPU
 ├── Run your operating system
 ├── Open applications
 ├── Run JavaScript
 ├── Handle files
 ├── Make decisions
 └── Run complex program logic

A CPU might have 4, 8, 16, 24+ powerful cores.

Each core is relatively sophisticated.

🎮 GPU — Graphics Processing Unit

A GPU is designed to perform many similar calculations at the same time.

For example, imagine you need to calculate the color of 1 million pixels:


CPU:

Worker 1 → Pixel 1
Worker 1 → Pixel 2
Worker 1 → Pixel 3
Worker 1 → Pixel 4
...

A GPU can do something more like:


GPU:

Worker 1    → Pixel 1
Worker 2    → Pixel 2
Worker 3    → Pixel 3
Worker 4    → Pixel 4
Worker 5    → Pixel 5
...
Worker 1000 → Pixel 1000

That's why GPUs are extremely good at parallel computation.

The important difference

CPU GPU
Main idea General-purpose Massive parallel processing
Cores Relatively few Thousands of smaller processing units
Good at Logic, decisions, operating systems Repeated mathematical calculations
Graphics Can do it Excellent
AI/ML Can do it Very fast
Sequential tasks Excellent Less suited
Parallel tasks Good Excellent

A neural network may perform billions or trillions of these operations.

That's where the GPU shines:

So, CPU and GPU aren't really competitors.

They work together:

CPU decides what needs to be done; GPU does huge amounts of parallel math very quickly.

This is also why GPUs became extremely important for AI, vectors, embeddings, neural networks, and LLMs.

Technically, the key difference is how the processor allocates hardware resources to computation.

1. CPU: optimized for general-purpose, low-latency computation

A CPU has a relatively small number of powerful cores. Each core contains sophisticated control logic, large caches, branch prediction, out-of-order execution, etc.

Conceptually:


                CPU
┌─────────────────────────────────────────┐
│ Core 0 │ Core 1 │ Core 2 │ Core 3 │ ... │
│        │        │        │        │     │
│ ALU    │ ALU    │ ALU    │ ALU    │     │
│ FPU    │ FPU    │ FPU    │ FPU    │     │
│ Cache  │ Cache  │ Cache  │ Cache  │     │
└─────────────────────────────────────────┘

A CPU is particularly good at:


if (user.isAuthenticated) {
    loadUserData();
} else {
    showLogin();
}

There are branches, decisions, dependencies, and irregular operations.

2. GPU: optimized for massive parallelism

A GPU has a much larger number of arithmetic processing resources.

Modern GPUs organize these into groups such as SMs (NVIDIA Streaming Multiprocessors) or CUs (AMD Compute Units).

Simplified:


                GPU
┌───────────────────────────────────────────┐
│ SM/CU │ SM/CU │ SM/CU │ SM/CU │ ...       │
│       │       │       │       │           │
│ ALUs  │ ALUs  │ ALUs  │ ALUs  │           │
│ ALUs  │ ALUs  │ ALUs  │ ALUs  │           │
│ ALUs  │ ALUs  │ ALUs  │ ALUs  │           │
└───────────────────────────────────────────┘

The GPU is designed to execute many operations concurrently.

For example, suppose we have:


C[i] = A[i] + B[i]

for 1,000,000 elements.

A CPU might process chunks using its relatively small number of cores.

A GPU can distribute the work across a huge number of threads:


Thread 0       → C[0] = A[0] + B[0]
Thread 1       → C[1] = A[1] + B[1]
Thread 2       → C[2] = A[2] + B[2]
...
Thread 999999  → C[999999] = A[999999] + B[999999]

The important concept is parallel throughput.

3. CPU vs GPU at the architectural level

Think about two different goals:

CPU:


                ┌── Complex instruction
                │
                ├── Branch
                │
                ├── Load data
                │
                ├── Make decision
                │
                └── Execute next instruction
                        ↓
                   LOW LATENCY

GPU:


Input data
    │
    ├── Operation 1 ─┐
    ├── Operation 2 ─┤
    ├── Operation 3 ─┤
    ├── Operation 4 ─┤
    ├── Operation 5 ─┤
    ├── ...          ├──> MASSIVE PARALLELISM
    └── Operation N ─┘

So:

CPU → optimize for latency and general-purpose execution

GPU → optimize for throughput and parallel execution

4. Why this matters for vectors and AI

This connects directly to what you were asking about vectors and embeddings.

Suppose an embedding is:


A = [0.2, 0.7, 0.1, 0.9]

and another vector is:


B = [0.4, 0.3, 0.8, 0.2]

A common operation is a dot product:


A⋅B=(0.2)(0.4)+(0.7)(0.3)+(0.1)(0.8)+(0.9)(0.2)

A GPU is very good at this type of workload because neural networks perform enormous numbers of multiply-add operations.

For a neural network, you might have a matrix:


                W

and an input vector:


                x

and calculate:


                y=Wx

For example:


                Matrix W
                ┌───────────────┐
                │ 0.2  0.7  0.1 │
                │ 0.4  0.3  0.8 │
                │ 0.9  0.2  0.5 │
                └───────────────┘
                       ×
                ┌─────────┐
                │   0.6   │
                │   0.1   │
                │   0.8   │
                └─────────┘
                       ↓
                       y

This produces many independent arithmetic operations that can be executed in parallel.

That's exactly the kind of workload GPUs are designed for.

GPUs typically emphasize memory bandwidth because thousands of computation threads need data simultaneously.

This is one reason AI accelerators use very high-bandwidth memory such as HBM in data-center systems.

6. SIMD/SIMT

A more technical distinction is the execution model.

CPUs use techniques such as SIMD (Single Instruction, Multiple Data):


ONE instruction
      ↓
┌─────┬─────┬─────┬─────┐
│ A+B │ A+B │ A+B │ A+B │
└─────┴─────┴─────┴─────┘

GPUs take this idea much further through SIMT (Single Instruction, Multiple Threads).

Conceptually:


            Instruction
                ↓
     ┌──────────┼──────────┐
     ↓          ↓          ↓
  Thread 0   Thread 1   Thread 2 ...
     ↓          ↓          ↓
  Data[0]    Data[1]    Data[2]

Threads are grouped together and execute efficiently when they follow similar instructions.

If GPU threads diverge heavily:


Thread 0 → IF
Thread 1 → ELSE
Thread 2 → IF
Thread 3 → ELSE

the GPU can become less efficient because the hardware is optimized for threads doing similar work.

Characteristic CPU GPU

Branch-heavy code Excellent Often inefficient
Parallel arithmetic Good Excellent
SIMD/SIMT SIMD SIMT

Matrix multiplication Good Excellent
Neural networks Can run them Highly optimized for them
Operating system Excellent Not its primary role
JavaScript/backend logic Excellent Generally inappropriate

One sentence to remember

A CPU is designed to execute a relatively small number of complicated instruction streams extremely flexibly, while a GPU is designed to execute enormous numbers of similar arithmetic operations concurrently.

And this is the fundamental reason GPU → matrix multiplication → neural networks → LLMs is such an important chain in modern AI.

In this CPU/GPU context, latency means the amount of time it takes for a computation to start and produce its result.

Simple example

Suppose your program asks:


CPU: "Calculate 5 + 3."

If the CPU produces the answer in 1 microsecond, that's its latency:


                Request ────────────────> Result
          1 μs

So:

Latency = how quickly you get an individual result.

CPU vs GPU

This is why we say:

CPU → optimized for low latency

A CPU is designed to quickly handle an individual task:


Task → CPU → Result
       ↓
    very fast

A GPU is optimized more for throughput—doing a huge amount of work overall:


Task 1 ─┐
Task 2 ─┤
Task 3 ─┤
Task 4 ─┤ → GPU → thousands of results
Task 5 ─┤
  ...   │
Task N ─┘

The GPU may have some overhead before it gets all those operations running, but once running, it can process massive numbers of operations simultaneously.

Latency vs throughput

This distinction is extremely important:

Concept Meaning Think of it as
Latency Time to complete one operation/request 🚗 How fast one car reaches the destination
Throughput Amount of work completed per unit of time 🚦 How many cars reach the destination per minute

For example:


CPU:
Request → Result
         ↓
      1 ms

GPU:
100,000 requests → many results
         ↓
      enormous throughput

So when we say "CPU is optimized for low latency, GPU for high throughput," we're saying:

CPU is excellent when you need an individual operation to finish quickly and flexibly. GPU is excellent when you have huge amounts of similar work that can be processed simultaneously.
