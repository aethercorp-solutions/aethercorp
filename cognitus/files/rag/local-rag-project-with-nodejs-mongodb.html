For MongoDB, I'd recommend MongoDB Atlas locally accessible if you want MongoDB Vector Search later, but if your goal is to learn the architecture first, you can run MongoDB locally with Docker.

1. Install Node.js

Check:


node -v
npm -v

I'd use Node.js 24 LTS/current LTS line for a new project.

Create your project:


mkdir rag-node
cd rag-node

npm init -y

Install the basic packages:


npm install express mongoose dotenv cors

For development:


npm install -D nodemon

2. Run MongoDB locally with Docker

This is probably the easiest setup.

Check Docker:


docker --version

Run MongoDB:


docker run -d \
  --name rag-mongodb \
  -p 27017:27017 \
  -v rag-mongodb-data:/data/db \
  mongo:8

Check that it's running:


docker ps

You should see something like:


CONTAINER ID   IMAGE     PORTS
xxxxx          mongo:8   0.0.0.0:27017->27017/tcp

Your local MongoDB connection is:


mongodb://localhost:27017

The important thing is:

Docker containers are not separate physical computers.

They are isolated processes running under Docker on your computer.

Compare it to installing normally

YOUR MAC

├── Redis

│
└── PostgreSQL

Everything is installed directly into macOS.

With Docker:


YOUR MAC
│
├── macOS
│
└── Docker
     │
     ├── Node.js Container
     │
     ├── MongoDB Container

     ├── Redis Container

Your browser can access:


http://localhost:3000

Your Node.js application can access MongoDB:


mongodb://mongodb:27017/ragdb

if Node.js and MongoDB are both containers on the same Docker network.

What does "container" actually mean?

Imagine your Mac has a big building:


                YOUR MAC
                ┌───────────────────────┐
                │                       │
                │       DOCKER          │
                │                       │
                │  ┌─────┐   ┌─────┐    │
                │  │Node │   │Mongo│    │
                │  │     │   │     │    │
                │  └─────┘   └─────┘    │
                │                       │
                └───────────────────────┘

Each container has its own:

  • filesystem
  • processes
  • networking
  • environment variables
  • dependencies

So your MongoDB container doesn't need MongoDB installed directly on macOS.

But containers share your computer's resources

This is important.

Containers aren't virtual machines in the traditional sense.

They ultimately use your Mac's:


CPU
RAM
Disk
Network

For example:


                YOUR MAC
                16 GB RAM
                     │
            ┌────────┴────────┐
            │                 │
         Docker            macOS
            │
      ┌─────┼─────────┐
      │     │         │
   Node   Mongo     Redis
    1GB    2GB       500MB

Docker manages those processes and resources.

And your MongoDB volume is outside the container

This part is especially important for the command you asked about earlier.

You had:


-v rag-mongodb-data:/data/db

Visually:


YOUR MAC
│
└── Docker
     │
     └── MongoDB Container
          │
          │ /data/db
          ▼
     ┌──────────────────────┐
     │ rag-mongodb-data     │
     │                      │
     │ MongoDB data         │
     │                      │
     │ documents            │
     │ chunks               │
     │ embeddings           │
     └──────────────────────┘

So:


Container = MongoDB program/environment

Volume = persistent MongoDB data

If you delete the container:


docker rm rag-mongodb

the volume can remain:


rag-mongodb-data

Then you can create another MongoDB container and attach the same volume.

The simplest mental model

Think of your Mac as a house:


🏠 YOUR MAC
│
├── 📦 Node.js container
├── 📦 MongoDB container
├── 📦 Redis container
└── 📦 Ollama container

Each 📦 is isolated, but they're all running inside your computer.

And Docker Compose becomes the thing that says:

"Start all these boxes, connect them together, configure their ports, and give them persistent storage."

For your Node.js + MongoDB RAG project, Docker Compose is the next concept I'd learn after docker run, because it makes this whole architecture much easier to manage.
