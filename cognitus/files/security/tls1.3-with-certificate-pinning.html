TLS 1.2+ with Certificate Pinning

TLS 1.2+ with Certificate Pinning is a common security requirement in banking, fintech, healthcare, and other high-security applications. It protects data in transit and helps prevent attackers from intercepting communications.

1. What is TLS?

TLS (Transport Layer Security) is the protocol behind HTTPS.

When your React Native app connects to:


https://api.example.com

TLS provides:

  1. Encryption – nobody can read the data.
  2. Integrity – data cannot be modified.
  3. Authentication – verifies the server is legitimate.

Without TLS:


React Native App
      ↓
email=user@example.com
password=secret123
      ↓
Internet

An attacker on public Wi-Fi could see everything.

With TLS:


React Native App
      ↓
Encrypted
      ↓
Internet
      ↓
API Server

The attacker only sees encrypted bytes.

2. Why TLS 1.2+?

Older TLS versions are insecure.

Version Status
SSL 2.0 Broken
SSL 3.0 Broken
TLS 1.0 Deprecated
TLS 1.1 Deprecated
TLS 1.2 Secure
TLS 1.3 Recommended

Most financial institutions require:


TLS 1.2 minimum
TLS 1.3 preferred

3. How TLS Handshake Works

When the app calls:


fetch("https://api.example.com/login")

The TLS handshake occurs before any API data is sent.

Step 1: Client Hello

App says:


Hello Server
I support:
- TLS 1.2
- TLS 1.3

Step 2: Server Hello

Server responds:


Use TLS 1.3
Here is my certificate

Step 3: Certificate Validation

The app validates:


Certificate
  ↓
Trusted CA?
  ↓
Domain matches?
  ↓
Expired?

Example:


Certificate says:

api.example.com

If user is visiting:


api.example.com

It matches.

Step 4: Key Exchange

Client and server create:


Session Key

Example:


A8X9-K2M4-P7Q1...

Used for encryption.

Step 5: Secure Communication

Everything is encrypted:


{
    "email": "user@example.com",
    "password": "secret123"
}

4. What Problem Does Certificate Pinning Solve?

Normal TLS trusts hundreds of Certificate Authorities (CAs).


App
 ↓
Trusts
 ↓
Any certificate signed by:
- DigiCert
- GlobalSign
- Let's Encrypt
- Sectigo
- etc.

If a CA is compromised or a fake certificate is issued:


Attacker
   ↓
Fake Certificate
   ↓
MITM Attack

The app may still trust it.

This is called:

Man-in-the-Middle (MITM)

5. What is Certificate Pinning?

Certificate pinning means:


Trust ONLY my server certificate

instead of:


Trust any valid CA

Without pinning:


App
 ↓
Any valid certificate
 ↓
Server

With pinning:


App
 ↓
Exact certificate/public key
 ↓
Server

6. MITM Example

Without pinning:


React Native App
       ↓
Attacker Wi-Fi Proxy
       ↓
API Server

Attacker presents a certificate.

If device trusts it:


TLS succeeds

Attacker can inspect traffic.

With pinning:


React Native App
       ↓
Certificate Check
       ↓
Certificate doesn't match
       ↓
Connection Rejected

Attack fails.

7. Types of Pinning

A. Certificate Pinning

Pin the whole certificate.


-----BEGIN CERTIFICATE-----
MIIF...
-----END CERTIFICATE-----

Pros:


Easy

Cons:


Certificate renewal breaks app

B. Public Key Pinning (Recommended)

Pin only the public key.


Public Key Hash

Example:


sha256/AAAAAAAAAAAAAAAAAAAA

Pros:


Certificate can be renewed

Cons:


Need proper key management

Most banking apps use this approach.

8. React Native Implementation

A common library is:


npm install react-native-ssl-pinning

Example:


import { fetch } from 'react-native-ssl-pinning';

const response = await fetch(
  'https://api.example.com/login',
  {
    method: 'POST',
    sslPinning: {
      certs: ['api_cert']
    },
    headers: {
      'Content-Type': 'application/json'
    },
    body: JSON.stringify({
      email,
      password
    })
  }
);

The certificate is bundled inside:


android/app/src/main/assets
ios/

9. Backend Requirements

For a Node.js API:

Use:


const https = require('https');

Enable:


TLS 1.2
TLS 1.3

Example:


const https = require('https');
const fs = require('fs');

https.createServer(
  {
    key: fs.readFileSync('privkey.pem'),
    cert: fs.readFileSync('fullchain.pem'),
    minVersion: 'TLSv1.2'
  },
  app
);

Or if using:

  • AWS API Gateway
  • AWS ALB
  • CloudFront
  • NGINX

configure:


Minimum TLS = 1.2
