Google OAuth and JWT

Think of Google OAuth and JWT as two different parts of authentication.

Simple flow 


User
  ↓
"Sign in with Google"
  ↓
Google OAuth
  ↓
Google verifies user
  ↓
Your backend receives Google's authorization/code/token
  ↓
Your backend creates YOUR access token
  ↓
Client stores access token
  ↓
Client sends token on every API request

1. Google OAuth = "Who are you?"

Google OAuth is mainly used to let Google authenticate the user.

For example:


User → Google
    "I am Paul and I successfully logged in."

Google can provide information such as:


email
name
Google user ID

Your backend then knows:

"Google has authenticated this person."

2. JWT = "Here is your API pass"

After Google authentication, your backend can create a JWT access token.

For example:


JWT
↓
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

The JWT might contain:


{
    "userId": "12345",
    "email": "paul@example.com",
    "exp": 1787040000
}

Your backend signs it with a secret/private key.

3. Client uses the JWT

The mobile app/web app stores the access token:


accessToken = "eyJhbGciOi..."

Then when calling your API:


GET /api/contacts
Authorization: Bearer eyJhbGciOi...

Your backend checks:


Is the JWT valid?
       ↓
Is the signature valid?
       ↓
Has it expired?
       ↓
Who is this user?
       ↓
Allow request

The important distinction

Technology Main purpose
Google OAuth Authenticate user through Google
JWT Represent authenticated user/session
Access Token Credential used to access your API
Refresh Token Get a new access token when it expires

So they are not the same thing.

A common architecture is:


                Google
                │
                │ OAuth
                ↓
         ┌───────────────┐
         │ Your Backend  │
         └───────┬───────┘
                 │
           creates JWT
                 │
                 ↓
         Access Token (JWT)
                 │
                 ↓
           Mobile / Web App
                 │
                 │ Authorization: Bearer JWT
                 ↓
            Your API

In one sentence:

Google OAuth proves who the user is; your JWT access token lets that authenticated user access your backend API.

In your implementation, the cleanest approach is:

Google OAuth → verify Google user → find/create your user → create YOUR JWT → return YOUR JWT to the app.

Right now, this line:


req.headers.token = token;
    return await signInWithGoogleToken(req, res, next);

is passing Google's OAuth token into your existing login flow. Instead, you can generate your own JWT after Google authentication.
