reCAPTCHA

reCAPTCHA is a free security service by Google that protects websites from spam, fraud, and automated bot abuse. [1] (https://developers.google.com/recaptcha), [2] (https://cloud.google.com/security/products/recaptcha)

How It Works

  • Behavioral Analysis: Tracks user interactions like mouse movements and typing patterns to tell humans and bots apart.
  • Risk Scoring: Evaluates traffic risk to block malicious access without hurting user experience. [1] (https://frontegg.com/glossary/recaptcha), [2] (https://www.radware.com/cyberpedia/bot-management/recaptcha/), [3] (https://cloud.google.com/security/products/recaptcha)

Main Versions

  • reCAPTCHA v3: Runs in the background without user interaction and returns a score based on activity.
  • reCAPTCHA v2: Uses the classic "I'm not a robot" checkbox or an invisible badge, showing image or puzzle challenges when risk is high.
  • reCAPTCHA Android: Protects native mobile applications using Google Play services. [1] (https://developers.google.com/recaptcha/docs/versions), [2] (https://developers.google.com/recaptcha), [3] (https://www.radware.com/cyberpedia/bot-management/recaptcha/)

To implement reCAPTCHA v2, you need to complete a two-part setup: a client-side integration to display the checkbox and a server-side integration to verify the user's response.

Here is the step-by-step guide to setting it up:

1. Get Your API Keys

Before writing code, register your website on the reCAPTCHA admin console.

  • Go to the Google reCAPTCHA Admin Console.
  • Choose reCAPTCHA v2 and select the "I'm not a robot" checkbox option.
  • Enter your domain name (e.g., yourwebsite.com).
  • Copy your two generated keys:
    • Site Key: Used in your HTML code (visible to users).
    • Secret Key: Used in your backend code (keep this private).

2. Client-Side Implementation (HTML)

Paste the JavaScript library inside your <head> tag, and place the reCAPTCHA container inside your <form> where you want the checkbox to appear.


<!DOCTYPE html>
<html lang="en">
<head>
    <meta charset="UTF-8">
    <title>reCAPTCHA v2 Implementation</title>

    <!-- 1. Load the reCAPTCHA JavaScript API -->
    <script src="https://www.google.com/recaptcha/api.js" async defer></script>
</head>

<body>

    <form action="verify.php" method="POST">

        <!-- Your form inputs -->
        <input
            type="text"
            name="name"
            placeholder="Your Name"
            required
        >
        <br><br>

        <!-- 2. Add the reCAPTCHA widget -->
        <div
            class="g-recaptcha"
            data-sitekey="YOUR_SITE_KEY"
        ></div>

        <br>

        <button type="submit">Submit</button>

    </form>

</body>
</html>

3. Server-Side Verification (Backend)

When a user checks the box, reCAPTCHA generates a token named g-recaptcha-response. When the form is submitted, your backend must send a POST request to Google to verify this token.

Here is a backend implementation example using PHP:


<?php
if ($_SERVER['REQUEST_METHOD'] === 'POST') {
    // 1. Get the secret key and the user's response token
    $secretKey = "YOUR_SECRET_KEY";
    $userResponse = $_POST['g-recaptcha-response'];
    $userIp = $_SERVER['REMOTE_ADDR'];

    // 2. Prepare the API request URL
    $url = "https://google.com" . $secretKey . "&response=" . $userResponse . "&remoteip=" . $userIp;

    // 3. Make the request to Google
    $response = file_get_contents($url);
    $responseKeys = json_decode($response, true);

    // 4. Check if the verification succeeded
    if ($responseKeys["success"]) {
        echo "<h3>Success! You are a human. Proceeding with form submission...</h3>";
        // Process your form logic here
    } else {
        echo "<h3>Verification failed. Please try again.</h3>";
    }
}
?>

If you're comparing Google reCAPTCHA with Cloudflare Turnstile, both solve the same core problem: detecting bots and automated abuse without making legitimate users solve annoying CAPTCHAs.

1. Google reCAPTCHA

Google reCAPTCHA has several generations.

The important modern options are:

reCAPTCHA v2

  • Checkbox: "I'm not a robot"
  • Can display image challenges.
  • Very recognizable.
  • Easy to implement.
  • More intrusive for users.

reCAPTCHA v3

  • No checkbox.
  • Runs in the background.
  • Returns a score, typically from 0.0–1.0.
  • Your backend decides what to do with suspicious requests.

For example:


User → Login
      ↓
reCAPTCHA v3
      ↓
score = 0.92
      ↓
Backend → allow

versus:


score = 0.15
      ↓
Backend → require additional verification / block

This is particularly useful for APIs, login, registration, password reset, contact forms, etc.

2. Cloudflare Turnstile

Cloudflare Turnstile is arguably the more attractive choice for a modern React + Node.js application.

It tries to verify that the user is legitimate without making them interact with a traditional CAPTCHA.

Typical flow:


React
  ↓
Turnstile widget
  ↓
Turnstile token
  ↓
Node.js / Lambda backend
  ↓
Cloudflare verification API
  ↓
allow / reject

The important thing is that the frontend token isn't enough.

Your backend must verify the token.

For your Castanet architecture

Given your architecture:


React Dashboard
       ↓
     Axios
       ↓
 API Gateway
       ↓
 AWS Lambda / Node.js
       ↓
 MongoDB

I'd lean toward Cloudflare Turnstile.

For example:


React
   │
   │ Turnstile token
   ▼
API Gateway
   │
   ▼
Lambda
   │
   ├── Verify Turnstile token
   │
   ├── Validate Firebase/Auth JWT
   │
   └── Process request
          │
          ▼
       MongoDB

That gives you two separate layers of protection:

  1. Authentication → Is this actually the authenticated Castanet user?
  2. Bot protection → Is this request likely coming from a legitimate human/client rather than automation?

Where reCAPTCHA is stronger

I'd choose Google reCAPTCHA if:

  • You already use Google heavily.
  • You want Google's established risk-analysis ecosystem.
  • You need reCAPTCHA's specific enterprise capabilities.
  • You already have reCAPTCHA implemented.
  • Your organization has standardized on Google security products.

For example, a large enterprise might already have:


Google Cloud
Firebase
Google Identity
reCAPTCHA Enterprise
Cloud Logging

In that environment, reCAPTCHA makes a lot of sense.

Where Turnstile is stronger

I'd choose Turnstile if:

  • You want minimal user interaction.
  • You don't want image puzzles.
  • You care about privacy.
  • You have a React frontend.
  • You have a Node.js backend.
  • You are protecting registration/login/forms/API endpoints.
  • You want something relatively simple to integrate.

For a startup-style application, I generally prefer:

Cloudflare Turnstile + your existing authentication system.

One important distinction

Don't think of either service as an authentication mechanism.

This:


Turnstile = "Is this request probably human?"

while:


Firebase Auth / JWT = "Who is this user?"
