app.use() and router.use()

In Express.js, both app.use() and router.use() are used to register middleware, but they work at different levels.

1. app.use()

app.use() registers middleware on the entire Express application.


const express = require("express");
const app = express();

app.use((req, res, next) => {
    console.log("Request received");
    next();
});

app.get("/", (req, res) => {
    res.send("Home");
});

Flow

When a request arrives:


Client
  ↓
app.use()
  ↓
Route Handler
  ↓
Response

Request:


GET /

Console:


Request received

Response:


Home

The middleware runs for every request.

2. app.use(path, middleware)

You can limit it to a specific path.


app.use("/api", (req, res, next) => {
    console.log("API middleware");
    next();
});

app.get("/api/users", (req, res) => {
    res.send("Users");
});

Request:


GET /api/users

Output:


API middleware

Request:


GET /

Middleware does not run.

3. router.use()

router.use() works exactly the same way, but only inside a specific router.

Example:


const express = require("express");
const router = express.Router();

router.use((req, res, next) => {
    console.log("Router middleware");
    next();
});

router.get("/users", (req, res) => {
    res.send("Users");
});

module.exports = router;

Main app:


const express = require("express");
const app = express();

const userRouter = require("./routes/users");

app.use("/api", userRouter);

Request:


GET /api/users

Flow:


Client
  ↓
app.use("/api")
  ↓
router.use()
  ↓
router.get("/users")
  ↓
Response

Console:


Router middleware

Response:


Users

Real-World Example

Suppose your API has:


/api/users
/api/orders
/api/products

You can organize routes:


app.use("/users", userRouter);
app.use("/orders", orderRouter);
app.use("/products", productRouter);

Users router:


router.use(authMiddleware);

Now:


/users/profile

requires authentication.

But:


/products

does not.

This keeps middleware isolated to a specific module.

Common Usage

Global middleware


app.use(express.json());

Every route can parse JSON.

Logging


app.use(logger);

All requests are logged.

Authentication for a router


router.use(authMiddleware);

Every route in that router requires login.

Visual Comparison

app.use()


Express App
│
├── Middleware
├── Route A
├── Route B
└── Route C

Middleware affects all routes.

router.use()


Express App
│
├── User Router
│   ├── Middleware
│   ├── /profile
│   └── /settings
│
└── Product Router
    ├── /list
    └── /details

Middleware affects only routes inside that router.

Simple Rule

Think of it like a building:


app.use()     = Security guard at the building entrance.
router.use()  = Security guard at a specific department.

Everyone entering the building passes through app.use().

Only people entering that department pass through router.use().

For a senior Node.js interview, a concise answer would be:

app.use() attaches middleware to the Express application, while router.use() attaches middleware to a specific Express Router instance. app.use() is typically used for global middleware such as logging, CORS, and body parsing, whereas router.use() is used for route-group-specific middleware such as authentication and authorization.
